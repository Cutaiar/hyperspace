01

The idea it is built around

Why six bands, and why four dimensions.

A four-dimensional rotation does not happen about an axis, the way it does in three dimensions. It happens in a plane — and 4D space has exactly six of them: XY, XZ, YZ, XW, YW, ZW.

A six-band spectrum analyser also produces exactly six numbers. That correspondence is the whole program: each band of the audio spectrum drives one independent plane of rotation, so the shape does not merely pulse in time with the music — it turns differently in six directions at once, and you can see which part of the sound is responsible for each.

02

One registry in the middle

The shape of the whole system, in one picture.

Every knob, key, band, hand and oscillator reaches the renderer through a single parameter registry. Nothing takes a shortcut. The registry resolves everything exactly once per frame, in Registry.apply(), and the render stack only ever reads what it wrote.

Everything points at the registry; the registry points at nothing above it.

03

Who may write a parameter

Three classes of writer, and no fourth.

Scene setter

Writes the base

The stored value — what a preset saves and undo restores. Every setter funnels into Param.set.

panel widgets · key, pad and hat rows · MIDI rows and knob glides · macro subscribers · preset and show loads · mouse orbit and zoom · undo and redo

Performer

Writes an offset

A transient departure from the base, rebuilt every frame and gone the moment the source stops feeding.

only Router.modulate → Param.modulate — one call site in the entire package, held by an AST-walking test. Adapters may only feed.

Object writer

Writes the object

Bypasses Param entirely; the delta is folded back into the base on the next frame.

ViewState.integrate (the accumulated angle) · camera and control resets · hand mirroring

Why that split is the load-bearing one

It dissolves the question every modulation system eventually trips over — what happens when two things grab the same control? A knob and a performer are never in competition, because they write different fields of the same parameter. What still needs a referee is performer against performer: one performer per parameter, enforced in the binding table's edit doors rather than in the per-frame pass, so the hot path never has to check ownership at all.

The frame

Seventeen steps in a fixed order — the one place that order exists, pinned by a test over stubs.

The sequence is not arbitrary. Every scene setter runs before the modulation pass, so a base write and the offsets on it land together in a single apply(). The undo watcher sits between the two groups, which is exactly why it sees every base written this frame and no performer at all.

One frame of lag, deliberately

Anything that reads a parameter while sources are being gathered — an LFO reading its own depth, a route scaled by a macro, the bridge sending values out — sees what apply() wrote last frame. That is what makes the pass non-recursive: nothing in it reads a value it is about to write. Each block is also individually guarded, so hot-reloaded code that raises records the error and the loop carries on drawing.

06

Subsystems

Where a feature crosses several modules at once.

Audio → bands → routes

A ring buffer feeds the FFT, which feeds six band lanes with an asymptotic ceiling instead of a hard clip. Each lane is a routable source; the band editor owns the crossovers and the dynamics recovery that keeps brickwalled masters moving.

audio · analysis · analyzer · bands

Hands

Ultraleap tracking shaped into twelve axes, two presence lanes and eight pinch switches. Each axis runs calibration, a One Euro filter, a dead zone and curve, then attack–decay dynamics with a spring back to rest when the hand leaves frame.

hands/core · hands/signal · hands/tape · hands/panel

The desk

An APC40 driving two layers of one table — the loaded preset's and the session's — plus invariant rows that mean the same on both. SHIFT latches the layer; the knob rings show the base and never chase a performer, so a knob can always catch.

midi · apc40 · ui_desk

Effects

Each shader file in the effects folder is an effect: its uniforms become parameters automatically. An effect aims either at the whole frame or at the polytope's faces, which can show the picture per face or in screen space.

fx · glsl · shaders/fx/*.glsl · ui_fx

Look-back & dream

A history of scene textures composites echoes over the live frame. With dreaming enabled, a worker thread pulls frames from that history, runs them through a network on the GPU and hands back dreamed ones — without ever blocking the frame.

lookback · dream

Outputs

Several render outputs: the first is the main window, each later one a window in its share group with its own presenter and overlay. Per-output switches decide scene, hands, pass-through and dim; window rectangles are remembered per output.

outputs · overlay · placement

Presets & shows

A preset is the performance — values, routes, desk, macros. A show is the session, holding a bank of twenty-four preset names and which one it starts on. Overwrites go to a listed trash first; factory presets are hidden, never deleted.

library · preset · config · homegit

Ghost hands

The tracked hands drawn over the finished frame, with a per-hand gauge, routed marks lit in colour against grey, a grab ring, and labelled tethers from each routed mark to the parameter it drives. Reads the skeleton raw — it is not a source.

ghost

Shapes in four dimensions

Twenty-six shapes. A cell count of zero marks a surface, not a 3D shape: the Clifford torus is a surface native to 4D. Each shape says how it fills W — native, lifted into it by a function of its own parameters, or masked: kept 3D, its W planes folded onto 3D ones as it is drawn. Only the Heart is masked.

geometry · render · tools/turntable
07

The boundaries are tested, not intended

What keeps a 32,500-line single process from turning into a knot.

The dependency rules above are not documentation that drifts — most of them are assertions. Tests walk the import graph and the abstract syntax tree to prove that the core never imports the MIDI adapter, the bridge or the dream worker; that the routing table imports nothing above it; that the render stack imports no registry; that Param.modulate has exactly one call site; and that importing the host pulls in no gated adapter, no torch and no tracking SDK.

Leaves — modules that import nothing from the package, so anything may import them — are named explicitly: analysis, tapers, undo, placement, homegit, geometry, tempo, lfo, glsl, gamepad, apc40, watchdog, and the hands package's signal and tape modules.

The hands package is built to be removed

It is the clearest case of the discipline. Its own docstring opens "a self-contained instrument, host optional … written to be lifted out whole", and the rule that keeps it liftable is that its core and signal modules import nothing from Hyperspace. Everything they need arrives duck-typed as an argument: the registry as anything with the right setters, the tracker as anything with a latest(), the MIDI sink as anything with a send(). One module knows the host, and extracting the package means replacing that one file.

A test walks the syntax tree and fails the build if either module ever grows a Hyperspace import — because, as that test says, the boundary erodes one convenient import at a time, and nobody notices until the day someone tries to extract it.
