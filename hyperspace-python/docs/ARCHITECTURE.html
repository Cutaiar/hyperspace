01

The idea it is built around

Why six bands, and why four dimensions.

A four-dimensional rotation does not happen about an axis, the way it does in three dimensions. It happens in a plane — and 4D space has exactly six of them: XY, XZ, YZ, XW, YW, ZW.

A six-band spectrum analyser also produces exactly six numbers. That correspondence is the whole program: each band of the audio spectrum drives one independent plane of rotation, so the shape does not merely pulse in time with the music — it turns differently in six directions at once, and you can see which part of the sound is responsible for each.

02

One registry in the middle

The shape of the whole system, in one picture.

Every knob, key, band, hand and oscillator reaches the renderer through a single parameter registry. Nothing takes a shortcut. The registry resolves everything exactly once per frame, in Registry.apply(), and the render stack only ever reads what it wrote.

Everything points at the registry; the registry points at nothing above it.

03

Who may write a parameter

Three classes of writer, and no fourth.

Scene setter

Writes the base

The stored value — what a preset saves and undo restores. Every setter funnels into Param.set.

panel widgets · key, pad and hat rows · every MIDI desk's rows and knob glides · OSC hits · macro subscribers · preset and show loads · mouse orbit and zoom · undo and redo

Performer

Writes an offset

A transient departure from the base, rebuilt every frame and gone the moment the source stops feeding.

only Router.modulate → Param.modulate — one call site in the entire package, held by an AST-walking test. Devices may only feed.

Object writer

Writes the object

Bypasses Param entirely; the delta is folded back into the base on the next frame.

ViewState.integrate (the accumulated angle) · camera and control resets · hand mirroring

Why that split is the load-bearing one

It dissolves the question every modulation system eventually trips over — what happens when two things grab the same control? A knob and a performer are never in competition, because they write different fields of the same parameter. What still needs a referee is performer against performer: one performer per parameter, enforced in the binding table's edit doors rather than in the per-frame pass, so the hot path never has to check ownership at all.

The frame

Sixteen steps in a fixed order — the one place that order exists, pinned by a test over stubs. The devices run in three of them.

The sequence is not arbitrary. Every scene setter runs before the modulation pass, so a base write and the offsets on it land together in a single apply(). The undo watcher sits between the two groups, which is exactly why it sees every base written this frame and no performer at all.

Dependency order, no lag

The modulation pass runs the routing table as a graph, each node after everything it reads. An LFO is a source with inputs: its knobs land, then it steps. A scale or a macro behind a route lands before the route that reads it. So an LFO owning another LFO's depth, a macro scaling a push, a hand on a modifier's release all act this frame — every corpus preset lands the same values as before, a frame earlier where it was late. Nothing reads a stale value but through a delay node: a loop with no delay in it keeps its last cable off, with a note on the routing page; a delay closing a loop makes it exactly one frame late. A parameter landed in the pass is never applied twice. The sinks still run after apply(), so what goes out to the DAW is this frame's value. Each block, and each device, is also individually guarded, so hot-reloaded code that raises records the error and the loop carries on drawing.

06

Subsystems

Where a feature crosses several modules at once.

Audio → bands → routes

A ring buffer feeds the FFT, which feeds six band lanes with an asymptotic ceiling instead of a hard clip. Each lane is a routable source; the band editor owns the crossovers and the dynamics recovery that keeps brickwalled masters moving.

audio · analysis · analyzer · bands

Hands

Ultraleap tracking shaped into twelve axes, two presence lanes, eight pinch switches, the dance sources and a grab. Each axis runs calibration, a One Euro filter, a dead zone and curve, then attack–decay dynamics with a spring back to rest when the hand leaves frame. A thin device wrapper puts it on the registry; its DAW messages go out through a sink.

hands/core · hands/signal · hands/tape · hands/panel · hands/device

The desk

An APC40 driving two layers of one table — the loaded preset's and the session's — plus invariant rows that mean the same on both. SHIFT latches the layer; the knob rings show the base and never chase a performer, so a knob can always catch. A second desk on the generic profile adds rows of its own, named by its role, on a layer of its own.

midi · apc40 · generic · ui_desk

Devices

Every input and output is a device on one registry, listed in the config and opened behind its own entry: polled with the scene setters, fed with the sources, sent after apply(). The config is watched, so a device comes and goes without a relaunch; one that fails is an error line, never a stopped frame. A phone app over OSC is added by an entry alone, and a recorded point cloud plays on the registry, off the router — and is drawn in the scene by the render graph.

devices · config · osc · bridge

Effects

Each shader file in the effects folder is an effect: its uniforms become parameters automatically. On the frame each effect is a node of the render graph — bitmap in, bitmap out, off ones read straight through — and exists only where the preset wires it: on the hands only, on one output only, before the trail, or into the polytope's faces, which can show the picture per face or in screen space.

fx · graph · glsl · shaders/fx/*.glsl · ui_fx

Look-back & dream

Two nodes since plan 36. The look-back records the picture wired into it and puts out its trail of echoes; a composite lays it on. The dream takes the picture wired into it and puts out a dreamed one (dream.on off passes it through; one live dream): with dreaming enabled, a worker thread runs frames through a network on the GPU and hands back dreamed ones — without ever blocking the frame.

lookback · dream

Masks & vision

A mask is its own purple wire — a pattern, a pixel passes or it does not — and never rides in a picture's alpha. A matte turns a picture into a mask (by brightness, coverage or a colour key); a cut cuts a picture by a mask; a segment takes any picture and puts out its foreground, its background and its mask, from Apple Vision on the Neural Engine (torchvision behind it) on a worker thread a frame or two late, or from a motion model with no network at all. A mask wired where a picture is taken shows white where it passes, black elsewhere — one way only: a picture becomes a mask through a matte. Edges is an effect file.

graph · masks · segment · shaders/fx/edges.glsl

Outputs

Several render outputs: the first is the main window, each later one a window in its share group with its own presenter and overlay. Per-output mutes silence its picture and hands, and what it shows is its own wires (else All outputs'); window rectangles are remembered per output.

outputs · overlay · placement

Presets & shows

A preset is the performance — values, routes, desk, macros. A show is the session, holding the desk's bank of twenty-four preset names, the rig's wires and a startup preset. Overwrites and deletes go to a listed trash first; nothing ships with the app and nothing is hidden — every preset is yours (one tier, 2026-10-28). Library.home is the library root (the home, or a shared folder named by [library] path); Library.machine is the home for this machine's own files. A patch (plan 40) is a group of GRAPH nodes saved with the cables that cross its edge — a knob or a hand kept as the address it is, the scene in and the outputs out kept as typed ports — spawned into any preset under fresh ids as one undo step; on the canvas a group folds its members into one node until +, a list in the preset the renderer never sees.

library · preset · patches · config

Ghost hands

The tracked hands drawn in the shape's own camera — as their own layer over or through the effects, or solid inside the scene, in front of and behind its edges — with a per-hand gauge, routed marks lit in colour against grey, a grab ring, and labelled tethers from each routed mark to the parameter it drives. Reads the skeleton raw — it is not a source.

ghost · graph

Modulation as a graph

Every route, macro subscriber, scale, LFO and envelope knob is an edge between sources, LFOs, envelopes, modifiers, macros and parameters, sorted once when the table changes and run each frame in that order. Modifiers — curve, scale, smooth, combine, threshold, delay — sit between a source and a route, live in the preset, and publish a lane a route reads like any other. A loop runs only through a delay.

modgraph · modifiers · routing · ui_routing

The node editor

One canvas for both graphs: the controllers (the APC40 as two nodes, a layer each; a desk template as one collapsible node; a missing device as a grey placeholder by role), the LFOs, the envelopes, the sequencer (its lanes' envelopes as cables), the modifiers, the macros, the parameters under the render node that owns them, the render graph's image cables and the outputs. A cable dragged is the row a Learn would make, or a wire in the preset's graph; Learn starts from a port. Positions live in the preset and the show.

graphview · ui_graph · imgui_node_editor

Render graph

The frame as wired nodes: the shape, the hands and a point cloud share one fixed camera with a depth buffer, so a hand can pass between the shape's edges. Zoom and pan move only the shape, in the world. A preset's file says all of its wiring (schema /7: nothing is filled in at load) — the hands in the scene or as a layer, an effect twice, a wire that gives one output its own picture or its own hands — and 789 golden frames pin every corpus preset's picture, and the fixture presets', to the byte.

graph · render · geometry · tools/golden_frames

Shapes in four dimensions

A hundred and one shapes, in families the Shape menu groups under 4D, 3D and Scenes. Each says honestly whether it is 4D or 3D (Shape.dims): a 4D shape turns through W; a 3D shape sits at w = 0 and the W planes leave it alone. A cell count of zero marks a surface, not a 3D shape: the Clifford torus is a surface native to 4D. A scene is several shapes in one frame; the 3D switch holds a 4D shape's pose and turns it rigidly in 3D.

geometry · render · tools/turntable

Face patterns

Seventeen patterns in one shader, each reading eight inputs that mean the same on every one: scale, glow, warp, speed, colour, sharp, hue, spread. One table names them for the registry, the FACES page and the shader. Speed is an integrated clock, so it never jumps; two patterns read the bands directly to draw the music.

patterns · shaders/patterns.glsl · ui_patterns · render
07

The boundaries are tested, not intended

What keeps a 48,900-line single process from turning into a knot.

The dependency rules above are not documentation that drifts — most of them are assertions. Tests walk the import graph and the abstract syntax tree to prove that the core never imports the MIDI adapter, the bridge, the OSC device or the dream worker; that the routing table imports nothing above it; that the render stack and its graph import no registry; that Param.modulate has exactly one call site; and that importing the host pulls in no gated adapter, no torch, no Apple Vision and no tracking SDK — the segment worker is imported by the renderer on a segment's first need, never by the graph, and loads its model inside its own first job.

Leaves — modules that import nothing from the package, so anything may import them — are named explicitly: analysis, tapers, undo, placement, geometry, tempo, modbank, sequencer, glsl, gamepad, apc40, generic, watchdog, modgraph (the modulation graph's sorter), and the hands package's signal and tape modules; lfo and envelope import only modbank.

The hands package is built to be removed

It is the clearest case of the discipline. Its own docstring opens "a self-contained instrument, host optional … written to be lifted out whole", and the rule that keeps it liftable is that its core and signal modules import nothing from Hyperspace. Everything they need arrives duck-typed as an argument: the registry as anything with the right setters, the tracker as anything with a latest(), the MIDI sink as anything that carries its messages out. Two modules know the host — the page and the device wrapper — and extracting the package means replacing those two files.

A test walks the syntax tree and fails the build if either module ever grows a Hyperspace import — because, as that test says, the boundary erodes one convenient import at a time, and nobody notices until the day someone tries to extract it.
