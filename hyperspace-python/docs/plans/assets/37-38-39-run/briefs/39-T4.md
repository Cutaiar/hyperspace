## Build (exactly T4 of the build plan, W4 of the spec)
1. **`hyperspace/segment.py`** (new): `SegmentWorker(backend, quality,
   …)` on `DreamWorker`'s shape — `submit(frame, index)` never blocks
   (latest wins, drops counted), `latest() -> (mask HxW uint8, index,
   size)` lock-free, errors caught into `.error` and said, the thread
   sleeps when nothing is submitted, `close()` joins within 1 s. Backends
   as classes with `open()`, `run(frame_rgba) -> mask`, `close()`:
   `VisionBackend` (pyobjc: the request built once per quality level, a
   `CGImage` from the frame's bytes, the result's `CVPixelBuffer` (`L008`)
   locked, read into numpy, unlocked; import inside `open()`),
   `TorchBackend` (LR-ASPP, fp16 on MPS if there, the spike's normalise
   and softmax, class 15; weights looked for in `<home>/weights` then
   torch's hub cache, downloaded on first use with a line on stderr, as
   the dream's are), `pick_backend(cfg)` (`[segment] backend` auto /
   vision / torch; auto = Vision on macOS else torch; a missing library
   is a **reason string** the node says, never an exception past
   `open()`). The torch backend shares one model between workers.
2. **`graph.py`**: `SegmentAt` (instance; the mode is a param, not in the
   entry), reader, every table line; pins `segment.fg` (IMAGE),
   `segment.bg` (IMAGE), `segment.mask` (MASK) in `PINS` as `scene.depth`
   is; `SegmentNode.run`: pull the newest result into the node's mask
   texture (`_frame_target` `name#mask`, one channel, keyed by result
   index; the orientation flag set for the CPU path), then submit —
   through **the shortcut** when `inputs["image"]` is a `MediaNode` whose
   channel's newest `MediaFrame` has CPU pixels and its `frame` id moved

   every other picture), and only when the input moved (a channel's
