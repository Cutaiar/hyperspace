# 39-T0 decisions — `edges.glsl`

## 1. Register-row drafts

**4xx — `edges`: the Sobel, the threshold, the glow, the direction hue**
- **Answer** (controller — 2026-10-27): a 3×3 Sobel on `luma(src.rgb)` (premultiplied rgb, so a see-through pixel reads dark). Eight taps exactly 1 px out (`1/u_res`), through `src()` (mirrored past the borders, so a frame border is no edge). Kernels `[-1 0 1; -2 0 2; -1 0 1]` and its transpose; the gradient is divided by 4, so a hard black→white step is magnitude 1. **Threshold** (0–1, default 0.2) is a ramp, not a gate: `clamp((|g| − t) / (1 − t), 0, 1)`. Below `t` nothing; at a full step full. **Glow** (0–4, default 0) is a second Sobel with taps 3 px out, its strength put through the same threshold and added at `glow / 4`. At 4 the halo is as bright as the line: a hard edge lights 6 columns instead of 2. **Direction** colours by `hsv(fract(atan(gy, gx) / TAU), 1, 1)`, the full angle: red for dark→light pointing right, chartreuse up, cyan left, violet down. When the glow is on, the glow ring's gradient is added in at the same weight, so the halo takes the line's hue. **Source** is `src(uv) × m`, alpha included. White is `(m, m, m, m)`.
- **Built**: one effect file, no Python. On the FX page and in the GRAPH picker like any effect, off until switched on. The scene through it is the polytope's lines drawn as double outlines (each scene line has two edges).
- **Other options**: a gate threshold (`m = |g| ≥ t ? |g| : 0`); hue by the axial orientation (`atan` mod π, so a thin line's two sides share one hue); glow as a radius rather than a strength; a separable blur for the glow; source mode with alpha = m (an opaque line of the source's colour even where the source is see-through); source mode as the spec's literal `src.rgb × m`, i.e. `vec4(src(uv).rgb * m, 0.0)`, where the alpha tail lifts alpha to max(rgb): the line as light, so a black source edge is transparent rather than an opaque black line (built: `src * m`, alpha included; judge at AJ.7 step 4).
- **To reverse**: edit the file. It hot-reloads, and only the `edges-scene` goldens (8) would re-record.
- **Rough edge**: a thin bright line (the scene's 1–2 px wireframe) gives two edges, so white mode reads as a doubled outline, and direction gives the line's two sides opposite hues. On a noisy camera the default threshold 0.2 may still let sensor noise sparkle (no pre-blur). Source mode at the dark side of an edge draws an opaque black line (honest coverage, but it may surprise).
- **Judge it**: AJ.7.

## 2. Hand-check draft

**AJ.7 — Edges on the scene, on the camera, and into a cut** (the projector rig or the laptop, GRAPH page)
Headless: `tests/test_fx_edges.py` (params, flat → black, a vertical edge, threshold, glow, direction hues); `tests/test_fx.py::test_each_effect_changes_the_frame[edges]` and `::test_every_effect_runs_on_the_face_target[edges]`; the `edges-scene` goldens (`tests/test_golden_frames.py`).
1. Load any scene preset. On GRAPH, wire `scene → edges → output.all.image` and switch edges on. The polytope's lines show as thin white outlines on black.
2. Sweep **Threshold** 0 → 1. At 0 every soft gradient of the faces' pattern shows; around 0.2 only the lines; near 1 almost nothing.
3. Raise **Glow** to 4. Each line gains a halo a few pixels wide, as bright as the line at 4.
4. **Colour** → source: the outlines take the scene's colours. → direction: lines facing different ways turn different hues, and the hue turns as the polytope rotates.
5. Wire a camera channel (`channel.a` with the camera) into `edges` instead. The room's edges (door frames, furniture, people's outlines) draw as lines, steady at the default threshold.
6. Once T2/T3 land: `edges → matte (luma) → cut.mask` with `pattern → cut.image` into an output. The pattern shows only along the lines.
*Pass:* steps 1–6 as written, with no GL error on the SYSTEM page and the frame rate unchanged (a 9-tap pass).
*Fail:* a flat area that is not black (the threshold or premultiplication is wrong: `test_a_flat_picture_makes_black`); lines at the frame's border (`src()` mirroring broken); direction all one hue (the `atan` arguments swapped or the glow gradient swamping it); camera edges that sparkle everywhere (noise above the threshold: raise it, or a pre-blur is the follow-up); in step 6 the pattern everywhere (the matte reads alpha, not luma, or the promotion is missing).

## 3. As-built notes

- **Built**: `hyperspace/shaders/fx/edges.glsl` as above. Fixture `tests/fixtures/presets/edges-scene.json` (`/7`, wired frame), made from `hands-fx` with acid swapped for edges, its `fx.acid.*` and `fx.mix` hand routes dropped (so no hand moves the picture), and edges' values at their defaults. It has 8 goldens (3 new PNGs; the rest reuse existing black / hands-only pictures). `tests/test_fx_edges.py` holds 15 cases.
- **Differs from the spec**:
  - (a) The fixture is in `tools/golden_frames.py`'s `WIRED_FIXTURES` as well as `FIXTURE_PRESETS`. A `/6`/`/7` wired frame has no old section to prove a frame signature against (the tool's `--signatures` raised on it otherwise), and its states are drawn as the windows' mutes, as the other wired fixtures are. So `frame-signatures.json` gains no case (still 125).
  - (b) Three existing tests needed bookkeeping:
    - `test_golden_frames.py`: the count goes up by 8 and `GOLDENS_SINCE` gains `edges-scene`.
    - `test_plan12_presets.py`: `edges` is on `EFFECTS_IN_NO_PRESET`, because every effect file must be on in a factory preset or on that list, and plan 39 edits no preset.
    - `test_graph_free.py::test_every_schema_is_among_the_sources`: a `/7` is tolerated among the fixtures, which until now were all old files. T4/T5's fixtures, which hold new kinds, will be `/7` too.
  - (c) `@order 75` was added (see the row).
  - (d) Source mode keeps the source's alpha × m. The spec said `src.rgb × m` and named no alpha.
- **Not verified by a person**: the look on the projector, the camera behaviour (noise), and the direction palette's taste.
- **Rough edges**: the doubled outline on thin lines; no pre-blur, so camera noise depends on the threshold.
