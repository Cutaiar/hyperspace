**4xx. The held copy carries the rig's bus cables (plan 36)**
- **Answer** (controller — 2026-10-27): at HOLD the hold keeps the wiring (`Renderer.wiring`), the rig's bus cables (`graph.RigWires` from the renderer's `rig_source`, the open show) and the extra hands states. For the program draw the renderer gets a stand-in `rig_source` holding the cables as they stood. A cable cut or joined during the hold counts as "the graph changed".
- **Built:** cutting a bus cable from All outputs into a window, or joining one, during a hold shows only in the preview behind GRAPH. The projector keeps the cable as it was until TAKE.
- **Other options:** treat the bus as the rig and leave it shared. A cut would then go straight to the projector, which is exactly the "scene built in front of the room" the hold exists to prevent.
- **To reverse:** cheap. Drop the `rig_source` swap in `Hold.program`.
- **Rough edge:** none known. The program's graph does not rebuild while held, because its key (wiring plus rig) never changes.
- **Judge it:** AI.2, AI.4.

**4xx. What the held copy does not carry: clouds and the effect files present**
- **Answer** (controller — 2026-10-27): both stay shared by the program and the preview. `cloud_source` is the device registry (the room). The effect files present (`FxState.specs`) are the disk. Neither is the look.
- **Built:** a cloud device listed, or an effect file added or removed during a hold, rebuilds the program's graph too.
- **Other options:** snapshot both at HOLD. A removed effect file cannot be drawn anyway (its program is gone), so holding the set buys little.
- **To reverse:** moderate. Hold a `cloud_source` stand-in like the rig's, and freeze the specs set for the key.
- **Rough edge:** saving an effect file during a show changes the projector even when it is held. This matches the spec's table row "an effect instance a newly loaded preset removed".
- **Judge it:** AI.6.

**4xx. The preview renderer reads the show's cables, never a default**
- **Answer** (controller — 2026-10-27): `hold.mirror` now hands over `rig_source` along with media, clouds, bands, hands and wiring. Without it the preview renderer had `rig_source=None`, which `graph.rig_of` reads as every bus cable standing: a wire filled in, against plan 36's rule.
- **Built:** a window whose bus cable the show has cut is black in the preview as on the projector, rather than showing All outputs.
- **Other options:** none. This is the rule.
- **To reverse:** do not.
- **Rough edge:** none.
- **Judge it:** AI.2.

**4xx. Drop stands again a bus cable cut during the hold**
- **Answer** (controller — 2026-10-27): yes. Drop goes back through `Undo.revert`. Its checkpoint takes the show's mark, and since plan 36 T1 that mark carries the rig's wires, so a cut made during the hold is put back. D3's "the preset's part, not the rig" filters the rig's *params* (output, eye, hands feel, tempo), not the rig's drawn cables. The cables are part of "the graph", which Drop puts back.
- **Built:** after DROP the canvas matches the projector exactly, cables included. ⌘Z brings the cut back.
- **Other options:** keep the cut through Drop as "rig". The projector would then change at Drop, contradicting "the projector never moved, so nothing changes there".
- **To reverse:** moderate. Filter the show mark's rig slot out of `_preset_part`.
- **Rough edge:** a GRAPH layout move (the rig nodes' positions) made during the hold also goes back with Drop, through the same mark.
- **Judge it:** AI.4.
