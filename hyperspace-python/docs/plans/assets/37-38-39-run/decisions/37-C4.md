### 4xx-b. "Nearest kept" is a ranked list per mode, by structure, then palette, then motion

- **Answer.** controller — 2026-10-27.
- **Built.** `faces_sheets.NEAREST`: for every mode, three other modes nearest first, each with one line on why. The rule: (1) the same structure on the face (radial about the centre; a straight-line lattice; a cell lattice; a flowing field; a band reader), then (2) the same palette and light (bright lines on dark, or a full fill), then (3) the same motion. `nearest_kept(mode, kept)` takes the first kept name in the list, else the first kept mode in `NAMES` order other than FLAT (FLAT only when nothing else is kept). So any subset the owner names answers `dropped → nearest kept` without a second judgement.
- **Other options.** A pixel distance between the sheets' tiles (cheap, but it ranks by colour and misses structure: CAUSTIC and FLAT are near by mean colour); the owner naming each dropped mode's replacement himself.
- **To reverse.** Edit `NEAREST`, run `tools/faces_sheets.py --map`; or the owner names replacements and P2 uses those.
- **Rough edge.** The ranking is the controller's eye on the sheets and the shader source, not the owner's. FLAT's neighbours (PLASMA, CAUSTIC, EMBER) are "the least pattern-like fills", a weak notion — but FLAT is only on faces-off presets.
- **Judge it.** Check AH.6 step 3.

## 4. The exact steps P2 takes when the list arrives (for the resumed C4)

Input: the kept list K (names). Dropped D = NAMES − K. Map each d in D to
`faces_sheets.nearest_kept(d, K)`.

1. **The index problem (decide first; the brief did not name it).** A preset stores
   `view.pattern` as an **index** (`patterns.py`: "appended, never inserted"). Removing a
   mode from `MODES` shifts every later index. Two ways:
   - (a) **Renumber + remap** (recommended: a short list, a knob with no dead stops): the new
     `MODES` is K in today's order; a table `OLD_TO_NEW[old_index] → new_index` (dropped →
     its nearest kept's new index). Every preset value is rewritten through it — this is a
     schema-visible change (an old build reads new indices as the wrong patterns), so it
     needs a `/8` marker or a `pattern_ids` note per the "no old-schema support" rule
     (owner 2026-10-25: both Macs update together, the library migrated forward with a
     backup) → owner call, register row.
   - (b) **Tombstone**: keep `MODES`' indices, mark dropped modes `retired`; the enum, the
     FACES page and the knob skip them; the loader maps a retired index to its nearest
     kept on load. No schema change, but `patterns.glsl` keeps a branch or a load-time map.
2. `hyperspace/patterns.py`: `MODES` → K (or retired flags); the module docstring's
   "appended, never inserted" rule restated; `OLD_TO_NEW` / `RETIRED_TO` table here (the
   one place mode names live).
3. `hyperspace/shaders/patterns.glsl`: delete the dropped `if (mode == k)` branches and their
   helper functions (`meter`, `pulse`, `marble`, `truchet`, `kaleido`, `pop`, `fbm3`,
   `band()` if METER and PULSE both go, `hash22` if CELLS goes …); renumber the kept
   branches to the new indices (option a). `tools/check_glsl.py` after.
4. `hyperspace/ui_patterns.py`: nothing structural (it reads `MODES`/`len(MODES)`); check the
   chip grid's rows for the shorter list; FLAT's note (index 0) if FLAT moves.
5. Readers of the mode list that follow on their own: `params.PATTERNS` (=NAMES, the enum
   and the desk knob's throw), `render.N_PATTERNS` (swatch rotation), `learn._PATTERN`,
   `apc40.SCENE`, `library` alias `pattern`. No edit expected; run their tests.
6. **Presets** (only those whose mode is dropped; the rest only renumbered under (a)):
   the factory files under `hyperspace/library/presets/` *and* their code sources — note
   `hyperspace/preset.py` writes `view_pattern=` for four presets (lines ~1609, 1703, 1735,
   1767) and the factory sources under `tests/fixtures/factory-sources/presets/`; plan 37's
   ownership table says `preset.py`: "nothing" — the controller must allow this edit.
   Each migrated preset's `note` gains one line: "Pattern X was retired (plan 37); now Y,
   its nearest." Then `tools/faces_sheets.py --map` and commit the map.
7. **Fixtures** under `tests/fixtures/presets/`: rewrite `view.pattern` the same way (they
   are `git add -f`'d); the *unwired* ones move no pixel. Fixture renumbering changes no
   signature (`frame-signatures.json` reads the graph, not the mode).
8. **Goldens** (`uv run python tools/golden_frames.py --record --only <slugs>`), only the
   *on screen* presets of a dropped mode (from the map's summary), the commit naming each
   with "pattern X retired → Y (plan 37 P2, owner's list of <date>)". Faces-off presets do
   not move. Under (a) a kept mode's preset renumbered moves nothing.
9. **Tests**: `tests/test_patterns.py` (per-mode table, shader accessors, pixel checks —
   most loop over `MODES`; any naming a dropped mode by index goes), `tools/pattern_sheet.py`
   (plan 22's sheets: loops; fine), `tests/test_faces_map.py` (NEAREST must then name only
   kept modes for the kept ones — rewrite `NEAREST`/`DRAWS` to K and keep the dropped
   names in a `RETIRED` table the map prints).
10. **The owner's Drive library**: a migration tool run on the owner's say, backup first
    (like plan 36's `tools/migrate_library.py`), the same `OLD_TO_NEW` table. Never by the
    build.
11. Docs (C5 / the docs task): DECISIONS "Face patterns" row 105's "appended, never
    inserted" amended; register rows for D1's answer and the remap; AH.6.
