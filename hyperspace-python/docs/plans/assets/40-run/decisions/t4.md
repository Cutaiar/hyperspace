## 1. Register-row drafts

**47a — An error is not a coming or going.**
**Answer:** controller, 2026-10-27.
**Built:** the registry's status comparison (`DeviceRegistry._word`) ignores an error on a device that is open: a poll that raised, or an adapter's own error. So a flaky adapter never flaps the listeners or puts "connected" in the footer every other frame; its SYSTEM line in the warning colour still says it. A device whose `open()` raised counts as `lost` while the registry retries it, so the open that finally succeeds is said as "apc40 connected — n controls live". In `wants`, an error status reads as `lost`.
**Other options:** say every status string change (it would flap); add a fifth `error` want state (the spec fixes four).
**To reverse:** small: `_word` and the state mapping in `wants`.
**Rough edge:** a device stuck in an adapter error (MIDI `io.error`) reads `lost` on the chip and says nothing when the error starts.
**Judge it:** AK.n1.

**47b — Only the preset's enabled rows count.**
**Answer:** controller, 2026-10-27.
**Built:** `wants` counts enabled performer routes (push/position), enabled preset-layer MIDI rows and modifier inputs. It never counts a session row (SHIFT layer, invariant controls, pad buttons, keys, sinks) or a disabled row. Several rows on one control are one control ("K1" once).
**Other options:** count disabled rows too (they read nothing either way); count session rows (they are the rig's, not the preset's).
**To reverse:** small: `devices._rows_of`.
**Rough edge:** a gate (`when`) on another device's source is not counted.
**Judge it:** 398 (AK hand check 5).

**47c — The desk's words for a row on a desk the rig lacks.**
**Answer:** controller, 2026-10-27.
**Built:** a MIDI row on a listed desk uses that desk's profile, so an APC40 gives "K1", "D3", "G8·1". On a desk the rig lacks, only the first role's (unqualified) rows use the table's profile. A qualified row (`cc@launch:0:7`) is described as "CC 7 ch1", because its profile is unknown.
**Other options:** always the APC40's glyphs (wrong for a generic box); never glyphs for a missing desk (loses "K1" with the APC40 unplugged, which hand check 5 needs).
**To reverse:** one line in `devices.wants`.
**Rough edge:** none known.
**Judge it:** 398.

**47d — The launch says nothing; a removal says only its note.**
**Answer:** controller, 2026-10-27.
**Built:** `open_all` records every status without a word, so starting the app with the APC40 plugged in puts nothing in the footer. A device that leaves config.toml keeps the existing "devices: x removed" note and nothing more. An added device says its status ("leap off", "leap lost — 3 rows wait", "leap connected — 3 rows live").
**Other options:** say every connected device at launch (footer noise at every start).
**To reverse:** small.
**Rough edge:** none known.
**Judge it:** 398.

**47e — The words of a row (`routing.row_words`).**
**Answer:** controller, 2026-10-27.
**Built:** "right hand y", "hands gap", "band 1", "pad A", "d-pad up", "axis LX", "CC 48 ch1", "note 53 any ch", "pitch bend ch3", "LFO 1", "env 2", "seq lane 4", "mod.3", an OSC address as itself, else the source. The role is never said: the caller says it ("apc40 (lost): K1"). The caller's `names` comes first. `cable_words` now calls it with the canvas port's name first, so a cable with no port reads "right hand y" where it read "hand:right.y".
**Other options:** pass routing's own apc40 glyphs as a default (routing already imports apc40, but the dispatch asked for the caller's callable).
**To reverse:** small.
**Rough edge:** "axis LX" (not "left stick x") because the gamepad's names live in gamepad.py, which imports glfw.
**Judge it:** AK.n2.

## Added after review (commit 5189232)

**47f — How `wants` finds the role of a row with no qualifier, outside MIDI.**
**Answer:** controller, 2026-10-27.
**Built:** the role is found in this order:
1. the scheme's primary (`DeviceRegistry.primaries()`: the first enabled device that publishes the scheme bare);
2. else the first listed device whose `schemes` include it, off devices included;
3. else `SCHEME_ROLE`'s usual name.

This is the canvas placeholder's rule (graphview's `by_scheme` lookup before `SCHEME_ROLE`). So a hands device listed off under another role (`hands1`) is wanted as "hands1 (off)", not as a phantom "leap (not in this rig)".
**Other options:** `SCHEME_ROLE` straight after the MIDI rule, as the spec's literal sentence has it. That names a missing "leap" while the rig lists the hands as `hands1`.
**To reverse:** two lookups in `devices.wants`.
**Rough edge:** a refused second hands device publishes no schemes, so its rows are the first one's.
**Judge it:** 399 (AK hand check 6).

**Note — "once per frame" covers the new path only.** The retry path inside `poll` still calls `_changed()` for each device whose retried `open()` succeeds, because the listeners must re-point before that device polls. This was there before T4. So two devices reopening through retry in one frame tell the listeners twice. The new end-of-frame call is suppressed whenever a retry already told them, so T4 adds no extra call. The letter of "once per frame" holds for status changes that happen inside an adapter, not for the retry path.
