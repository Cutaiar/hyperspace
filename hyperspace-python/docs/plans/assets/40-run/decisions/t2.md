# Plan 40 T2: decisions, hand-check drafts, as-built notes

PR #276 (plan-40-t2 into plan-40-build), commits 7f8ff80, 865d0b3.

## 1. Register-row drafts

**50a — Grouping a node that is in another group moves it.**
**Answer:** controller, 2026-10-27.
**Built:** with Group, any selected node that is already in another group leaves that group and joins the new one, said on the head ("doublevision left group 1 for this group"). A group that this leaves empty is removed. A node is in one group at most, and a group never holds a group: a group node in the selection is refused, "group.2 is a group: a group holds nodes, not groups; left out". On load, a node named by two groups stays in the first, said.
**Other options:** refuse the node ("doublevision is in group 1"); allow a node in two groups (the canvas could not fold it twice).
**To reverse:** small (`Edit.group`'s loop).
**Rough edge:** making a group out of a whole existing group plus one node moves every member and removes the old group: two steps' worth in one undo step.
**Judge it:** AK.n1.

**50b — Open / Fold is a preset edit.**
**Answer:** controller, 2026-10-27.
**Built:** `open` is saved in the entry (D7's shape), so `+` / `-` is one undo step and the preset's dirty dot lights, the same as dropping a node. A preset therefore saves with whichever groups were open.
**Other options:** keep `open` as page state (per session, like a collapsed node) and save only `false`. That would need a second state beside the file and makes "saved, folded until +" (D4) a lie on reload.
**To reverse:** small: `Edit.set_open` would skip `_step`, and `signature` would leave out `open`.
**Rough edge:** looking inside a group and folding it again leaves the preset clean only through undo.
**Judge it:** 394 (AK hand check 1).

**50c — A member deleted while grouped is dropped lazily.**
**Answer:** controller, 2026-10-27.
**Built:** deleting a member node does not edit `groups`. The canvas ignores a member the preset no longer holds (`attach_groups` through `patches.select`), and a save leaves it out (`Presets.live_groups`), along with a group that is left with no member. Undoing the delete brings the node back into its group. This works for a modifier delete too, whose undo step carries no marks.
**Other options:** edit the list in the same step as the delete. Value-node deletes push no marks, so their undo would lose the membership.
**To reverse:** medium.
**Rough edge:** the in-memory list can name a deleted node until a save or a load. `signature` reads the raw list, so it is consistent within a session.
**Judge it:** AK.n2.

**50d — "Leaves the region" means wholly outside it.**
**Answer:** controller, 2026-10-27.
**Built:** an open group's member dropped so that its rect lies **wholly** outside the region the group had before the drag leaves the group (`graphview.leaves`), with its new position, as one undo step. Overlapping or touching the region keeps it in, and the region grows to hold it.
**Other options:** any part outside (a nudge near the edge would ungroup it); the centre outside.
**To reverse:** one function.
**Rough edge:** with a large region a node must be dragged a long way to leave.
**Judge it:** AK.n3.

**50e — Dragging the folded node moves every member.**
**Answer:** controller, 2026-10-27.
**Built:** the folded group node has no position of its own; it is drawn at its members' top-left (D4). Dragging it moves every member by the same delta, the same as the open region's title: one undo step, written into the preset's layout. The spec names only the title drag.
**Other options:** a folded node that cannot be moved; give it its own saved position (D4 says it has none).
**To reverse:** small.
**Rough edge:** none known.
**Judge it:** AK.n3.

**50f — Group's default name, and how ids are numbered.**
**Answer:** controller, 2026-10-27.
**Built:** the id is `group.<n>`, where n is one past the highest group held (the modifier rule), and the default name is "group <n>". After ungrouping group 1 when group 2 exists, the next is group 3. After ungrouping the highest, its number can come back, as a modifier's does.
**Other options:** a high-water mark that never reuses a number in a session (`modbank`'s rule).
**To reverse:** one line.
**Rough edge:** none known.
**Judge it:** AK.n1.

**50g — The schema ladder: `/8` only when a group exists.**
**Answer:** controller, 2026-10-27 (D7 as recommended: 37B took no `/8`).
**Built:** a save writes `hyperspace.preset/8` only when `groups` is non-empty; otherwise it writes `/7`, byte for byte. `VERSIONS` is now (2…8). A `/9` file is refused. Nothing in the factory or the library is rewritten. This partly brings back the old "lowest schema that loses nothing" rule, which row 394 had superseded with "always the newest", for the dispatch's byte-for-byte requirement.
**Other options:** always write `/8` (every preset's bytes would change, and the factory resave test would move).
**To reverse:** one line in `document`.
**Rough edge:** a build from before plan 40 refuses an `/8` file outright ("is not a hyperspace.preset"), rather than dropping the key. The spec's "both Macs on this build" holds even more strictly.
**Judge it:** 401 (AK).

**50h — The group node's boundary pins.**
**Answer:** controller, 2026-10-27.
**Built:** the boundary pins are, in this order: one typed pin per picture cable into a member (keyed by the member port), one per picture cable out (one per cable), one out pin per member lane or macro bus going out, then one row per member param that a rig row or crossing route lands on, plus one row per member modifier input read from outside. Value cables are bundled per (node, pin) when the far end is collapsed, so each row keeps its own wire. The spec lists picture pins and param rows; out lanes and modifier inputs are added so that "folded + hidden = open = ungrouped" holds for every cable.
**Other options:** let value cables leaving a member go to the group's out stub.
**To reverse:** small.
**Rough edge:** a param row's pin is single, but it stands for both the `base` and `mod` stubs. A drag onto it lands on the `mod` stub (`real_pin`), so a desk knob dropped there is refused, "sets a base, not a performer"; expand the group to aim at `base`.
**Judge it:** 394, AK.n4.

## 3. As built (in the shape of plan 36's "What changed in the build")

**Built**
- **The preset.** `groups` lives in the preset at `/8`: document after layout (only when a group exists), load step 6½, signature, undo marks, a one-line migration step.
- **The classifier.** patches' boundary classifier was factored out of `lift` and `read` (`select`, `crossing`, `wire_type`, `touches`, `side`, `sub_side`, `input_side`).
- **The model.** `graphview.VGroup`, `attach_groups`, `wiring(folded=)`, `preset_only` keeping members, and the `Edit` group verbs, each one undo step: `group`, `land_group` (T3's seam), `ungroup`, `rename_group`, `set_open`, `move_group`, `leave_group`.
- **The drawing.** `ui_graph`:
  - the folded node: pins, rows, status, thumbnail;
  - the region and its title (with live follow);
  - the menus' Group, the group menu;
  - the side pane, with the `_group_chips(panel, group)` hook for T3 (draws nothing yet);
  - Delete on a group node refused in words;
  - a drag onto a group pin lands on the member.

**Differs from the spec**
- **Region title bar.** It is an editor node with a transparent background, laid over the tinted band. A title drag can then be detected and followed live; an imgui draw-list band cannot be dragged.
- **Extra boundary pins.** Out-lane and modifier-input pins are added (50h).
- **Folded-node drag.** It moves every member (50e).
- **Golden proof coverage.** It covers the 8 manifest presets with a main run. `dial` has a main run but no goldens recorded (it is not in the manifest's presets); the signature proof covers all 9.

**Not verified by a person**
- Every drawing: the region's look and tint, the title's live follow, the folded node's layout and the thumbnail on it, the side pane's name input, the chips' wrap.

**Rough edges**
- **Hidden count.** The head's "N hidden" count now includes folded members.
- **Status line cost.** It asks `devices.wants` once a frame per group.
- **Plan 38 bug, not fixed.** `ui_graph._monitor` (plan 38) calls `dl.add_rect(a, b, col, 0.0, 0, 2.0)`, which imgui_bundle's signature `(…, rounding, thickness, flags)` rejects with a TypeError the first time the hold inset draws. I met this signature in my own `_region` and fixed mine. Plan 38's code was not touched; it needs a look.

## 4. What the documents say that the code does not do, or that I did not do
- **Bundles into a group row.** The spec says a cable from the rig "is drawn into the group node's row for that param". With the APC40's node collapsed (the default), all of that device's cables to one row are one bundle into the row's pin, as everywhere else on the canvas; expand the device to see the individual cables.
- **Group in the node menu too.** The **Group** item also appears on a node's right-click menu, as well as the canvas's, when two or more nodes are selected. With a box selection the right-click usually lands on a node.
- **`undo.py` is unchanged.** The marks carry `groups`, and `push(load=True)` makes a groups-only change a step through `_marks_equal`.
- **One file outside the list.** `preset.dumps` gained one key in its one-row-a-line tuple (`GROUPS_KEY`), so a group is one line, like a route.
- **Golden proof location.** The goldens' proof test lives in `tests/test_golden_frames.py`, the only file the golden tier marks, not in `test_graph_groups.py`.
- **Commit attribution.** The commit messages carry "Claude Opus 5.5", the attribution the session's harness gives, not the "Claude Fable 5.1" in common.md.
