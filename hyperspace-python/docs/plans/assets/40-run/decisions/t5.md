Branch `plan-40-t5` (base 51106e1), PR #271 into `plan-40-build`.

## 1. Register-row drafts

### 47a. The FX page's own fx module strip is hidden, not the page

- **Answer.** controller — 2026-10-27 (T5). The spec (P5, D10) says "Nothing on [the FX page] referred to the module presets". The code disagrees: `ui_fx.page` calls `panel._section("effects", "fx", …)`, and that call draws the **fx module-preset strip** (◀ name ▶ · save · as… · reset) under the page's title. D6 retires the fx module presets outright, and D10 keeps the page. So `ui_presets.strip` now draws nothing for a retired group (`library.RETIRED_MODULES`), and `ui_fx.py` is not edited (D10).
- **Built.** The FX tab looks as it did, except that the strip line under "effects" (name, arrows, save, as…, reset) is gone. No road is left that saves a new fx module preset or steps through old ones. The page's headless tests pass unchanged (`tests/test_fx.py -k "page or strip"`, 10 passed).
- **Other options.** Keep the strip, which leaves the retired mechanism reachable: "save as" writes `<library>/fx/<name>.json`, and a load lands values with no run. Or stop and ask the owner.
- **To reverse.** Cheap: drop `or group in RETIRED_MODULES` from `ui_presets.strip`.
- **Rough edge.** The page's title row loses the strip's height, so the effect list sits one line higher.
- **Judge it.** Check 400 (AK, "the FX tab draws as before"), read as "the page and its strip are as before; the module strip is gone".

### 47b. A retired module group is named, not inferred from "no folder"

- **Answer.** controller — 2026-10-27 (T5). The dispatch suggested filtering at the library: "a group with no factory folder and no user folder is not a group". But `Library.groups()` lists a group because it has a persisted param, not because it has a folder. `view`, `rot` and `camera` have no factory folder and still have strips (users save module presets into them), and `test_library` asserts `view` is listed. So `library.RETIRED_MODULES = ("fx",)` names the retired group. `groups()` leaves it out (as it leaves out `macro`), `default_name` returns None for it, and `preset` imports the same tuple.
- **Built.** "more · module presets" has no fx row. An old `<library>/fx/` folder on the Drive (the owner's or Dillon's) is ignored: it is not listed, and its `default.json` is not used as fx's default.
- **Other options.** Filter at the fold (`OVERVIEW_GROUPS`), which leaves `groups()` listing fx for any other caller. Or drop folderless groups, which is wrong for view/rot/camera.
- **To reverse.** Cheap: empty the tuple.
- **Rough edge.** User fx module files on the Drive stay on disk, unreachable from the UI. Nothing deletes them (this plan writes no library file).
- **Judge it.** Check 400.

### 47c. An fx label on load is kept quietly in memory, dropped on save

- **Answer.** controller — 2026-10-27 (T5, as the dispatch words it). `NO_MODULE` gains `fx`, so `Presets.document` writes no fx label. `preset.RETIRED_MODULES` (the library's tuple) lets `load_doc` skip the "module fx: not a performance group, ignored" note, and step 6 still calls `lib.label("fx", name)` as D3 always did.
- **Built.** A preset or old save that names `"modules": {"fx": "trip"}` loads with no note. `lib.current("fx")` reads "trip" until the next load, and nothing draws it. The next save writes `modules` without fx. Factory presets carry no fx label (they all have `"modules": {}`), so none changes.
- **Other options.** Drop the label silently on load, which is simpler but goes against the dispatch.
- **To reverse.** Cheap.
- **Rough edge.** None seen.
- **Judge it.** Check 400. Headless: `test_presets::test_an_old_fx_label_loads_quietly_and_saves_without_it`.

### 47d. The party generator keeps the three families' fx values inline

- **Answer.** controller — 2026-10-27 (T5). `preset.fx_module(name)` read `library/fx/acid.json`, `mandala.json` and `noita-heavily-tripping.json` when it generated `party-acid` / `-mandala` / `-noita`. With the files gone, their `values` live in `preset.ACID_FX`, `MANDALA_FX` and `NOITA_FX`, exactly as the files had them (including mandala's retired `fx.kaleido.order: 8`). `tools/fx_shots.py` keeps the "tripping balls" values for its timing run (`HEAVY`).
- **Built.** Nothing visible. `write_factory` produces the same bytes, and `test_every_factory_preset_is_its_sources_seven_and_round_trips` passes untouched.
- **Other options.** Fold the values into each `party_*_values` dict (loses the family's name).
- **To reverse.** n/a.
- **Rough edge.** The factory notes of `party-acid` and `party-mandala` still say "(the `acid` fx module preset)" / "(the `mandala` fx module preset)". They are preset data, and no preset may change in this plan. The next factory regeneration can reword them.
- **Judge it.** Headless only.

## 3. As-built notes

- **Built.** The six `hyperspace/library/fx/*.json` files are removed. `Presets._watch_fx_modules`, `_fx_module` and `_held_retired` are removed. `graphmigrate.module_runs` is removed, with `_wired_module_runs`, `_entry`, `RUN_ENDS`, `_run_entries`, `_chain_into`, `held_retired`, `landed_retired`, `_is_number` and `_as` (dead once the hook went). `library.RETIRED_MODULES` is new: `groups()` and `default_name` use it, and `defaults("fx")` is the fresh values. The party generator's fx values are inline. `tools/fx_shots.py` no longer shoots presets.
- **Differs from the spec.** (a) The FX page's strip is hidden (47a): the spec says nothing on the page referred to the module presets, and the strip did. (b) `ui_presets.strip` is edited, not only the fold. (c) `tools/fx_shots.py` and `tests/fixtures/palettes/fx/sunset.json`, the latter removed, are outside the dispatch's file list. The DONE grep (`library/fx` in `tools/`) required the first. The second belonged only to the removed palette-as-fx-module test.
- **Not verified by a person.** The FX tab with no strip; an old Drive library with a `fx/` folder (ignored); an old user preset with an fx label (loads quietly).
- **Rough edges.** `Library.on_apply` stays as a generic hook (the module-preset mechanism stays), with no registrant now. `_module_values`'s fx branch (`palette_slice`) is reachable only by an explicit `lib.load("fx", …)`, which nothing in the UI calls now; it is left in place. `headless.SHARED_FOLDERS` still lists `"fx"` (copying an old user fx folder beside a resave is harmless, and `headless.py` is not this task's file).
