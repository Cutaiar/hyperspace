# N5 — controllers as nodes; the APC40 as two nodes: decisions, hand checks, as-built

Branch `plan-28-n5-controllers`, base `d94115e`, with `origin/plan-28-30-integration` 2a3599c (D3, docs only) merged in. Rows are numbered `2xx` and hand checks `Y.n`.

## 1. Register-row drafts

### 2xx. The APC40's two nodes: ids, names, and which ports each carries
- **Built.**
  - A device whose `layers` has two or more entries (today only the first MIDI role's APC40: `("preset", "global")`) is drawn as one node per layer by `graphview.device_nodes`.
  - The first node keeps N2's id `device:apc40` and its name `apc40`. It carries every control of the layout, the invariant ones included. It draws the preset layer's rows and the invariant rows.
  - The second node is `device:apc40/global`, named `apc40 (SHIFT)`. It carries every control **except** the invariant ones, and draws the global layer's rows (`bindings.json`).
  - "Invariant" is the table's own test, `Bindings.is_invariant(Binding(control, ""))`: SHIFT, plus the control of any enabled layer-None row (the crossfader / MASTER, the bank pads, transport, TAP, the band pads…). Nothing is listed by hand.
  - The first node's pins stay `out:<address>`, so a drag or Learn reads them exactly as before N5. The SHIFT node's pins are `out:<address>|global`; the port's `addr` is still the plain address.
  - Both node ids are the show's layout keys (`graphview.home`: devices are the rig's).
- **Other options.** One node with a layer toggle (the design rejected a layer view, decision 12). Ids `device:apc40` and `device:apc40.shift`.
- **To reverse.** `device_nodes` returns one node; the SHIFT node's saved position is dropped as an unknown id.
- **Refusal (review round 1, D5).** A drag from a SHIFT-node port into a `base` stub is refused whatever the latch: "<addr> on the SHIFT node is the session's (bindings.json): map it on ROUTING" (`Edit._value_refusal`). The global layer is never a Learn target.
- **Rough edge.** The global layer's rows are edited on ROUTING only.
- **Judge it.** Y.10.

### 2xx. The desk's port groups
- **Built.** The groups, in this order on each desk node: `invariant` (first node only), `track knobs`, `device knobs`, `knobs` (cue level), `faders` (track faders, MASTER, crossfader when not invariant), `clip grid` (the 8×10 field and the scene column), `buttons`. They come from the profile's control kind (`Port.group`), with knobs split by Akai's name ("track knob 3" / "device knob 1"). Inside a group the order is the layout's. A generic desk (one layer, no layout) has no ports, as before.
- **Other options.** The raw kinds (`knob`, `fader`, `grid`, `button`), which is N2's; the glyph rows (G1…G10).
- **To reverse.** `graphview.desk_group` / `DESK_GROUPS`.
- **Rough edge.** An invariant fader (the crossfader) sits in `invariant`, not `faders`.
- **Judge it.** Y.10.

### 2xx. How the SHIFT latch is read: the table's `layer_of(role)`, in `refresh`
- **Built.**
  - `MidiIO` does not own the latch. It reads `Bindings.layer_of(role)`, which `desk.shift` sets, and the page reads the same value.
  - Each frame, `graphview.refresh` sets each layered node's `up` (its layer is the one up on its role) and each port's `up` (an invariant port, layer "", is always up).
  - A cable from a port whose layer is down is **dormant** (faint), the same as a lost device's.
  - On the page, the down node's title and ports are faint; an up layer's ports are drawn bright (`ui.TEXT`), and invariant ports stay `ui.DIM`.
  - A latch flip rebuilds nothing, because `key` does not move.
- **Other options.** Read `desk.shift` from the registry (the first role only). Add an `up_layer` property on `MidiDevice` (devices.py was not needed for it).
- **To reverse.** The block at the top of `refresh`.
- **Rough edge.** A second MIDI desk with no latch of its own is one node (its `layers` is `("preset",)`), and so is never faint.
- **Judge it.** Y.10.

### 2xx. A layered row on an invariant control is drawn off
- **Built.** A preset-layer or global-layer row whose control is invariant never acts and never lights (D6). Its cable is `off` (dormant), and its hover says "(under an invariant control)". It leaves that control's port on *apc40*, in the `invariant` group (review round 1), never a port on the SHIFT node. So "invariant controls on *APC40* only" holds even for such a row.
- **Other options.** Hide it.
- **To reverse.** The `shadowed` line in `build`.
- **Rough edge.** None known.
- **Judge it.** Headless (`test_the_apc40_is_two_nodes_…` covers the layers; no factory row is shadowed today).

### 2xx. A desk template is a subgraph node: its ports are its controls; collapsed, its rows are not drawn
- **Built.**
  - When the loaded preset names a `desk_template`, the page passes `(name, rows)` to `build`. These are the rows as the load expanded them, the same ones a save compacts against (`ui_graph.template_of`).
  - `build` draws one node, `template:<name>` (kind `template`, column 0, saved in the **preset's** layout). It has one port per template row, named "<control> → <target>", with pins `out:<address>|template`.
  - A live preset-layer row that is still the template's (same control, target, op and value: `compact_desk` would write no override for it) is a cable from that node, with `VCable.inside = "template:<name>"`.
  - An override, or any row on a control the template does not map, hangs off *apc40* as before.
  - A template control that was overridden or darkened is a port with no cable (unpatched).
  - The page starts every template node collapsed: its ports are listed and none of its cables is drawn. Its **+** opens it (`ui_graph.is_open` / `toggle_open`, state `st["open"]`) and its rows draw as cables; **−** collapses it.
- **Other options.** Collapsed, draw one bundled cable per target node. Put the overrides inside the subgraph too.
- **To reverse.** The template block in `build`, plus `template_of` and `drawn_cable` in `ui_graph`.
- **Rough edge.**
  - While the node is collapsed, the params its rows set still show a patched `base` stub with no visible cable. The stub's hover names the template: "set by desk template <name> (collapsed: + shows it)" (`ui_graph.hidden_by`, review round 1).
  - `template_of` reads the new public `Presets.template_at_load()` (what a save compacts against). It falls back to the library's file.
- **Judge it.** Y.11.

### 2xx. An edit inside a template is an override, through the same calls
- **Built.** Nothing new was written for this; the existing calls give it:
  - Deleting a template row's cable is `Edit.disconnect`, which calls `table.remove` (a preset-layer row). The next save writes a dark row for that control.
  - Dragging a template port onto a `base` stub is `Edit.connect`, which goes to the desk learn (`learn_control`). That replaces the template's row on that control, and the save writes it as an override.
  - The new row is no longer the template's, so its cable then leaves *apc40*.
  - The template file is never written.
- **Other options.** Template-level edits that rewrite the template file (rejected: the template is shared by every preset that names it).
- **To reverse.** n/a.
- **Rough edge.** After an edit, the cable "jumps" from the template node to *apc40*. That is honest (it is now an override), but it can surprise.
- **Judge it.** Y.11.

### 2xx. Roles, not serials: a grey placeholder `device:<role>`
- **Built.**
  - A row from a role the rig lists no device for draws from a grey node `device:<role>` (kind `device`, `placeholder=True`, status "not in this rig: its cables wait for it"). Its cables are dormant.
  - The role is chosen in this order:
    - the row's qualifier (`axis@p2` → `p2`, `cc@launch` → `launch`);
    - for an unqualified MIDI row, the desk's first role;
    - otherwise the kind's usual role from `config.py`'s example list (`hand`/`hands` → `leap`, `axis`/`pad`/`hat` → `pad`, `cc`/`note`/`pitch` → `apc40`);
    - for any other scheme, the scheme itself (an OSC device's scheme is its role).
  - Because the id is the real device's, a device of that role arriving takes the placeholder's saved position.
  - The keys stay their own `source:key` node, as N2 had them.
  - Fixed on the way: N2 drew a qualified MIDI row (`cc@launch:…`) with no such device from the first desk's node. It now gets its own placeholder.
- **Other options.** Keep N2's `source:<scheme>` nodes.
- **To reverse.** The placeholder branch in `source_pin`, plus `SCHEME_ROLE` / `NO_DEVICE`.
- **Rough edge.**
  - With no desk listed there is one placeholder, not two. Its preset-layer and global-layer rows on one control share one pin, dormant either way.
  - `SCHEME_ROLE` guesses the role of an unqualified row whose scheme no listed device publishes from `config.py`'s example names. A rig that names its hands role differently gets a placeholder called `leap`, and the real device takes its own id, not the placeholder's place.
- **Judge it.** Y.12.

### 2xx. The hands node's groups: axes, pinches, grab, presence, dance
- **Built.** The groups are `hands/device.py`'s own, except that its `switches` are told apart by address: a `.grab` port goes in `grab`, every other switch in `pinches`. The order stays the device's. Nothing in the hands package changed (`test_hands_boundary` is untouched).
- **Other options.** Add the two groups in `hands/device.py` itself (it would be cleaner there, but the hands package stays as it is in this run).
- **To reverse.** `graphview.hand_group`.
- **Rough edge.** `presence` is a fifth group the design did not name.
- **Judge it.** Y.10.

## 2. Hand-check drafts (plan 28)

**Y.10 — The APC40 as two nodes with the real desk, SHIFT latched and released.**
- **Headless:** `test_the_apc40_is_two_nodes_and_each_row_hangs_off_its_layers_node`, `test_invariant_controls_are_ports_on_the_first_node_only`, `test_the_hands_node_groups_axes_pinches_grab_and_dance`.
- **Setup:** the rig, with the APC40 connected; load party-trip; open GRAPH, turn **patched only** off on both desk nodes.
- **Steps:**
  1. Look at *apc40* and *apc40 (SHIFT)*.
  2. Press SHIFT on the desk (it latches). Press it again.
  3. With the Leap on, look at the hands node's folds.
- *Pass:*
  - two nodes. *apc40* lists `invariant` first (SHIFT, the bank pads, transport, TAP, the crossfader / MASTER), then the knobs, faders, clip grid and buttons. *apc40 (SHIFT)* has no invariant control.
  - the band-strip knobs' cables (`band.sel.*`) leave the SHIFT node; the preset's knobs leave *apc40*.
  - latched: *apc40 (SHIFT)* is bright and *apc40*'s preset ports and cables go faint, while its invariant ports stay as they were. Released: back. The desk's own rings and LEDs behave exactly as before N5.
  - the hands fold as axes, pinches, grab, presence, dance.
- *Fail:*
  - nothing changes on latch: `refresh` not run (the page not open), or the table's latch is not the one SHIFT flips;
  - a control on both nodes that should be invariant: `is_invariant` lacks a row.

**Y.11 — A templated desk on the canvas.**
- **Headless:** `test_a_templated_desk_is_one_collapsed_node_whose_edits_write_overrides`, `test_a_factory_preset_draws_no_template_node`.
- **Setup:** a scratch library with the plan 24 C3 fixture template and preset (`tests/fixtures/desk-templates/`) copied in; load TEMPLATED; open GRAPH.
- **Steps:**
  1. Find *template fixture shape*. Press its **+**.
  2. Delete D1's cable.
  3. Drag D3's template port onto `view.speed`'s square `base` stub.
  4. Save as a new preset and open the file.
- *Pass:*
  - collapsed, it lists 7 controls ("D1 → view.depth4" …) and draws no cable; opened, 5 cables. D2 (`dream.mix`) and K3 (`view.pattern_mix`) leave *apc40*. K2 and D2's template ports have no cable.
  - after steps 2–3 the file has `"desk_template": "fixture shape"` and `"desk"` with a dark `cc:*:16` and the `cc:*:18 → view.speed` override. The template file is unchanged.
- *Fail:*
  - no template node: `template_of` found no `template_of_loaded`;
  - the template file changed (it must never be written).

**Y.12 — A SHIFT-layer cable in bindings.json, a preset-layer one in the preset; a missing role.**
- **Headless:** `test_a_missing_role_is_a_grey_placeholder_with_dormant_cables`; N3's `test_deleting_a_cable_removes_the_route_and_undo_puts_it_back`.
- **Setup:** the rig.
- **Steps:**
  1. Select a `band.sel.*` cable on *apc40 (SHIFT)* and press Delete.
  2. Select a preset knob's cable on *apc40* and press Delete, then ⌘Z.
  3. Unplug the pad (or list a `p2` row with no second pad).
- *Pass:*
  - step 1 is refused with "… is the session's (bindings.json): edit it on ROUTING", and `bindings.json` is unchanged;
  - step 2 removes the row from the preset (dirty dot), and ⌘Z puts it back;
  - a row from a role the rig lacks hangs off a grey node named by that role, faint; plugging in or listing the device lights it in place.
- *Fail:*
  - a placeholder named after a scheme (`axis@p2`): `SCHEME_ROLE` or the qualifier was not read.

## 3. As-built notes

### What was built (N5)
- **`hyperspace/graphview.py`.**
  - Model fields:
    - `VPort.layer` / `up`;
    - `VNode.layer` / `role` / `up` / `placeholder`;
    - `VCable.inside`;
    - kind `template` (in `KINDS`, column 0, preset home).
  - The controllers section: `PRESET_LAYER`, `GLOBAL_LAYER`, `TEMPLATE`, `LAYER_LABEL`, `INVARIANT`, `DESK_GROUPS`, `SCHEME_ROLE`, `NO_DEVICE`, `PLACEHOLDER_STATUS`; `desk_group`, `hand_group`, `device_nodes` (N2's `device_node` kept as its base), `template_rows`.
  - `build(..., template=)`, which adds the layered port pins (`add_layer_port`), the template node, `row_pin` (a desk row's node by layer and template) and the placeholder branch in `source_pin`.
  - `refresh` reads the latch.
  - `Edit` is untouched.
- **`hyperspace/ui_graph.py`.**
  - `template_of`, `is_open`, `toggle_open`, `drawn_cable`.
  - `shown` lists every port of a template node.
  - `_node`: the template node's **+** opens it; a down layer's title is faint.
  - `_port`: an output port is lit or faint by its layer.
  - `_canvas` skips the cables of a collapsed subgraph; `_place` lays a template node out at full height.
  - `view_of` passes the template.
  - The `CREATE` / `DELETE` tables and `_state` are untouched (the open set is made by `setdefault` in `is_open`).
- **`devices.py`** is unchanged: `Base.layers` already existed and `MidiDevice.layers` gives the two.
- **Tests.**
  - `tests/test_graphview_devices.py`: 6 tests, the four the prompt names, plus the hands groups and no template node on a factory preset.
  - `tests/test_graphview.py`: one assertion changed (the hands' `switches` → `pinches`).
- No fixture added: the plan 24 C3 fixtures (already tracked) are reused.

### What no person has verified
- The two nodes at the machine with the real desk and the latch.
- The template node's look and its **+**.
- Legibility of the faint / bright ports at the rig's font size.
- The placeholder's look.

### Known rough edges
- (Fixed in round 1: a drag from a SHIFT-node port into `base` is refused whatever the latch.)
- A collapsed template's targets show patched `base` stubs with no visible cable.
- A placeholder desk is one node.
- (Fixed in round 1: `template_of` reads the public `Presets.template_at_load()`.)

## 4. Where the documents and the code differ
- The design says "each port sending only while its layer is up, a press belonging to the node that was up when it went down (D12)… rings and LEDs follow the node that is up". That is the desk's behaviour, which is unchanged and not N5's. N5 only draws it: ports lit or faint, cables dormant while their layer is down.
- "the hands' groups: axes, pinches, dance, grab": the code also keeps `presence` (the device has it).
- The brief says "the latch read through the registry". It is read from the table the registry's desks share (`Bindings.layer_of(role)`), which is what `MidiIO` itself reads. Nothing in `devices.py` needed exposing.
- No `docs/` file was edited.
