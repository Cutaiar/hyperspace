## Register rows (summary)
- 291 The slice: `hue_from` → `hue_to` going up the wheel (through 360 when to < from), plus `hue_turn` (wraps) added to both ends; from = to is one hue; 0 → 360 is the whole wheel; the ends don't wrap (so 360 can stay 360). Defaults are the whole cylinder: the identity on an opaque ground. Checks 267, 269. (Fix round 1: hue_turn added.)
- 292 The hue map: the old triangle fold, bit for bit, for arcs up to 180°; above that the peak slides (`smoothstep(180,360,arc)`) to the identity at 360°. The reason: a continuous map from the circle onto a partial arc can't be the identity, and a linear map would put a seam through every red. Checks 267, 268.
- 293 Sat and val are a linear map (`mix`), never a clamp. Checks 267, 268.
- 294 from > to inverts and is allowed. Check 269.
- 295 Old documents are read as the slice on load (`palettecompat.palette_slice`): values (any instance), routes, desk rows, macros. Centre rows go to `hue_turn`. A centre set outright (a position route or a base sub) becomes the turn, with the arc laid about 0. Width pushes and their depth subs split onto both ends. A width base sub is converted when it stays inside 0–360, otherwise dropped with a note. A note appears only when the palette would show the change (on with mix > 0 or a row naming it, compress mode, wider than 180°). Check 271. (Fix round 1.)
- 296 `// @param choice [a|b] n "Label"` makes an enum (`Kind.ENUM`), drawn as a combo. Check 270.
- 297 The strip: mode combo, a "compress into" line, and hue/sat/val as one row each (`from → to`), with a hue bar. sat/val were renamed `_lo/_hi` → `_from/_to` so all three rows read the same way. Check 270.
- 298 The gradient map is kept as the second mode. It's a different transform (paints by brightness). Check 270.
- Amended: 135 (an identity now exists), 136 (mode is now a choice), 138 (superseded by 291–294), 139 (the palette's rows, 297). Row 134 is unchanged (the ids are still `fx.palette.*`).
