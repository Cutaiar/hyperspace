# N3 — editing the modulation on the canvas: decisions, hand checks, as-built

Branch `plan-28-n3-edit-modulation`, base 5ab9458, with `origin/plan-28-30-integration` d5d905f (D2) merged in. Rows are numbered `2xx` and hand checks `Y.n`.

## 1. Register-row drafts

### 2xx. A cable into `mod` makes the row a hand learn would make, through `learn.row_for`
- **Built.**
  - Dragging a source onto a param's round `mod` stub calls `Bindings.add` with the row `learn.row_for` returns. `row_for` is `Learn._row`'s table moved out to module level, with no behaviour change. It gives:
    - a **push** when the source is centred (the device port's `bipolar`: a hand's roll, a stick) or the param is centred on zero;
    - otherwise the **position** fader at depth 1.
  - A hand push lands at the hands' own Learn depth (`hands.learn_depth`); any other source's push lands at `PUSH_DEPTH`.
  - If the param already has a performer, the result is `Ask`, and the page puts up ROUTING's Replace / Keep prompt (`ui_routing.ask`). Replace calls `replace_owner`.
  - A desk knob, a pad button or a key dropped on `mod` is refused: "a desk knob sets a base, not a performer; aim at base".
- **Other options.** The prompt's literal rule: push only for a hand axis, otherwise position at 1. That would land a band onto a centred param (`rot.rate.*`) as a fader pinned at one end.
- **To reverse.** Have `Edit.route_for` build the row itself.
- **Rough edge.** A source the device registry does not list (no tracker connected, so its ports are only row-made) is never read as centred. Its cable lands as position, unless the param itself is centred.
- **Judge it.** Y.6, Y.7.

### 2xx. `base` takes desk and pad setters only, through the learns' own roads; the refusal words
- **Built.**
  - A desk control (`cc` / `note` / `pitch`, any qualifier) dropped on `base` goes through a private `Learn(...).learn_control`. That is the desk learn: a preset-layer `abs` row (a `toggle` for a note or a trigger param), `bind(write=False)`, and the same refusals for an invariant control, the global layer and SAVE.
  - A pad button or the D-pad goes through `Learn.learn_pad_button`. That gives the session's row, `bindings.json` is written, and it is not an undo step, exactly as the pad learn behaves today.
  - A hand is refused with "a hand sets no base; aim at mod". Other lanes get the same words with their own noun: "a band", "an LFO", "a modifier", "a stick".
  - A key is refused with "keys are the session's rows: map them on ROUTING".
- **Other options.** The prompt's literal row for a pad, `Binding(src, pid, "abs", layer="preset")`. That is an `abs` row on a button, which does nothing useful, and `is_session_row` would class it as the session's anyway.
- **To reverse.** `Edit._setter`.
- **Rough edge.** A pad setter writes `bindings.json` immediately and cannot be undone, as the pad learn does today. The private Learn's "learned …" words are not shown on the footer; only refusals reach the page's head.
- **Judge it.** Y.7.

### 2xx. A cable's end is moved by dragging from where it lands; two input pins mean "move"
- **Built.**
  - The widget cannot pick up an existing link, so a drag that starts on a **patched input pin** (a route's `mod` stub, a modifier's `in`) and ends on another input pin moves that cable.
  - A route moves with `move_route(target=…)`: same op and depth, and its macro depth subscribers follow it.
  - If the new param already has a performer, it asks. Replace is `replace_owner(row, target=…)`.
  - A modifier input moves its source to the other modifier's input.
  - A drag between two input pins with no cable is refused with "join an output to an input".
- **Other options.** Ctrl-drag; a "move to…" item on the cable's menu.
- **To reverse.** `Edit.move`.
- **Rough edge.** The source end cannot be moved by a drag. Delete the cable and draw a new one, or insert a modifier.
- **Judge it.** Y.6.

### 2xx. A modifier dropped onto a cable: free node, released over the widget's curve
- **Built.**
  - When a **modifier node with no cables** is let go, its centre is tested against every route and modifier-input cable, using the cubic the widget draws: handles at `link_strength` 100 canvas units, sampled 16 times (`graphview.bezier` / `cable_near`).
  - If the centre is within 14 canvas units of one, the modifier is inserted into it (`Edit.insert_modifier(cable, mod id)`):
    - the cable's source becomes the modifier's first input;
    - the modifier's lane becomes the cable's source (`move_route`; op and depth kept);
    - a push keeps its old source's rest (`Router.rest_of`), so a centred hand stays centred through a smooth.
  - A cable's right-click **insert ▸ <kind>** does the same with a new modifier.
- **Other options.** Use the mouse position rather than the node's centre; the widget's own hovered link (while dragging a node, the node covers the cable).
- **To reverse.** `ui_graph.dropped` and `_moved`'s two lines.
- **Rough edge.** Pin positions are last frame's pin centres, not the widget's exact pin pivots. A modifier that is already patched is never inserted by a drop: unpatch it, or use **insert**.
- **Judge it.** Y.6, Y.8.

### 2xx. The node picker: modifiers by kind, idle macros
- **Built.**
  - Right-click on the empty canvas opens **add ▸ modifier ▸ curve · scale · smooth · combine · threshold · delay** (`Bindings.add_modifier`) and **macro ▸ <the idle macros>**.
  - Every macro is already a node, because its knob is modulatable. Picking one labels it "macro N", so ROUTING's strip names it too.
  - The new node lands where the menu opened, saved in the preset's layout.
  - A modifier or macro node is deleted from its right-click **delete** or with the Delete key:
    - a modifier's lane routes stay, dormant (N1's rule); the widget deletes the node without its links;
    - a macro loses its label and subscribers, and the knob stays.
  - The rig's nodes are refused with "<label>: the rig's, not the preset's".
- **Other options.** Hide idle macros from the canvas; the picker on a drag into empty space (`query_new_node`).
- **To reverse.** `ui_graph.picker` / `macros_free`, `Edit.show_macro`.
- **Rough edge.** The label "macro N" dirties the preset. Removing a macro node clears a label the owner typed.
- **Judge it.** Y.8.

### 2xx. A macro dropped on `mod` is refused in words
- **Built.** A cable dragged from a macro's `bus` output onto a param's `mod` stub is refused, and the page says "a macro sets a base or scales a depth; aim at base or a depth stub". A macro can only land on a `base` stub (a base subscriber) or on a route's `depth` stub (a depth subscriber).
- **Why.** The design's first sentence ("Drag from a source, modifier or macro port to a param's `mod` port → `Bindings.add`") lists a macro port among the things that become a route. But a macro is a param, not a lane: no Router scheme publishes a macro's knob, so a route with a macro as its source would sit dormant forever. The design's own "Drag from a macro → a `Sub`" is what the code builds.
- **Other options.** A route sourced from a macro, which would need a new `macro` lane scheme fed by `follow_macros`.
- **To reverse.** Moderate: publish the macros as a lane in `Router.follow_macros`, then drop the `MACRO_NO_MOD` branch in `Edit._macro_refusal`.
- **Rough edge.** A performer who wants one knob both to set a base and to drive a param's modulation has to use two subscribers, or route the desk knob itself.
- **Judge it.** Y.7 (the head's words when a macro is dragged onto `mod`).

### 2xx. Deleting a macro node clears its label and every subscriber
- **Built.** A macro node's Delete (the key, or its right-click **delete**) rewrites the table's macros without that macro (`set_macros(macros_doc() minus it)`). Its label and every subscriber go, and the knob itself stays: the eight `macro.*` params are the rig's. It is one undo step ("delete node macro.N"). On ROUTING's macro strip the knob shows with no label and no subscribers.
- **Other options.** Refuse deleting a macro node, as for the rig's other nodes. Or remove only its subscribers and keep the label.
- **To reverse.** One branch in `Edit.remove_value_node`.
- **Rough edge.** A label the owner typed is lost with it; ⌘Z brings it back.
- **Judge it.** Y.9 step 3 (added by N6: the node delete; hand check 250).

### 2xx. Deleting cables: the preset's go, the session's are refused
- **Built.**
  - The Delete key on a selected cable, or the cable's **delete**:
    - a route is removed with `remove` (its depth subscribers go with it);
    - a preset-layer desk row is removed, and the desk is redrawn;
    - a macro subscriber is taken out of its macro;
    - a modifier input is unset.
  - A session row's cable (keys, the pad, an invariant or global-layer desk row: `is_session_row`) is refused with "<source> is the session's (bindings.json): edit it on ROUTING".
  - Each edit is one named undo step ("delete cable …", "connect … → …", "insert smooth into …").
- **Other options.** Let the canvas edit `bindings.json` too.
- **To reverse.** `Edit.disconnect_value` and `ui_graph._value_cut`.
- **Rough edge.** None known.
- **Judge it.** Y.9.

### 2xx. The seam with N4: dispatch by type, N4's methods by name
- **Built.**
  - `graphview.Edit.connect` / `refusal` / `disconnect` / `remove_node` send any request that touches an `image` / `geometry` / `mask` pin (`rout:` / `rin:`), a `render` cable or a render or output node to `Edit.wire(src, dst)`, `Edit.unwire(cable)` and `Edit.remove_render_node(nid)`, plus an optional `Edit.wire_refusal(src, dst)` for the drag's words. These are looked up by name, and until N4 adds them the request is refused with "render cables: not yet".
  - On the page, `ui_graph.CREATE` maps a drag's type to a handler. `value` and `trigger` map to `_value_drag`; `image`, `geometry` and `mask` map to `_render_drag`, which refuses.
  - `ui_graph.DELETE` maps a cable kind to a handler. route, setter, sub and input map to `_value_cut`; render maps to `_render_cut`, which refuses.
  - N4 replaces the render entries and adds its methods; nothing in N3's functions changes.
  - The node delete is the `DELETE_NODE` table by node kind (fix round 1; N4 filled its render and output entries).
- **Judge it.** Headless only: `test_render_pins_are_n4s_and_refused_in_words_until_then` and `test_create_and_delete_open_only_in_the_typed_dispatch`.

## 3. As-built notes

### What was built (N3)
- **`graphview.py`.**
  - `VPort.bipolar`, set from the device port.
  - The editing section: `Refusal(str)`, `Ask(old, new, commit)`, the refusal words as constants, `pin_kind` and `is_output`.
  - `Edit(table, reg, router, view, profile)` with these methods:
    - requests: `connect`, `refusal`, `connect_value`, `route_for`, `subscribe`, `set_input`, `move`, `disconnect`, `disconnect_value`, `add_modifier`, `insert_modifier`, `show_macro`, `remove_node`, `remove_value_node`;
    - the dispatch by type and name: `is_render`, `_render`.
  - Drop geometry: `bezier`, `cable_near`.
  - It now imports `learn` (which precedes `graphview` in `hotreload.MODULES`) and more names from `routing`. It still imports no imgui.
- **`learn.py`.** `row_for` at module level; `Learn._row` calls it.
- **`ui_graph.py`.**
  - State keys via `setdefault`: `note`, `pin_xy`, `menu`, `menu_at`.
  - Page functions: `edit_of`, `connect`, `disconnect`, `insert_modifier`, `add_modifier`, `show_macro`, `remove_node`, `dropped`, `macros_free`, `menu`, `picker`, `port_param`.
  - Canvas handlers: `_create` / `_delete` with `CREATE` / `DELETE`; `_menus` (the pin, link, node and background context menus, drawn suspended); `_pin_menu` (calls `Panel._ctx_learn_block`, shared with the widgets' menu since fix round 1).
  - The head shows the last refusal, otherwise a hint.
  - `_moved` calls `dropped` for a modifier.
  - Each pin records its canvas centre.
- **Tests.**
  - `tests/test_graph_edit.py`: 14 tests, the eight the prompt names plus the N4 seam, the picker and delete, the menus drawn, the curve test, the create / delete dispatch pin, and a canvas route being the preset's.
  - `tests/test_graphview.py::test_the_page_is_read_only` was removed. N2's own docstring said "N3 and N4 open them"; its replacement is `test_create_and_delete_open_only_in_the_typed_dispatch`.

### What no person has verified
- Every gesture on a real canvas: the drag itself (`query_new_link` reporting the pin pair, the reject colour and tooltip), the Delete key's queries, the four context menus opening on the right subject, the picker's drop position (assumed canvas units inside the editor), and a node dropped on a cable.
- The headless tests drive the page's functions and draw the menus, but cannot simulate a mouse drag on the widget.
- The windowed smoke run called the page's `connect` / `insert_modifier` from inside the live draw loop; it did not drag.

### Known rough edges
- The source end of a cable cannot be dragged.
- A pad setter is not an undo step (as the pad learn).
- "macro N" labels dirty the preset.
- Drop detection uses last frame's pin centres.
- The private Learn's success words are not shown.

## 4. Where the documents and the code differ
- **The prompt's pad base row** (`"abs", layer="preset"` through `bind(write=False)`). The code uses the pad learn's own row (toggle, step or fire; the session's). The design's "as a desk learn does" is read as "as the learns do" (row above).
- **"push at the hand learn's depth for a hand axis, else position at 1".** The code follows `learn._row`'s full table, which the same sentence names (row above).
- **"From a macro → a Sub".** A macro dragged onto a `mod` stub is refused; only `base` and `depth` take one.
- **The picker's macros.** Every macro is already a node in N2's build, so the picker offers the idle ones and names them, rather than adding nodes.
- No `docs/` file was edited.
