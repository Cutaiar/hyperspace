## 1. Register-row drafts

### 2xx. The placement keys are `after` and `into`, both kept

- **Built.** An effect node in a preset's `graph` section may carry
  `"after": "<node>"` or `"into": "<node>"`, never both:
  - `after` puts the effect on that node's picture, and every consumer of it reads the effect;
  - `into` puts it on that node's `image` input alone.

  A placed effect may name instance 1 (`{"kind": "effect", "file": "palette", "after": "hands"}`), which takes the file itself out of the chain. An unplaced instance 1 is still refused with "2 or more", as A4 did. The section writes instance 1 by its file alone, and an extra instance with `instance`.
- **Other options.**
  - One key with a port suffix (`"at": "output.2.image"`): it reads less plainly and needs a port vocabulary that N4's wires will bring anyway.
  - Drop `into` and express "into output.2" as `after: output.2`.
- **To reverse.** `EffectAt`, `_effect_entry`, `GraphSpec.to_json`, and the three fixtures. N4 reads both keys as wires.
- **Rough edge.** `after: output.<n>` is accepted and means the same as `into: output.<n>` (an output has no picture of its own to come after). Both forms are written back as the file had them.
- **Judge it.** X.4, X.5.

### 2xx. The placeable vocabulary and which key each name takes

- **Built.** The placeable names are `scene`, `hands`, `hands.<n>` (n ≥ 2), `history`, `output.<n>` (n ≥ 1), and an effect instance this build has. "This build has" means a file on disk, or an extra instance the same section declares.
  - `into` takes only the history, an output or an effect. The scene's and a hands layer's inputs are geometry, so `into: scene` / `into: hands` are refused with "its inputs are geometry, not a picture: after 'scene' folds its picture".
  - An effect cannot sit after or into itself.
  - Read with no list of files (pure `read_graph(section)`), any well-formed effect name is accepted. A file that is missing at build is then dormant.
  - The note's words: `graph: palette after 'teapot' — this build places after scene, hands, hands.2 …, history, output.1 …, or an effect; the default placement`. For `into`, the list reads "history, output.1 …, or an effect".
- **Other options.** One list for both keys, which would let `into: scene` mean `after: scene`. That hides a mistake.
- **To reverse.** `placement_error`, `_PLACE_NODE` / `_PLACE_EFFECT`, `PLACE_WORDS`.
- **Rough edge.** `hands.<n>` is placeable only when that node makes the layer (one layer per graph). Otherwise it is dormant, "no hands.2 layer this frame".
- **Judge it.** X.6.

### 2xx. A refused placement costs only that effect its place, not the graph

- **Built.** Both keys at once, a non-string, a name outside the vocabulary, or a loop of placed effects each give a note on the preset strip ("graph: …; the default placement"). That effect goes back to the default placement: an extra instance stays in the chain at its order, and instance 1 is the file, always in the chain. The rest of the graph lands. The section is kept as the file had it, so a save does not drop it.
  - `read_graph` returns these in `GraphSpec.notes` (compare=False, so a spec still round-trips equal).
  - `GraphSection.read` is now an instance method, so it can pass the FxState's files.
  - Anything else unreadable still raises `GraphError` and gives the default graph, as A4 does.
- **Other options.** Treat a bad placement like any unreadable section: the note "; the default graph" and the whole section dropped. That is simpler, but it contradicts the prompt's words "the default placement" and loses the hands wiring for one typo.
- **To reverse.** `_effect_entry`'s tuple, `read_graph`'s notes, `GraphSection.read`.
- **Rough edge.** The kept section means a later save writes the refused placement back unchanged. That is intended, but a person fixing it must edit the JSON (or use N4's editor).
- **Judge it.** X.6.

### 2xx. A loop is refused at read and again at build, with the loop in words

- **Built.** `placement_loops` follows each placed effect's target through other placed effects. Every effect on a loop gets the note `palette after 'acid.2' — that makes a loop (palette after acid.2 into palette)` and the default placement. `default_graph` checks again (`Graph.notes`, the same words plus "; the default placement") and puts those effects back in the run, so a hand-built `Wiring` cannot loop either. `Graph.insert` also refuses an edge whose consumer is upstream of the node; this cannot happen past `placement_loops`, but it guards the sorter, which has no loop check of its own.
- **Other options.** Detect only at build, using the graph's sort.
- **To reverse.** `placement_loops` and its two callers.
- **Rough edge.** Every member of a loop is refused, not just the last one named.
- **Judge it.** X.6.

### 2xx. A placement on a node the built graph lacks is dormant: no node, words on OUTPUT

- **Built.** `default_graph` builds no node for a placed effect whose target is absent this frame, and records why in `Graph.dormant`. The cases:
  - `palette after hands — no hands layer this frame`;
  - `palette.2 into output.3 — no output 3 this frame`;
  - `… — output 2 shows no picture this frame` (its scene is off and no hands go through);
  - `… — no kaleido effect in this build`;
  - `warp after palette — palette is dormant this frame`.

  The effect does not fall back into the chain: it is placed, just not built. The OUTPUT page lists `dormant: …` lines under the output blocks (`ui.dormant_lines`), and the "shows:" hover uses `graph_words(spec, graph.dormant)`. The graph is rebuilt whenever the switches change, so a placement comes back as soon as its node exists.
- **Other options.**
  - Put a dormant effect back in the chain run. That would bend the whole picture when the preset said to bend only the hands.
  - Keep a node with no input.
- **To reverse.** `_place_one`'s returns and `Graph.dormant`.
- **Rough edge.** Dormancy follows the graph's key, which is the switches. It does not follow "a hand is visible": with the hands switch on and no hand in the box, the palette node exists and simply has nothing to fold (no pass).
- **Judge it.** X.7.

### 2xx. How an effect sits on an edge: made once in `run` after a texture, folded by the output into an output

- **Built.**
  - **After the scene or a hands layer** (`Node.MAKES`), or after such an effect: in its own `run`, the effect folds that texture once into a held pool texture (`Effect.makes`, `_made`). Every consumer reads that one picture, and a source with no picture (no hand drawn) gives none. Making it in `run`, before any pipeline paints, means the held texture can never be a consumer's target (D0's aliasing constraint, met by construction).
  - **On a layer** (`see_through`): its pass runs with `u_opaque = 0`, so a see-through pixel stays see-through (`FxChain.run_one(…, opaque=0)`). It is laid on at the layer's `ghost.alpha` with the layer's depth. The output lays it through `Renderer.lay`, whose "over" is the same arithmetic as `Ghost.composite`. The layer's readout is then split always, so the guide and labels are never folded.
  - **After or into a painted node** (the history, an effect of the run): D0's paint path is unchanged, and the effect is held when it has two readers.
  - **Into an output:** the effect sits on the output's `image` port (`Output.folds`). The output folds the frame texture it settled on into a held pool texture and shows that. The output's pipeline is then never painted direct.
  - `after:` rewires every consumer's image port except the ones that read something else of the node (`Node.REFS`: the cover's face buffer, `depth`, `readout`).
  - After an effect of the run: one node per pipeline (`palette`, `palette(scene+hands)` …).
  - The pool is 2, plus one per held effect (two readers), plus one per placed effect that makes a texture or folds an output.
  - A placed node is listed right after its source, so it sorts (and SYSTEM lists it) under its source.
- **Other options.**
  - Paint the layer through the effect on demand at each consumer: either one pass per consumer, or the D0 aliasing risk in `Effect.image(None)` from a `lay`.
  - An output-fold node that re-runs the pipeline into the effect: two runs of the chain.
- **To reverse.** `Effect.run` / `_made` / `fold` / `_one`, `Output.folds` / `run`, `Fx.run`'s direct test, `Graph.pool`, `Graph.insert`.
- **Why the node decides `opaque` (review round 1).** `opaque` is a property of what the effect folds, not of the edge it sits on: a layer's picture is premultiplied over a see-through ground wherever it is read. So `Effect.see_through` walks back to the source and gives `u_opaque = 0` for a layer whoever consumes it, and a consumer never has to know. D2 and N4 inherit this: an edge carries no `opaque`, and a wire from a layer into any port keeps the ground see-through.
- **Presenters (review round 1).** The projector and the glass are presenters on the rig (`app._open_presenters`, `slots[1:]`). An output laying an effect hands `_compose` the effect's folded texture (`hands_tex`), so a presenter's `Handoff.hands` is the folded layer. `Effect.ghost` passes through to the layer's own Ghost, so with `hands.2` making the layer the presenter gets ghost 2's opacity, as before D1. An output folded by `into:` hands its presenter the folded frame. The `Handoff` docstring now says `frame` / `hands` may be a half-float pool texture: `Presenter._ext` wraps every name as "f1", which declares only the wrapper's dtype, and a shader samples by name whatever the real format.
- **`fx_on` (review round 1).** The renderer's `fx_on` is "an effect of a chain run is on": `chain(FRAME)` minus `Graph.placed_names`. With only placed effects on, a through output stands down as with none: no SCENE+HANDS run, no second frame texture, `chain_runs` 0. The placed effect still runs, and its clock moves in `run_one`, or through the capture's advance when its edge had nothing to fold. The OUTPUT page reads it from `stats["fx_on"]`.
- **Rough edge.** A presenter's frame or hands may be half float (see above). This is plan 26's Handoff contract, widened, and is a rough edge to register.
- **Judge it.** X.4, X.5, X.8.

## 3. As-built notes (for `30-shader-nodes.md`)

### What was built — D1

- `graph.EffectAt(file, n, after=None, into=None)`, with `name`, `placed`, `where` and `unplaced()`. Instance 1 is allowed when placed.
- `placement_error` holds the vocabulary and its words. `placement_loops` finds loops.
- `instance_name`, `PLACE_KEYS`, `PLACE_WORDS`.
- `GraphSpec.notes` (compare=False). `GraphSpec.wiring()` fills `Wiring.placed`. `effect_counts` keeps only files with n > 1. `to_json` writes `after` / `into`.
- `read_graph(section, effects=None)` notes refused placements and loops instead of raising.
- `Wiring.placed` is part of the renderer's graph key, so a load with placements rebuilds the graph.
- `Node.MAKES` is set on Scene, HandsLayer and Readout. `Node.REFS` is set on Cover {scene}, Composite {depth} and Output {readout, depth}.
- `Effect(…, placed=)` gains `makes`, `see_through`, `run`, `alpha`, `depth`, `_made`, `fold` and `_one`.
- `Fx.effects` lists only the run. `Fx.run` never paints direct for a folding output.
- `Output.folds`. `settle` looks through the folds. `run` folds the settled frame, and lays an effect-layer with `Renderer.lay`.
- `Graph.insert`, `folds`, `dormant`, `notes`. `pool` counts placed held effects.
- `default_graph` leaves placed effects out of the runs, forces the layer's readout to "always" when an effect sits on it, and places them (`_place`, `_place_one`, `_consumers`).
- Words: `placement_words`, `output_placement_words`, `history_words` (placements), `graph_words(spec, dormant)`.
- `fx.FxChain.run_one(…, opaque=None)`.
- `preset.GraphSection.read` is now an instance method and passes the files on disk. Refused placements give "; the default placement" notes and the section is kept.
- `ui.output_shows(…, n=)`, `ui.dormant_lines`, and the OUTPUT page's hover and dormant lines.
- Fixtures `palette-hands.json`, `palette-glass.json`, `acid-scene.json` (force-added). `FIXTURE_PRESETS` has 4 entries, giving 24 new goldens (580 in all), and the completeness count gains `+ 3 * 8`.

### What no person has verified

- Every picture on the projector and the glass (X.4–X.9). The goldens only prove the frames are stable and that the folds are where the tests say.
- That the folded hands' colour reads as intended at distance: the ghost hands are low-saturation, so a centre of 200 gives a grey-teal, not a vivid blue.
- The windowed smoke run with `palette-hands` as the startup preset: SYSTEM's `palette` line under `hands` is checked headless only (see the report).

### Known rough edges

- A presenter's `Handoff.frame` / `hands` may be a half-float pool texture, not RGBA8 (the plan 26 contract, widened; the docstring says so).
- `fx.active()` (the golden manifest's `effects_on`, `FxChain.active`) still counts a placed effect. The renderer's `fx_on` and the OUTPUT page do not.
- An effect placed with `target = faces` is off on its edge and runs in the faces chain. Placement is not checked against `target`; D2's tip should say so.
- The palette-hands goldens for `scene+hands` and `scene+hands+through` are the same picture. Since review round 1, the through output stands down, and its manifest route reads SCENE with hands over.
