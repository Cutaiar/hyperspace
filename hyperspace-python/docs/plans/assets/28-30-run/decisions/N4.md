## 1. Register-row drafts

### 2xx. The wire list's keys: `{"from": "<node>", "to": "<node>.<port>"}`, in its own `wires` list

- **Built.** The preset's `graph` section takes a second key, `wires`, beside `nodes`. Each wire is exactly `{"from": …, "to": …}`:
  - `from` is a node's name, which means its one output: `scene`, `hands`, `hands.2`, `history`, an effect instance (`palette`, `acid.2`), or a composite (`composite`, `composite.2`);
  - `to` is `<node>.<port>`: `output.2.hands`, `acid.2.image`, `history.image`, `composite.over`.

  The list is kept in the order the file gives it and written back that way, one wire per line (`preset.dumps`). A section with no wires writes no `wires` key. `GraphSpec.wires` holds the list as read.
- **Other options.**
  - Wires nested on each node (`"inputs": {"image": "history"}`). This is shorter for effects, but outputs are not nodes in `nodes`, so it would need a second form for them.
  - `to` as two keys (`node`, `port`). This is noisier, and `output.2.hands` already reads as a port.
- **To reverse.** Change `Wire`, `_read_wires`, `GraphSpec.to_json`, `preset.dumps`, and the two fixtures.
- **Rough edge.** A wire list's order has no meaning, but two specs that differ only in order compare unequal. The only cost is a graph rebuild.
- **Judge it.** Y.1, Y.2.

### 2xx. Which ports a preset may wire: image ports only; a hands node's place stays its `into`

- **Built.** A preset may wire these ports:
  - `output.<n>.image`, `.hands` and `.readout`;
  - `history.image`;
  - an effect's `image`;
  - a composite's `under` and `over`.

  Geometry and mask ports are typed, so a wrong drag can say why it is wrong, but they cannot be wired:
  - `ghost → scene.geometry` gives the note "a hands node's place is its into (ghost into scene or layer), not a wire";
  - `cover → …` gives "the cover is the history's own".

  On the canvas, a geometry cable dragged from a hands node into the scene or the layer does land: it sets that node's `into`, which is the same JSON as A4's.
  - `output.<n>.readout` takes only a hands layer: "takes a hands layer's guide".
  - A composite cannot take the history `over`, because the history paints into what reads it and has no texture to lay.
  - An output's `depth` port is not wireable. It follows the blend.
- **Other options.**
  - Geometry wires in the JSON (`{"from": "ghost.2", "to": "scene.geometry"}`). That would be two spellings of A4's `into`.
  - Wiring the depth port, which would mean depth-aware against something other than the scene.
- **To reverse.** Edit `WIRE_TAKES` / `WIRE_MAKES` in `graph.py`.
- **Rough edge.** There are two spellings for "hands in the scene": a geometry drag on the canvas, and `into` in the JSON. The canvas writes the JSON's.
- **Judge it.** Y.3.

### 2xx. How D1's `after` / `into` map onto wires, and when the short form is written

- **Built.** `after X` is the wire `X → E.image`. `into Y` is the wire `E → Y.image` (`into output.2` is `output.2.image`). `GraphSpec.all_wires()` / `d1_wires` say this.

  Wires go the other way too (`split_wires`), so D1's builder does the work:

  | Wires on effect E | What E becomes |
  |---|---|
  | fed by one wire, wired into nothing | `after` its source, and every consumer reads it |
  | fed by no wire, wired into one output's or the history's `image` | `into` that node |
  | fed and wired on, or wired into a `hands` / `readout` / composite port | built as an explicit edge: E reads exactly its source, and only the named ports read E |

  A D1-only section is still written short, byte for byte. A section read from wires is written as wires. An edit on the canvas writes wires: a D1 placement the edit replaces is dropped from its node, and an extra instance stays in the chain.
- **Other options.** Normalise everything into one form on save. That would re-spell a hand-written file, and D1's three fixtures would change.
- **To reverse.** Edit `split_wires`, `d1_wires`, and `graphview._unplace`.
- **Rough edges.**
  - D1's `into: <effect>` (palette into warp) has no wire spelling. The wire `palette → warp.image` reads as "warp after palette", so that form stays short.
  - A wire into an effect's image and D1's `after` on the same effect count as two wires into one port, so the wire is refused.
- **Judge it.** Y.1.

### 2xx. Outputs as nodes: a wire overrides that port alone, and the guide goes with the hands shown

- **Built.**
  - **`output.<n>.image` ← S.** The output shows S through an end of its own, `graph.Wired`, named `wire(output.<n>)`. Like a pipeline's end, it paints straight into the output when it can, and otherwise once into a frame texture. It ignores the output's scene and through switches. If the output's `hands` port was empty (through, or hands in the scene), its readout goes too, unless the readout is wired, because the guide goes with the hands shown.
  - **`.hands` ← S.** S is laid over, depth-aware when the blend is depth. The output gets that layer's guide if it had none.
  - **`.readout` ← layer.** The output shows that layer's guide.
  - **Unnamed outputs.** An output no wire names is node for node the default graph's, so it follows the session's switches. A load never writes a switch.
  - **Graph key.** The wires ride in `Wiring.wires`, `.placed` and `.composites`, so `Renderer._graph_for`'s wiring comparison rebuilds the graph when they change.
- **Other options.**
  - Keep an image-wired output's switch-derived hands and readout. The guide would then float on a picture with no hands.
  - Make the image wire also take over `hands`.
- **To reverse.** Edit `_Wiring._put` and `Wired` in `graph.py`.
- **Rough edges.**
  - In the golden manifest, a wired output's route reads `none` (`tools/golden_frames.py`). `test_golden_frames` allows only `outputs.NAMES` or `none`, and the prompt lets that test change only by its count. The fixture's `graph` in the manifest says what the wire is.
  - `stats["routes"]` carries `"wire(output.2)"` as the key.
- **Judge it.** Y.2, Y.4.

### 2xx. A `hands` wire on a through output replaces the switch's hands (review round 1)

- **Built.**
  - **A through output.** On a through output (its hands laid on before the chain: `fx(scene+hands)`, `fx(hands)`), a wire into `output.<n>.hands` moves that output's picture to the end the hands were laid onto: the scene's end, or the ground with the scene off. Only the wired node is then laid over, at the output. Without this, the hands were drawn twice when the chain bent them (through the chain, and again over), or the wire was dropped when it did not (the fallback put the switch's layer back).
  - **Not a hands layer.** Anything a wire lays on the hands port that is not a hands layer (the scene, a composite, an effect) is laid through the node, as its own picture: `Renderer.lay`, and the presenter's `Handoff.hands`. It is never laid through hands 1's Ghost.
  - **The history.** `history → output.<n>.hands` is refused ("the history paints into what reads it, so it is not laid over: wire it into the output's image, or an effect after it over").
- **Other options.**
  - Lay the wired layer on through the chain too, as the through switch does. That would need a pipeline per wired layer.
  - Refuse a hands wire on a through output.
- **To reverse.** `_Wiring._put`'s hands branch; `Output.run`'s `laid_node`.
- **Rough edge.** On a through output, the effects no longer bend the hands while a hands wire is on it. The wire wins over the switch, by design.
- **Judge it.** Y.2.

### 2xx. The refusal words, and what each refusal costs

- **Built.** Each refused wire is a note: `graph: wire <from> → <to> — <why>; the default wiring`. That wire is left out, its port keeps its default (or D1's placement), and the rest stands. The section is kept as the file had it. The reasons:
  - "no node 'X': a wire leaves scene, hands …, history, an effect or a composite";
  - "no X effect in this build";
  - "output.1 is an output: it makes nothing to wire on";
  - "output.1 has no port 'picture' (it takes image, hands, readout)";
  - "ghost makes geometry, output.1.image takes a picture";
  - "no hands.2 layer in this graph (hands makes the layer)";
  - "output.1.readout takes a hands layer's guide (hands)";
  - "palette sits after 'hands' already (its node says so): one place";
  - "output.1.image takes one wire, and 2 go into it (scene and history): it keeps its default";
  - "palette has no wire in, so it sits into one port (…): wire its input to feed more";
  - "that makes a loop (palette → acid.2 → palette)".

  A malformed wire (not `{"from", "to"}` strings, or the same wire twice) is unreadable. That is a `GraphError`: the default graph, as A4 does for nodes.

  A wire on a node this frame lacks (output 3 with two outputs, no layer) is dormant (`Graph.dormant[str(wire)]`): "wire hands → output.3.hands — no output 3 this frame". It shows on OUTPUT's dormant lines and in the graph words.
- **Other options.** Drop the whole graph on any refused wire.
- **To reverse.** Edit `wire_error`, `_read_wires`, and `GraphSection.read`'s suffix.
- **Rough edges.**
  - Every wire into a doubly wired port is refused, not just the later one.
  - Every wire on a loop is refused.
- **Judge it.** Y.3.

### 2xx. The picker's list, and how edits land

- **Built.**
  - **The picker.** Right-click the canvas: one item per effect file on disk (`effect <file>` → `EffectAt(file, n + 1)`, its `fx.<file>.<n+1>.*` params declared at their defaults, the instance in the chain at its order), then `hands` (`HandsAt(n + 1)`, drawn in the scene while another node makes the layer, else the layer), then `composite` (`CompositeAt(n + 1)`, blend over, built only once a wire feeds it).
  - **A node's menu.** Right-click a render node: delete; `draw solid` / `draw lines` for a hands node; `laid over` / `add` / `depth` for a composite.
  - **Delete.** The Delete key on a render cable is `unwire`. A cable that is the default graph's is refused: "… is the default graph's: no wire says it (wire something else into … to replace it)". On a render node, delete removes an extra effect instance, hands node or composite, with every wire on it. Instance 1 of an effect, hands 1, the scene, the history and the outputs stay, each with words.
  - **How an edit lands.** Every edit is a new section read back through `read_graph` with the build's files:
    - a note is the refusal, and nothing changes;
    - otherwise one undo step (`undo.push(label, load=True)`; the library's marks carry the graph), then `GraphSection.land` (the preset dirty, the renderer handed the new wiring);
    - an edit that empties the section lands no section, so the preset is clean again when it had none.
  - **The seam with N3 (as merged).**
    - **The dispatch tables.** These are N3's: `ui_graph.CREATE[type]`, `DELETE[cable kind]` and `DELETE_NODE[node kind]`. Image, geometry and mask go to `_create_render`; `"render"` goes to `_delete_render_cable`; `"render"` and `"output"` go to `_delete_render_node`. N4's handlers follow N3's contract: they accept or reject the widget's item themselves.
    - **Undo.** N4's handlers do not go through N3's `_act`. Their undo step (`load=True`) is pushed by `render_edit`'s `Edit`, and only when an edit lands.
    - **`graphview.Edit`.** This is N3's class, with keyword-only `graph` / `render` / `push` and the attribute `said`. N4's methods are `wire`, `wire_refusal`, `unwire`, `add_node`, `drop_node`, `remove_render_node` (= `drop_node`) and `set_node`. N3's `_render` turns their plain words into a `Refusal`.
    - **The menu.** N3's single `MENU` popup carries N4's picker items (`effect ▸ <file>`, `hands`, `composite`) and N4's render-node items. A render cable's menu delete is `unwire`.
- **Other options.**
  - A picker of effect instances already declared.
  - Edits that write the spec directly, without reading it back. That would mean two code paths for refusals.
- **To reverse.** Edit `graphview` "render edits" and `ui_graph` "edits".
- **Rough edges.**
  - A loaded section that carried a refused wire or placement is kept as the file had it, but the first canvas edit writes the accepted spec, so the refused part is dropped then.
  - A drag's "red with words" is a tooltip, not a note on the strip.
- **Judge it.** Y.1, Y.5.

- `tests/test_graphview.py::test_the_page_is_read_only` became `test_the_page_edits_only_through_its_dispatch`. N2's test said "N3 and N4 open them"; this is the one assertion changed outside my files.
