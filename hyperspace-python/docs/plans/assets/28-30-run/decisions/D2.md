## 1. Register-row drafts

### 2xx. A placed effect's chip sits in a grid of its own, its place after its name

- **Built.** The FX page still edits the default chain. An effect the loaded preset's graph places (`after` / `into`) leaves the chain's chip grid.
  - **Layout.** Placed chips are drawn in a second grid under the first, three to a row like it. Two grids of a and b chips never take more than one row beyond a single grid of a + b, so with 13 effects the page is at most one row taller. It never scrolls at the control size (`test_the_page_fits_with_three_placed_effects`).
  - **Label.** The chip's text is the effect's label, then where it sits: `Warp · after hands`, `Palette · into output 2`, `Acid 2 · after scene`. It is cut with an ellipsis to fit the chip.
  - **Hover.** The name's hover has the label whole (`placed after hands`), then "placed by the preset's graph, not in the chain: moved in the preset's JSON, not by a drag", then `dormant: …` when the built graph has it dormant.
  - **No drag.** The chip is no drag source and no drop target. A drop among the chain's chips never rewrites a placed effect's `order` (`_drop` works over the chain only).
  - **LED and strip.** The LED switches it, and the name opens its strip, which is any effect's (order slider included). The strip title's hover reads `warp.glsl · after hands` in place of `#20`.
  - **Source of the words.** The words come from one function, `graph.placed_chips(spec)` (instance name → words).
- **Other options.**
  - One chip to a row with the words beside it. This was round 0, and it scrolled the page with three placed effects.
  - Keep the chip in its grid place with a mark and the place in the hover only. The place is not readable at distance, and the chip looks reorderable.
- **To reverse.** `ui_fx.page`'s second grid, `_chip(place=, dormant=)`, `placed_label`, `_drop(placed=)`.
- **Rough edge.**
  - At three chips to a row, a long label and place is cut (`Kaleidoscope · aft…`). The hover has it whole.
  - The page reads the *preset's* spec (`Panel.graph_now`), not the built graph. A placement refused only at build would still show as placed. `read_graph` refuses loops, so no preset reaches this.
- **Judge it.** X.10.

### 2xx. The status line keeps the chain's labels and adds the count of placed effects that run

- **Built.** The status line under the bypass lists the running chain's labels without the placed effects, then ` · N placed`:
  - `Acid → Palette · 1 placed`;
  - with only placed effects running, `nothing in the chain · 1 placed`.

  N counts the placed effects that run on the frame: switched on with mix above 0 (they are in `chain`), aimed at the frame, and not dormant in the built graph (`renderer._graph.dormant`). With none placed, the line is byte-identical to before.
- **Other options.** The prompt's literal `3 in the chain · 1 placed`. It drops the labels the line has always shown and the FX tests assert.
- **To reverse.** `ui_fx._status`.
- **Rough edge.** The count says how many, not which. The placed grid says which.
- **Judge it.** X.10.

### 2xx. The chip's place words and OUTPUT's placement words are two vocabularies

- **Built.** The two vocabularies:
  - **The FX chip (`graph.placed_chips`)** uses the key and the node: `after hands`, `into output 2`, `after scene`, `into history`, `after acid 2`. It is the edit view, so it reads like the JSON it came from.
  - **OUTPUT's "shows:" line and LOOKBACK (`graph.placement_words`, D1)** use the effect on the picture: `palette on the hands`, `acid 2 before the history`, `palette 2 on output 2 only`. That is the show view: what the picture gets.

  **N4 extends `placed_chips`** for wires: a wire into an effect's input is that effect's place. `placement_words` stays the show's words, and N4 adds a wire case there only if OUTPUT needs to say it.
- **Other options.** One vocabulary for both. `palette on the hands` is too long for a chip, and `after hands` reads poorly on the output line.
- **To reverse.** Have `placed_chips` call `placement_words`.
- **Rough edge.** The same placement reads two ways on two pages.
- **Judge it.** X.10 and X.9.

### 2xx. A dormant placement still shows as placed, said only in the hover

### 2xx. A placed effect aimed at the faces says "on the faces" and is not counted as placed

- **Built.** The `target = faces` chain is not on the graph (row below). An effect both placed and aimed at the faces runs in the faces chain, not on its edge. So its chip reads `Warp · on the faces`, its hover reads "placed after hands, aimed at the faces: it runs in the faces' chain", the frame's `· N placed` count leaves it out, and the faces row lists it.
- **Other options.** Refuse the placement at load when the effect is aimed at the faces. But `target` is a param a person can change at any time, so this is a load-time check on a live value.
- **To reverse.** `_chip`'s `said` and `_status`'s count filter.
- **Rough edge.** The preset says `after hands`, but the chip does not.
- **Judge it.** X.11.

### 2xx. The `VALUE` port: a fourth type, named, used by no node

- **Built.** `graph.VALUE = "value"` sits beside `IMAGE`, `MASK` and `GEOMETRY`, and `graph.PORT_TYPES` holds all four. It is a scalar or small float vector a node publishes once a frame. Its docstring names its two uses:
  - the palette's `palette` value out (centre, width, the sat and val ranges, the ramp anchors) for a lights sink (plan 29);
  - an image-in `sample` port on the palette that would set its params from a bitmap.

  No node publishes or reads one (a test walks every Node class and the built default graph). `patch.RENDER_VALUE = "value"` names it on the modulation side, as a future `source` node whose id is the node's port (`palette:palette`). `patch.py` does not import the graph, so it stays a leaf. `Node.__init__` already type-checks a wired port, so the first node to declare a `VALUE` wires like any other.
- **Other options.**
  - A typed shape (a `ValuePort(n, names)` dataclass naming the vector's fields).
  - Deferring the type to plan 29.

  Both were rejected for now: either would be built with nothing to read it.
- **To reverse.** Delete `VALUE`, `PORT_TYPES` and `RENDER_VALUE` (nothing reads them).
- **Rough edge.** The vector's layout (which float is the centre) is undecided until a node publishes one.
- **Judge it.** None at the machine: nothing is drawn.

### 2xx. The faces target stays an inner chain

- **Built.** `target = faces` still runs inside the shape's face drawing (`render.face_fx`), not on a graph edge. The `fx.<name>.target` tip now says so: "On the faces it runs inside the shape's face drawing: the one shader run the render graph does not show, and a placement in the preset's graph does not move it." An effect both placed and aimed at the faces runs in the faces chain (D1's rough edge). The status counts it on the faces row, not as placed.
- **Other options.** The lift, "faces as a layer": the shape's faces drawn to a texture of their own, which becomes an image edge where any effect can be placed. That is a change to the scene's drawing, and it puts the face pass's translucency and depth at stake.
- **To reverse.** Build the lift (a plan of its own).
- **Rough edge.** The graph and the GRAPH page do not show this one shader run. SYSTEM times it inside the scene.
- **Judge it.** X.11.
