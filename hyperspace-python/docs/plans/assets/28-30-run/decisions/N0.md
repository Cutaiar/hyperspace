# N0 — the modulation graph in dependency order: decisions, hand checks, as-built

Branch `plan-28-n0-patch`, base 5d18192.

## 1. Register-row drafts

**2xx — `patch.py`'s types.**
**Built:** `PatchNode(id, kind, delay=False)` (kinds `source lfo modifier macro param`; an LFO's or a modifier's or a source's id is the address a row names — `lfo:0`, `mod:3`, `hand:right.y` — a param's or a macro's its param id, so the two never collide: an address has a `:`, an id never does); `PatchEdge(src, dst, port, cable=None, enabled=True)` with ports `mod when depth base in` and the LFO knobs `shape rate sync depth phase reset` plus `trigger` (`lfo.trigger` → every LFO); a modifier's own param edge is named by its param (`mod.2.attack` → `mod:2` port `attack`). `cable` is the route's `(source, target)` on its `mod`, `when` and `depth` edges. `Patch(nodes: dict, edges: list)` with `add` / `link`; `ordering(patch)`, `order(patch)` (DFS post-order, dependencies first, ties in insertion order, `Graph._sort`'s walk), `cycles(patch)` (every elementary loop once, from its earliest node, capped at 256). Beyond the prompt: a `when` port (a row's gate source orders before the row — needed for a gate on an `lfo:` lane) and the `shape / sync / reset / trigger` knob ports (every LFO knob param is one of its inputs).
**Other options:** nodes as a list; a gate folded into the `mod` edge; only `depth / rate / phase` as LFO ports (the prompt's list).
**To reverse:** small — patch.py is data; N2 draws from it.
**Rough edge:** a switched-off row is in the patch as disabled edges (drawn, not run); a cut cable looks the same.
**Judge it:** — (tests only); N2's GRAPH page will show it.

**2xx — Which params the pass lands, and how `Param.apply` is idempotent.**
**Built:** `Router.modulate` lands (`Param.apply`) **only the params a later node of the pass reads** — a `scale`, a macro behind a depth subscriber, an LFO knob, a modifier's own param. Every other param, the leaves, lands in `reg.apply()` exactly as before, in registry order. The mark: `Registry.begin_frame()` (called by `Router.modulate`) bumps `Registry.frame` and sets `Registry.landed`; `Param.apply(mark)` records `_mark` and returns at once if called again with the same mark; `Registry.apply()` passes `landed` and then clears it, so an `apply()` with no pass before it (tests, `Registry.remove`) lands everything as it always did. `Registry.nonfinite` now also names a param that dropped a NaN inside the pass.
**Other options:** land every param node in the pass (the prompt's literal wording) — then a leaf trigger (a band-layout change, `preset.select`) fires in the middle of the pass, and its order changes from registry order to patch order; a per-param boolean flag cleared by `Registry.apply`.
**To reverse:** one condition in `_rebuild_patch` (`land = node.id in reads` → always true).
**Rough edge:** a param that something reads lands in patch order, not registry order — the same value, a different moment in the frame; a test that calls `p.apply()` by hand between `modulate` and `reg.apply()` on such a param lets it go.
**Judge it:** Y.n1.

**2xx — The patch cache key.**
**Built:** `Router.patch` is rebuilt when `_patch_key` changes: every performer row by identity and its `source target op enabled scale when`, `macros_serial`, every macro subscriber (identity, `depth`, `base`), the modifiers' `(id, kind, inputs)` (N1, by `getattr`), the LFO count and `Registry.serial` (new: moves on every `add` / `remove`). The key is a tuple built once a frame (≈ 4 µs on party-trip); nothing per row is re-derived on a hit. A depth subscriber's `from` / `to`, a row's `value`, `rest`, `motion` are read live and need no rebuild.
**Other options:** a serial bumped by every table edit door (the table is also mutated in place — the ROUTING page, tests — so a missed door would run a stale patch).
**To reverse:** `_patch_key`.
**Rough edge:** a `Bindings` replaced by a new object with identical rows at the same `id` (after a free) would not rebuild — the identity `id(table)` makes it vanishingly unlikely.
**Judge it:** —.

**2xx — A loop's cut and its note.**
**Built:** a loop that passes through no delay modifier is broken at its **last cable in table order** among the cables on the loop: that cable's edges are disabled in the patch (it does not run), the row stays in the table, enabled, and saves as written. One note per cut on ROUTING's head, in the warning colour, while the loop stands: `loop: lfo:0 → lfo.2.rate → lfo:1 → lfo.1.depth → lfo:0 needs a delay — lfo:1 → lfo.1.depth is off until it has one` (node ids, not labels). Loops are cut one at a time, re-listed after each cut. A macro's **base** subscriber never closes a loop (it is a scene-setter that ran at step 3, so it puts no constraint on the pass).
**Other options:** the row switched off in the table (then the preset is dirty and the save writes `enabled: false`); the note in `table.notes` (cleared by every edit, the loop still standing); labels ("LFO 1") in the note.
**To reverse:** `_rebuild_patch`'s loop; the two lines in `ui_routing.head`.
**Rough edge:** the row's checkbox still reads on; only the note says it is off. An LFO owning its own depth (`lfo:0 → lfo.1.depth`) — which ran before with a frame of lag — is now refused until N1's delay sits in it.
**Judge it:** Y.n2.

**2xx — A delay's place in the order.**
**Built:** an edge into a delay modifier orders like any other (a plain delay runs after its input), unless the delay reaches that edge's source again — then that edge does not order, the delay runs before its input and emits what it held (`patch.ordering`). `cycles` lists no loop through a delay.
**Other options:** every edge into a delay non-ordering (a delay always first) — then a delay on a computed lane, stepped statefully, is two frames late.
**To reverse:** `patch.ordering`.
**Rough edge:** with N1's stateful `delay` (`last frame's input`), a delay that closes a loop runs first, reads its input's lane as it stood (last frame's) and emits what it held — two frames round the loop. N1 / the integration should make a loop-closing delay emit its input's lane as it stands (one frame) — see §4.
**Judge it:** Y.n3 (after N1 lands).

**2xx — The LFOs inside the pass.**
**Built:** `Router.use_lfos(lfos, clock)` (app.main calls it once); `Router.modulate(analyzer, dt, now)` calls `LFOs.begin(t, clock)` (a held global trigger lands; `outputs` becomes this frame's list), `LFOs.publish` (labels, rests, the lane vector), then `LFOs.step_one(i, dt, t, clock)` at each LFO's node, writing the lane in place. Every LFO is a node whether or not a cable touches it, so each steps once a frame, in index order unless a dependency says otherwise (a random LFO's draws follow that order). A per-LFO reset is late (held for the next step) only if **that** LFO has already stepped at this t (`LFO.at`), so a reset a performer fires in the pass before its LFO's node lands at phase 0 the same frame. `LFOs.step` is `begin` + every `step_one`, for a caller with no router. A bare `Router` (no `use_lfos`, the tests') steps no LFO.
**Other options:** the bank passed to every `modulate` call.
**To reverse:** `app.frame` back to `lfos.step` / `publish` before `router.modulate`; `use_lfos` dropped.
**Rough edge:** a hot reload of `routing` into an app.py from before this run keeps the old order (no `use_lfos`, the app steps the LFOs itself) — harmless.
**Judge it:** Y.n4.

## 4. Where the documents and the code differ
- **"a `param` node … then applies that param now"**: built for the params a later node reads; the leaves land in `reg.apply()` (row "Which params the pass lands"). Values are identical; the design's intent — nothing reads a stale value — holds.
- **"assert the new sequence equals the old shifted by one frame for every param a performer moves"**: a param a performer moves directly (hand → `fx.zoomblur.amount`) was never late, so its sequence is **identical**, not shifted; only a param downstream of a lagged read is shifted, by the base build's lag (`_lag_of`, computed from the table: one frame per lagged read on the way). The test asserts exactly that, for every modulatable param and every LFO output of every factory preset. The design's intent ("every existing preset produces the same effective values one frame earlier") is what it proves.
- **The N1 seam**: N1 (branch `plan-28-n1-modifiers`, decisions/N1.md) built `Router._step_modifier(mid, dt, lanes)` and a `_step_modifiers(analyzer, dt)` called once at the top of `Router.modulate` stepping every modifier in id order. At integration: keep N1's `_step_modifier` body, drop its `_step_modifiers` call (the pass calls `_step_modifier` per node, in order), make sure the `mod` lane vector exists before the pass (N1's `_publish_modifiers`), and decide the loop-closing delay (§1 "A delay's place"): for a delay that runs before its input, emit the input's lane as it stands.
- The prompt's ports list for an LFO is `depth rate phase`; every knob is wired (`shape sync reset` too, and `lfo.trigger`).
- `tests/test_hotreload.py` derives the watched list from the package, so `patch` needed no edit there.

## Fix round 1 (after N1 merged; head 9df0e8e)

**2xx — The equivalence oracle's shape.**
**Built:** the base build's `Router.modulate` (5d18192) is copied verbatim into `tests/test_routing.py` as `_lagged_modulate` (a function taking the Router as `self`), not a flag in the package and not a recorded fixture. It shares the Router's own helpers with the new code: `_resolve_lane`, `gated`, `rest_of`, `feel_of`, `_move`, `table.mods` / `depth_subs`. Only the order and the lag differ. Before any change, the copy was checked bit-for-bit against the real base build over all 23 factory presets. It lives in a test file, so the package's one `p.modulate` call site is untouched.
**Other options:** a test-only flag in `Router.modulate` (a second `p.modulate` call site, which breaks the boundary walk); a committed recording (large, and it could not follow a helper's change).
**To reverse:** delete the function and the test.
**Rough edge:** a change to a shared helper moves both sides together, so the oracle proves timing and arithmetic order, not the helpers.
**Judge it:** —.

**2xx — A loop of modifiers alone.**
**Built:** a loop with no cable on it (`in` edges only) keeps the last modifier's input on the loop off, in modifier id order. That modifier is dormant (its lane is NaN) and a note is added: `loop: mod:1 → mod:2 → mod:1 needs a delay — mod.2's input mod:1 is off until it has one`. The cut then goes on to the next loop. `patch_cut` holds both kinds of pair: a cable `(source, target)` and a cut input `(input address, modifier node)`.
**Other options:** cut the loop's first input.
**To reverse:** `_rebuild_patch`.
**Rough edge:** the modifier's input combo still shows the input.
**Judge it:** Y.n2.

**2xx — A delay closing a loop.**
**Built:** that delay runs first. N1's `_step_modifier` takes `early=True` from the plan and emits its input's lane as it stands, which is last frame's value. On the loop's first frame, before anything has stepped, it emits the rest (0). A loop through a delay is therefore exactly one frame late. A plain delay still runs after its input and uses N1's stateful step: its rest first, then one frame late.
**Rough edge:** if the loop's other source goes away, the early delay emits its rest, not NaN.
**Judge it:** Y.n3.
