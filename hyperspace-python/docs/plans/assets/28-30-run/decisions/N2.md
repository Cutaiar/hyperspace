# N2 — the GRAPH page, read-only: decisions, hand checks, as-built

Branch `plan-28-n2-graph-page`, base `acc0f7e`. Rows `2xx`, checks `Y.n`.

## 1. Register-row drafts

### 2xx. Node and pin ids are strings with a kind prefix; the widget's integer ids are a per-panel map
- **Built.** Nodes: `device:<role>`, `source:<scheme>`, `analyzer`, `lfo.<n>`, `mod.<n>`, `macro.<n>`, `render:<node name>` (incl. `render:eye`, `render:output.<n>`), `group:<group>`. Pins: `out:<address>`, `base:/mod:/depth:<pid>`, `in:<mod id>.<k>`, `bus:<macro id>`, `rin:<node>/<port>`, `rout:<node>`. The node ids are the `layout` keys the owner sees in a preset file. `ui_graph._id` maps each string to a stable int for the editor.
- **Other options.** Hashing strings to ints (collisions); bare names (`shape`, which clashes with the band `scene` group).
- **To reverse.** The layout keys change, so any saved `layout` would need migrating.
- **Rough edge.** A render node renamed by a later plan loses its saved position.
- **Judge it.** Y.3.

### 2xx. Params with no render node: a node per group; the camera gets an `eye` node of its own
- **Built.** `graphview.OWNERS` is the one table: `view`/`rot`/`pattern` → `shape`; `ghost[.<n>]` → that hands node; `cloud` → the first point-cloud node; `dream` → `history`; `fx.<effect>.*` → that effect's node in the scene's pipeline (else its first node), `fx.on/mix/select` → `fx`; `camera`/`eye` → `render:eye` (no render-graph node: it has no image ports); `output.<n>.*` → `output.<n>`. Every other group (and a mapped one whose node is not in this frame's graph) → `group:<group>`. `lfo.<n>.*` sit on their LFO's node, `mod.<n>.*` on their modifier, `macro.<n>` on its bus node. The `scene` *group* (band scenes) is not the render `scene`.
- **Other options.** One "misc" node; put the camera on `shape`.
- **To reverse.** One dict.
- **Rough edge.** With no render graph (before the first frame, or headless) everything falls to group nodes. Effects in the other pipelines (`acid(hands)`) carry no params.
- **Judge it.** Y.2.

### 2xx. What the canvas draws: modulatable params, plus every target any row names; setter rows into `base`; no sinks, no `scale`/`when` cables
- **Built.** Param ports are every modulatable non-alias param plus any param a route, a desk/pad/key row or a macro sub names. Desk, pad and key rows are `setter` cables into `base` (keys draw from a grey `source:key` node). A route's `scale` and `when` are written on the cable's hover, not drawn, because a param has no output pin. Sink rows are not drawn. Only macros with subs, a label or a cable get a node.
- **Other options.** Draw every param (~700 ports); draw only the routes.
- **To reverse.** The filters in `graphview.build`.
- **Rough edge.** The APC40's ~100 desk rows make many base cables. They are faint while their control is idle, and N5 splits them into two nodes. Setter cables are shown faint, not dashed: `ed.link` cannot draw a dashed cable. Only the `base` stub's square glyph tells a setter apart from a route.
- **Judge it.** Y.1.

### 2xx. The layout: the preset's map for the look's nodes, the show's for the rig's; a drop dirties; tidy forgets
- **Built.** `preset["layout"]` holds modifiers, macros, every render node (except outputs) and performance-group nodes. That includes `render:eye`, kept in the preset deliberately: its ports are `camera.*`, which are performance params. The `eye.*` fov and distance params are session params but not modulatable, so they draw only when some row targets them. The show's `layout` holds devices, sources, the analyzer, LFOs, outputs and session-group nodes (`graphview.home`). Positions are whole canvas units, written sorted, one node a line in a preset. A node is written only when the user drops it (on mouse release). Auto-placed nodes are never written. A preset's layout is part of `signature()`, so moving a node dirties the preset; the show's is part of `Project.is_dirty`. **Tidy** deletes the canvas's nodes from both maps (this dirties) and re-lays every node out. It asks for no confirmation; instead it is one undo step (`ui_graph.forget` → `undo.push("tidy the graph", load=True)`), and ⌘Z puts both maps back. The library's marks carry both maps (review round 1): `Marks.take` stores a copy of `Presets.layout` and `put` restores it; `Project.mark` / `remark` carry `layout` and `_saved_layout`; and `Marks.put` gives the same show its layout back too. An unreadable entry is dropped with a note; no key means no note and no dirt.
- **Other options.** Keep everything in the preset; write auto positions too (noisy diffs).
- **To reverse.** `graphview.home`, `Presets.layout` / `Project.layout`.
- **Rough edge.** A drag on its own is not an undo step: positions come back only with the undo of a load or a tidy. Undoing an earlier load in the same show also puts back the show's positions as they were then, which loses a later drag of a rig node.
- **Judge it.** Y.3, Y.4.

### 2xx. The tidy columns
- **Built.** Left to right: sources (devices, keys, analyzer) 0, LFOs 1, modifiers 2, macros 3, param-group nodes 4, render nodes from 5 by their depth in the render graph, outputs last. Nodes are stacked down each column by estimated height (patched ports). Placed nodes take no room.
- **Other options.** One render column.
- **To reverse.** `graphview.COLUMN` / `_columns`.
- **Rough edge.** 13 effects per pipeline make a wide canvas. A node's own expand and its folds count toward its height (`auto_layout(expanded=, folds=)`), so expanding a node pushes the unplaced nodes under it down instead of overlapping them. Dropping a node re-stacks the rest of its column.
- **Judge it.** Y.3.

### 2xx. The editor context lives on the panel, not in ui_graph; Panel.close destroys it
- **Built.** `panel._graph["editor"]` is made on the page's first draw (`Config.settings_file = ""`). A hot reload of `ui_graph` keeps it, so no second context is made (tested by reloading the module). New `Panel.close()` → `ui_graph.close` runs in app.py at quit and in the ⌘R restart list (`close_all(..., panel, ...)`), before imgui shuts down. Calling it twice is safe.
- **Other options.** Destroy and recreate on reload (selection and zoom would be lost).
- **To reverse.** `ui_graph._state` / `close`.
- **Rough edge.** A reload of `ui.py` re-classes the Panel, and the state dict survives it too. The test rig never calls close, so its contexts die with the imgui context.
- **Judge it.** Y.5.

### 2xx. The selection pane goes below the canvas by default; a **beside** chip or a wide page puts it in a side column
- **Built.** CONTROLS is `ui.PANEL_W` 540 px wide, so the page is about 420 px. The owner therefore sees the ROUTING row or effect strip in a 240 px pane under the canvas by default. The head's **beside** chip (or a page at least 720 px wide, i.e. CONTROLS widened by hand) puts it in a 320 px side column instead. The effect strip is `ui_fx.strip(panel, name)`, factored out of the FX page unchanged.
- **Other options.** Always a side column (a canvas about 100 px wide at the default size); a lower threshold (the same problem).
- **Rough edge.** Selection is read a frame late (last frame's canvas).
- **Judge it.** Y.4.

## 2. Hand-check drafts (plan 28)

**Y.1 — The GRAPH page shows one table.** Headless: `test_every_route_is_one_cable_and_every_cable_one_route`, `test_the_routing_page_and_the_graph_page_show_one_table`, `test_macro_subs_are_cables_into_base_or_depth`. Setup: load party-trip and open GRAPH beside ROUTING. *Pass:* each route is one solid cable into a param's round `mod` stub. Desk and key rows are faint cables into square `base` stubs. Adding a route on ROUTING shows a cable on GRAPH next frame. *Fail:* a cable missing or doubled (the view key not moving: `graphview.key`).

**Y.2 — Params sit under their render nodes.** Headless: `test_params_group_under_the_render_node_that_owns_them`. Setup: an effect on, the hands on. *Pass:* `view.*` is on `shape`, `fx.acid.*` on `acid`, `dream.*` on `history`, `camera.*` on `eye`, `tempo` and `master` on their own nodes. *Fail:* everything sits on group nodes (no `renderer._graph` yet).

**Y.3 — Layout and tidy.** Headless: `test_layout_round_trips_through_the_preset_and_the_show`, `test_a_node_dropped_on_the_canvas_is_saved_in_its_home`, `test_auto_layout_gives_every_unplaced_node_a_column`. *Pass:* dragging `shape` dirties the preset. Saving, loading another preset, then loading this one back puts `shape` where it was dropped. Dragging an LFO dirties the show instead. Tidy lays out sources → LFOs → modifiers → macros → render → outputs. *Fail:* a node snaps back while it is being dragged (`_place` re-setting it), or a factory preset is dirty on load.

**Y.4 — Hover and selection.** *Pass:* hovering a cable shows from → to, the reading and the depth (turning a depth-subscribing macro changes it). Clicking a route shows its ROUTING row below the canvas: CONTROLS is 540 px wide by default, so this is where it lands. The **beside** chip moves it into a side column; widen CONTROLS to give both room, or it shows beside by itself at a page width of 720 px or more, and editing the depth there moves the cable's thickness. Clicking an effect node shows its strip. *Fail:* the tooltip lands in the wrong place (suspend/resume).

**Y.5 — Quit, ⌘R and hot reload.** Headless: `test_the_editor_context_is_made_once_kept_across_a_reload_and_destroyed_on_close`. *Pass:* save `ui_graph.py` with the page open: the page goes on drawing and keeps its zoom. Quitting and ⌘R exit without a crash. No `NodeEditor.json` appears anywhere. *Fail:* a crash on quit (context destroyed after imgui).

## 3. As-built notes

### What was built (N2)
- `hyperspace/graphview.py`, the model (no imgui): `VPort`, `VNode`, `VCable`, `View`, `OWNERS`, `render_owner`, `device_node` (the one device → node builder, for N5), `build`, `refresh`, `key`, `reading`, `auto_layout`, `height`, `home`, `split`. Extra keywords on `build`: `lanes=` (this frame's normalised analyzer lanes) and `bands=` (band names).
- `hyperspace/ui_graph.py`, the page: `page`, `editor`, `close`, `view_of` (rebuilds only when `key` moves, otherwise `refresh`), `expanded`, `shown`, `cable_tip`, `timing_line`. It draws no `begin_create` / `begin_delete`. N3 adds them in `_canvas` after the links, and reverses pin ints through `st["names"]`.
- `ui.py`: `PAGES` gains `("graph", "graph", None)` after routing, plus `Panel._page_graph`, `Panel.close` and a SYSTEM line (`graph page: X ms median (N nodes, M cables)`).
- `ui_fx.py`: `strip(panel, name)` factored out of `page`.
- `preset.py`: `LAYOUT_KEY`, `Presets.layout` (read in `load_doc` step 6½, written last by `document`, in `signature`), `dumps` writes one node a line.
- `library.py`: `LAYOUT`, `read_layout`, `Project.layout` / `_saved_layout` (read in `_take`, written by `to_doc` when non-empty, compared in `is_dirty`).
- `app.py`: the panel is in both close lists.
- `hotreload.MODULES`: `graphview` after `osc`, `ui_graph` before `ui`. `test_hotreload` needed no edit (it derives the list).
- Tests: `tests/test_graphview.py` (14).

### What no person has verified
- The canvas at the machine: legibility at the rig's font sizes, zoom and pan, colours, the pin glyphs, the APC40's long port list, the narrow-page pane.

### Known rough edges
- Draw cost: about 2.3 ms median in the windowed smoke (53 nodes, 228 cables, patched only), about 3.8 ms with every node expanded (headless).
- `graphview.key` builds a tuple over every binding each frame (microseconds; noted).
- Port positions are estimated for `auto_layout`, not measured.
- D1's `after` / `into` placements are not read. A placed `Effect` node shows because the render cables come from `render_graph`'s nodes and their inputs generically (tested with a hand-built graph).

## 4. Where the documents and the code differ
- The brief says graphview imports `devices`. It does not need to: the registry is read through the protocol. It imports `routing`, `params`, `graph`, `patch`, `modifiers`.
- "selection … in a side column": the column is beside the canvas only on a wide page and below it otherwise (row above).
- The design names LFO knobs `depth rate phase`: every knob `lfo.<n>.*` is a port. `lfo.trigger` sits on `group:lfo`.
- "SYSTEM's panel line" did not exist, so this WP adds the GRAPH page's own line.
