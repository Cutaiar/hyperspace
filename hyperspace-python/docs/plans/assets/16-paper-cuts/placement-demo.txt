==== real launches (2026-10-04, pasted by hand; everything above this line is the script's)

This machine, one screen connected — GLFW says:
  screen 0: 'Built-in Retina Display' work area x=0 y=33 w=1728 h=1010
No second screen, no projector: nothing below shows a window moving between screens.
Every launch ran on a fresh temp home (HYPERSPACE_HOME=/tmp/p16wp4/home.odT5Tt), 20 frames.
Launches 2–4 went through a wrapper that calls app.main() with app._windows wrapped to
print glfw.get_window_pos / get_window_size of both windows right after creation
("probe:" lines); the app's code was not instrumented.

-- launch 1: first launch, no windows.json, no config.toml
$ HYPERSPACE_HOME=<tmp> HYPERSPACE_FRAMES=20 uv run hyperspace
dream: mps · alias copy path · fp32 · weights <tmp>/weights
(exit 0)
<tmp>/windows.json, written at the quit:
  control = {"x": 752, "y": 65, "w": 960, "h": 900, "screen": "Built-in Retina Display"}
  render  = [{"x": 16, "y": 65, "w": 1280, "h": 820, "screen": "Built-in Retina Display"}]
(placement asks for y = 33 + 16 = 49; macOS puts the content area at 65, title bar under
the menu bar — the same as before this change, which asked for the same spot.)

-- launch 2: the file as launch 1 left it
$ HYPERSPACE_HOME=<tmp> HYPERSPACE_FRAMES=20 uv run python probe.py
probe: render: pos=(16, 65) size=(1280, 820)
probe: control: pos=(752, 65) size=(960, 900)
(exit 0; windows.json rewritten with the same numbers — the round trip does not drift)

-- launch 3: windows.json edited by hand to another spot on the same screen
  control = {"x": 520, "y": 140, "w": 900, "h": 760, ...}
  render  = [{"x": 180, "y": 210, "w": 1000, "h": 640, ...}]
$ HYPERSPACE_HOME=<tmp> HYPERSPACE_FRAMES=20 uv run python probe.py
probe: render: pos=(180, 210) size=(1000, 640)
probe: control: pos=(520, 140) size=(900, 760)
(exit 0; windows.json after the quit: control 520, 140, 900×760; render 180, 210, 1000×640)
