## 1. Register-row drafts

**1xx — The preset's `graph` section is a list of the nodes that differ from the default graph, one JSON object per node**
- **Built:** a preset may carry `"graph": {"nodes": [...]}` (`graph.GraphSpec`, `graph.read_graph`, `preset.GraphSection`). Each entry names its `kind` and, for a second or later node, its `instance`; the rest of an entry is its wiring — `hands`: `into` (`layer` | `scene`), `draw` (`solid` | `lines`), `laid` (`over` | `add` | `depth`, only on the hands node that makes the layer); `effect`: `file` and `instance` ≥ 2 (instance 1 is the file itself, always there); `history`: `holds` (`scene` | `scene+hands`). A node that is the default (hands 1 a solid layer laid over, the history of the scene) is left out, so `{"nodes": []}` and no section both mean the default graph. A save writes the section back in a fixed order (hands by instance, effects by file and instance, the history, later kinds), one node per line in the file (`preset.dumps`), placed before `values`. Nothing that is a param goes in it: an effect's on/mix/order, `ghost.*`, `dream.*` stay in `values` or the show. The owner will see a `graph` block in a preset file that has one, and none in any factory file.
- **Other options:** a full node-and-edge list (every node and every wire, `{"nodes": {...}, "wires": [...]}`) — what plan 28's editor will want, but today only the default graph's builder exists, so most of it would be ignored or re-derived and every file would be long; a flat object of the `Wiring`'s fields (`{"hands": "scene", "blend": …}`) — shorter, but it cannot name instances or a later node kind.
- **To reverse:** local to `graph.read_graph` / `GraphSpec.to_json` and `preset.GraphSection`; no factory file carries a section, so only owner-written presets would need rewriting.
- **Rough edge:** the section is wiring choices for the default graph, not a graph: the outputs (session) still come from the OUTPUT page's switches, so a preset cannot say which output gets which hands node. At most one hands node makes the layer (two `into: "layer"` is refused). Keys are strict: an entry with a key this build does not know is unreadable (a note and the default graph), so a newer build's extra key falls back whole in an older one — but the section is kept as the file had it and written back on save.
- **Judge it:** V.18.

**1xx — A section this build cannot read is a note and the default graph, and is kept as the file had it**
- **Built:** an unknown node kind (`"teapot"`), a value out of its choices, a key a node does not take, two nodes of one instance, two layers, `laid` on a node that makes no layer: `graph: unknown node kind 'teapot' (this build knows effect, hands, history); the default graph` on the preset strip's warning line; the values, routes and desk land as ever. The section is kept verbatim (`GraphSection.doc`) and a save writes it back, so a preset written by a later build (say, plan 28's node kinds) survives a save in this one. A `cloud` kind in a preset's graph is such an unknown kind in this run: point clouds follow the device list (A4b: `default_graph(…, clouds)` from the registry), not the preset's graph section, until plan 28 (orchestrator's ruling, review round 1). The whole section falls back, never part of it.
- **Other options:** drop only the bad node (a partial graph the author never wrote); drop the section on save (loses a newer build's work).
- **To reverse:** one branch in `GraphSection.read`.
- **Rough edge:** a preset whose section fell back is not marked "dirty" and saves it back unread; the note is the only sign.
- **Judge it:** V.18.

**1xx — The instance marker as built: `fx.<file>.<n>.*` for an effect, `ghost.<n>.*` for a hands node, its layer `hands.<n>`**
- **Built:** A0's rule, used. A second acid in the chain is the effect named `acid.2` in `FxState` (`set_instances`; its spec is the acid file's, labelled "Acid 2"), so its params are `fx.acid.2.on/mix/speed/blend/order/target/bend/…` ("Acid 2 mix" on ROUTING and in learn lines), performance params a preset's `values` carry; it has its own clock and order and runs on the file's one compiled program (`FxChain` programs are keyed by file). A second hands node is `ghost.2` with `ghost.2.on/alpha/mirror/guide/tethers/style` ("Ghost 2 opacity"), session params like `ghost.*` (same group); its layer node is `hands.2` and its lone readout `readout.2` on the SYSTEM page. The first instance keeps today's ids, so no preset or binding migrates. `fx.declare` re-declaring an effect file drops only that effect's own ids (`fx.<name>.<key>`, key with no dot), never an instance's under it; `fx.parse` refuses a purely decimal `@param` key (A0's guard, at the source).
- **Other options:** an instance as its own effect file (`acid_2.glsl`: a copy to keep in step); a per-instance prefix group (`fx2.acid.mix`: a new first segment, rejected by A0).
- **To reverse:** `FxState._extras` / `set_instances` and `ghost.prefix`; before an owner preset uses `fx.acid.2` cheap, after it a rename of saved ids.
- **Rough edge:** an `fx` module preset saved while a second acid exists holds `fx.acid.2.*`; loading it where the graph has one acid says "unknown id(s)". A second instance of an effect not on disk waits (its count is kept and it appears with the file). `ghost.2.*` are session params, and a show restores its session before its startup preset declares the node: review round 1 fixed what that cost (the ids reported as unknown at launch, the settings lost to a fresh state with `on` false, the show dirty at once, a save writing the defaults over the owner's mirror, style and opacity). Now the show holds them back (`Project._apply` does not report `ghost.<n>.*` it cannot place; `is_dirty` and `save` carry the held-back ids, `Project._held_back`), and `GraphSection` seeds a newly declared node from the open show's session once per show opened (`Project.opened`), an id the show lacks taking the state the landing left; so the glass comes up as saved and the show is clean. A setting changed live, then the node dropped and brought back by presets in the same show, keeps the live value.
- **Judge it:** V.19, V.20.

**1xx — A second hands node is its own `Ghost` over its own `GhostState`, made by the renderer on first use and kept while the app runs**
- **Built:** `preset.GraphSection` declares `ghost.2.*` on a `GhostState` it keeps for the run (`states`), hands it to the renderer (`Renderer.ghost_states`), and `Renderer.ghost_of("ghost.2")` makes a `Ghost` over it on first use, following the first ghost's tracker and routing table every frame; the graph's `Hands`, `HandsLayer` and `Readout` nodes draw through their own node's Ghost, and `Output` lays its own layer's Ghost and its own readout's (`_compose(ghost=, readout_ghost=)`). The layer and the readout are kept per node in `frame.data` (A3's single `Frame.hands` / `Frame.readout` slots are now only "any"). A graph that no longer holds `ghost.2` releases its Ghost (`Renderer.drop_ghosts`, also on a hot reload); a preset that brings the node back finds its settings as they were (the state is kept, the params re-declared over it).
- **Other options:** the state owned by the renderer (the registry would then need the renderer to declare `ghost.2.*`, which the render stack must not do); a fresh state per load (the glass's mirror and style lost at every preset change).
- **To reverse:** local to `GraphSection.land`, `Renderer.ghost_of`.
- **Rough edge:** `ghost.2.on` starts off (`GhostState`'s default, decision 24), so a preset that adds the node shows nothing on the glass until the show switches it on. The extra Ghost is not a hot-reload target (it is released and rebuilt from the new `ghost.py` instead); the HANDS page shows `ghost.*` only — `ghost.2.*` are reachable from ROUTING, Learn and the desk, not from a page of their own (plan 28).
- **Judge it:** V.20.

**1xx — Where two hands nodes go: every `into: "scene"` node in the scene, the `into: "layer"` node (else the first) on the outputs without the hands in their scene**
- **Built:** `graph.default_graph` with `Wiring.extra`: the scene draws every in-scene hands node (solid first, A3); the layer is drawn from the node `into` "layer", else from the first (A3's single node, `Wiring.layer_node`), and laid over or through on every output whose hands switch is on and whose scene does not hold hands (the scene switch off, or no node in the scene). An output showing the scene with hands in it takes the first in-scene node's readout (the readout alone, or its own layer's when it is also the layer); one taking the layer, the layer's. With `ghost` in the scene and `ghost.2` the layer: the projector (scene + hands) shows `ghost` in its scene, the glass (scene off, hands on) shows `ghost.2`'s own picture — its own style, opacity, mirror and guide.
- **Other options:** both nodes on every output (the projector would show the hands twice); a per-output choice of node (needs output.N params and a session decision: plan 28's editor).
- **To reverse:** local to `default_graph`.
- **Rough edge:** a glass that shows the scene too (scene on) gets the scene's hands, not the second node; to put the second node on the glass its scene switch must be off.
- **Judge it:** V.20.

**1xx — A hands node's time is decided by the consumer edge (`Graph.timed`), never set on the node**
- **Built:** `Hands.TIMED` is a plain `False`; `Graph.timed` lists every node that times itself plus every solid geometry a scene draws (`Graph.in_scene`), so one hands node feeding a scene and a layer has its own line (its in-scene draws) beside the layer's, and the same node object in two graphs is never changed by either (A3 set `in_scene` on the node from the Scene's constructor). SYSTEM lines with two hands nodes, `ghost` in the scene and `ghost.2` as the layer: `ghost scene cover hands.2 readout history fx … output.N`.
- **Other options:** per consumer edge timing of every draw (a `ghost→hands` line as well as `ghost→scene`): more lines for one hand pass.
- **To reverse:** two lines in `Graph.timed`.
- **Rough edge:** the layer's draw of a node that is also in the scene is still counted in the layer's line, not the node's.
- **Judge it:** V.17 (A3's), V.20.

**1xx — "Hands as lines" is a hands node's `draw: "lines"`: the style's own meshes drawn as edges (`ctx.wireframe`)**
- **Built:** a hands node may be drawn `lines` (`HandsAt.draw`, the graph JSON's `draw`): `Ghost.draw_solid(…, lines=True)` and `Ghost.layer(…, lines=True)` draw the style's spheres, capsules and palm as their triangles' edges, one pixel wide, depth-tested and depth-writing as ever (`Geometry.draw(lines=)` sets `ctx.wireframe` and puts it back); the guide stays solid, drawn after the parts as for any style but HANDS. It is a node setting in the preset's graph, not a param: `ghost.style` stays the session's, so a preset could not say "lines" through it, and the hands' look as params is out of scope (H3). Default `solid`: today's picture.
- **Other options:** a sixth `ghost.style`, LINES (a session param: a preset could not choose it; an enum index the owner would see in every style menu); quads for the bones like the shape's edges (a real line width; a new draw path in `ghost.Geometry`).
- **To reverse:** remove `draw` from `HandsAt` and the `lines` keyword (three call sites).
- **Rough edge:** wireframe lines are one pixel wide whatever the dpr (core GL has no wide lines), so on a 2× screen they are thin; the capsule's tessellation shows as a dense hatching rather than a skeleton of lines — the owner judges whether this is "lines" or wants bone lines (plan 28 / H3).
- **Judge it:** V.21.

**1xx — The OUTPUT and LOOKBACK pages say the wiring in words, on lines they already had**
- **Built:** the OUTPUT page's "shows:" line says the wiring under a preset's graph (`ui.output_shows(…, wiring)`): an output whose scene holds the hands "scene + hands: in the scene as lines" — whatever its own hands switch says (review round 1: the scene holds them anyway, the switch wires only the readout); a layer laid on its node when there are two ("hands through the effects (2)"), "as lines", "· depth-aware" / "· added". With the default graph the words are today's, unchanged ("scene + hands over the effects" already says over / through). Its hover gives `hands: in the scene · …` (`graph.hands_words`) and the loaded graph in one line (`graph: hands 1 in the scene as lines · history with the hands`, `graph.graph_words`). The LOOKBACK page says `history: the scene` or `history: the scene · with the hands` under its switch (`ui_lookback.history_line`, `graph.history_words`), in the spacing that row had. No editor (plan 28). The existing switches still set the default graph's wiring.
- **Other options:** a line per output of its own (`hands: …` under "shows:") — four outputs then overflow the control window (the page-fit tests); the whole graph as a line on the page — the same.
- **To reverse:** local to `output_shows` and the two pages.
- **Rough edge:** after a hot reload of graph.py the held `Wiring` / `GraphSpec` are the old module's classes, so `output_shows`'s `wiring != Wiring()` is always true until the next preset load (harmless today: the default wiring's `layer_words` is "" and in-scene needs `in_scene()`). The full graph line is on a hover only; a hidden layer node ("hands 2") is named by number, not by what it is for.
- **Judge it:** V.22.

**1xx — Undoing a load puts the loaded preset's graph back first**
- **Built:** `library.Marks.take` carries `GraphSection.mark()` (the spec and the section as read); `Marks.before` lands it again before the values, so undoing the load of a preset with a second acid removes `fx.acid.2.*` and redo brings them back with their values. A load refused for a value that will not land puts the graph that was there back, with its instances' values.
- **Other options:** none worth it: without it an undo would put values on params that no longer exist.
- **To reverse:** two lines in `Marks`.
- **Rough edge:** none known.
- **Judge it:** V.18.
