## 1. Register-row drafts

### 1xx. What makes a desk control "dead": `learn.cannot_show`

- **Built.** The coverage report calls a control **dead** when the loaded preset has a row on it but cannot show that row's param. Click-to-map never offers such a param as one of this preset's own. The rule reads the preset's bases as loaded, not modulation, group by group:
  - `pattern.*`, `view.pattern` and `view.pattern_mix` are dead when the faces are off.
  - `view.bmp_*` (alpha, scale, mode, amp, rate) are dead when the faces are off, or when `view.bmp_file` is empty.
  - `view.points_alpha` is dead when points are off, and `view.lines_alpha` when lines are off.
  - `fx.mix` is dead when the effects are off (`fx.on`).
  - `fx.<effect>.<key>` (not `.on`) is dead when the effects are off or that effect is off.
  - `dream.*` (not `dream.on`) is dead when the look-back is off.
  - `rot.rate.*` and `view.plane.*` are dead when rotation is off (`view.rotate`: `ViewState.integrate` returns early).
  - A target the registry lacks is dead ("no such param").
  - Everything else can always show. A switch the values do not name counts as on.

  Today this makes K7 (`view.bmp_alpha`) dead on every factory preset, and K4/D4 (pattern, pattern mix) dead on the presets that have the faces off.
- **Other options.**
  - Judge by the live frame (a modulated base, a hand turning the faces on). That changes from moment to moment, so the report could not be committed.
  - Add more groups: instances 0 (nothing is drawn at all), the bitmap's path params while its alpha is 0, the look-back's dream knobs while `dream.mix` is 0, an LFO's knobs while no route reads that LFO.
  - Leave out the bitmap-file rule. Then K7 would read as mapped on every preset.
- **To reverse.** Edit `learn.cannot_show` (one function, with its comment table above it) and run `uv run python tools/desk_coverage.py` to rewrite the report.
- **Rough edge.**
  - The render toggles are invariant (C1), so the performer can press Faces at any time. A pattern knob on a faces-off preset is "dead" until someone does.
  - "No bitmap file" makes K7 dead everywhere, because the fresh desk puts bitmap alpha on K7 and no factory preset ships a bitmap.
- **Judge it.** Check U.8.

### 1xx. The preset layer the coverage counts: 38 controls

- **Built.** The table's columns are fixed:

  - every other control the factory map (`apc40.DEFAULT_MAP`) gives a preset-layer row: the grid-motion pads G3·5–8, the plane buttons G8·1–6, the view reset G5·9, the cue knob C (shape), and ▲ ▼ (B16, B17);
  - less any control an invariant row of the session table holds.

- **Judge it.** Check U.8.

### 1xx. The desk template format: `hyperspace.desk/1` in the `desk` group; a preset names one and keeps its overrides

- **Built.** A template is `<root>/desk/<slug>.json`: `{"schema": "hyperspace.desk/1", "name", "note"?, "desk": [rows]}`. The rows are in a preset's `desk` form (no `layer`), written one row per line (`preset.template_doc`, `dumps`).
  - **Where the files live.** The factory's live in `hyperspace/library/desk/`, which ships empty. That needs no folder and no marker file: the group lists `[]` without one. The user's live in the library root, so `[library] path` shares them (plan 25).
  - **Naming a template.** A preset names one with `"desk_template": "<name>"`, written before `"desk"`, and then `"desk"` holds only overrides:
    - an override row replaces every template row on an overlapping control (`Binding.overlaps`, so `cc:*:16` and `cc:0:16` are one control);
    - a dark row `{"source": "cc:0:49", "dark": true}` leaves a template control unmapped.
  - **Load** (`expand_desk`). The desk is the template's rows that no override or dark row covers, in template order, followed by the override rows. They then go through `set_desk` as any desk does.
  - **Save** (`compact_desk`). The file gets the name and the live rows that differ from the template on each control (in live order), then a dark row for each template control the live desk leaves unmapped (in template order). A template row the load would drop (an invariant control, SAVE) is no difference.
  - **Reading the reference.** It is read from the loaded preset's file (`Presets.template_of_loaded`), not held in memory, so an undo that brings back an earlier preset also brings back its reference.
  - **Missing template.** The load note is "desk template 'x' not loaded (…): this preset's own desk rows only", and the desk is the overrides alone. A save keeps the reference, with every live row as an override.
  - **Plain presets.** A preset with no `desk_template` key takes exactly today's code path.
  - **The `desk` param group.** Templates are read only through `Library.desk_template` and are never applied as a module preset of the `desk` param group (`desk.slew`, `desk.pad.*`), which has no strip.
- **Other options.**
  - A separate group name (`desk-templates/`). That would avoid sharing the folder name with the `desk` param group, but the plan names `hyperspace/library/desk/`.
  - Register `desk` as a `Library.kind`. That would change the session `desk` param group's project-load bookkeeping (`Project._apply` skips kinds) for no gain.
  - Overrides keyed by glyph rather than MIDI source.
  - Overrides that always rewrite the whole expanded desk. A fix to the template would then not reach the presets that use it.
  - Hold the reference on `Presets` at load. It would go stale after an undo.
- **To reverse.** Remove `TEMPLATE_KEY` handling in `Presets.load_doc` and `_desk_part`, the four helpers in `preset.py`, and `Library.desk_template`, `DESK` and `DESK_SCHEMA`. Any preset that names a template would then need its desk expanded first.
- **Rough edge.**
  - There is no UI to save or edit a template. The owner writes one by hand or with `preset.template_doc` + `dumps`.
  - Editing a template file on disk does not re-apply a loaded preset that uses it (the file watch follows the preset's own file). Reload the preset. Until then a save compacts against the template **as the load read it** (`Presets._at_load`, review round 1), so the edit never turns into overrides that undo it; the fix lands at the next load.
  - The template folder is the `desk` param group's folder name too, so `Library.default_name("desk")` is None: a template named "default" is never taken as that group's default module preset (review round 1).
  - A hand-edited desk holding two rows on one knob by two spellings (the template's `cc:*:16` and a `cc:0:16`) loses the any-channel one on a save-and-load round trip.
  - Plan 13's `same()` (the migration's comparison) sees a templated user preset's overrides, not its expanded desk. This is harmless: the migration has run on both homes. Note for C7.
  - Saving against a missing template loses that preset's dark rows: there is nothing to darken.
  - An older build that loads a templated preset ignores `desk_template` and chokes on a dark row.
- **Judge it.** Check U.9.

### 1xx. Click-to-map ranks the preset's own params first: `learn.ranked`

- **Built.** While a control that can be mapped is picked (`ui_desk.picking`), the desk lists this preset's params on its empty ground under the transport row (`ui_desk.OFFER` = layout x 9.7–13.7, y 10.45–13.4; a test proves it covers no control, so the desk's layout and hit-testing never move). The list comes from `learn.ranked`, a pure function over (id, group) of every desk target, the bases, the performance groups' defaults (`Library.defaults`), the routed set (enabled route targets and macro base subscribers) and the ids on the desk. It is built in four tiers, each in registry order:
  1. **routed**: a route or a macro moves it;
  2. **moved**: its base is off the group default;
  3. **on**: it belongs to an effect, the look-back, the faces (pattern, bitmap), the points or the lines, and that module is on;
  4. **on the desk**: it is already on a control.

  A param the preset cannot show (`cannot_show`) is never one of these. The rest are grouped by registry group, performance groups first. A chip, "all params ▾", opens a popup with this preset's params (each tagged with its tier) and a menu per group of the rest. A click calls `Learn.map_picked`, the same road the page click takes, and that road still works beside it. The offer is cached per pick, table state, macros serial and loaded preset.
- **Other options.**
  - A popup that opens on the pick. This was rejected: an imgui popup blocks hovering every other window, so a second click on the desk (let go, or pick another control) or on a page param would only close it. That would break plan 17's tested behaviour.
  - A block at the top of the panel's page. Pages are laid out to fit without scrolling.
  - Rank "on the desk" first. Other tier orders.
  - Score session params "moved" against their fresh values.
- **To reverse.** Drop `_offer` from `ui_desk._body`. `learn.ranked` and `cannot_show` can stay for the report.
- **Rough edge.**
  - At the default control-window size the desk is small: the offer is about 107×79 px. Its items are drawn in 11 px type, and the chip reads "all ▾" beside the head, so five items show and the rest scroll (review round 1; a test holds the chip and three items inside it). On the big desk (panel hidden, or a wide window) it holds more, at the labels' size, with "all params ▾".
  - The "on" tier includes an effect's plumbing keys (`.blend`, `.order`, `.target`) beside its look params. Leaving them out is the owner's call (U.10).
  - A long list (TRIP's routed pattern inputs) pushes the moved and module params down. Use the "all" chip.
  - The offer reflects the state at the moment of the pick. A base moved during the pick does not re-rank it.
- **Judge it.** Check U.10.
