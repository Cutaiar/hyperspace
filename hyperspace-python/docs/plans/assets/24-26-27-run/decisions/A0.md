## 1. Register-row drafts

**1xx — The instance marker for an extra render node is a number right after the node's prefix (`fx.acid.2.mix`)**
- **Built:** `params.instance_id(node, key, n)` and `params.instance_of(pid, node)`. Instance 1 keeps today's id (`fx.acid.mix`, `ghost.alpha`, `dream.mix`). Instance n ≥ 2 is `<node>.<n>.<key>` (`fx.acid.2.mix`, `ghost.2.alpha`). The first segment, which is the group, never changes, so an extra instance lands in the same part of a preset as its first, and no preset or binding migrates for a single-instance graph. The rule is in ENGINEERING §2. The owner will see these ids in ROUTING, learn lines and preset files once A4 adds a second instance.
- **Other options:** `fx.acid#2.mix` / `fx.acid@2.mix` (unambiguous, but a new character in ids that OSC addresses, file names and bindings would all have to accept); `fx.acid_2.mix` (collides with an effect file named `acid_2`); `fx2.acid.mix` / `2.fx.acid.mix` (a new first segment: changes the group, rejected by the plan).
- **To reverse:** cheap before A4 ships a second instance (two functions and one doc paragraph). After that, a migration of every saved id that carries a marker.
- **Rough edge:** a purely decimal segment after the prefix is the marker. That forbids an effect file or a param key that is purely digits (pinned by a test), and it looks like the existing collection indices `band.2.trim` / `pattern.mod.3`, which are not node instances: `instance_of` is only asked about node prefixes (`fx.<file>`, `ghost`, `dream`).
- **Judge it:** V.3.

**1xx — Golden frames render the eight output states as eight outputs of one frame**
- **Built:** per preset and hand state, one rig draws all eight `Switches` states as eight views of one `draw_outputs` call. Output 1 is 4× MSAA like the window and sets the scene's sample count; the other seven are plain targets. 46 rigs in about 8 s, so the golden test costs about 6 s of the gate.
- **Other options:** one output per state, each with its own rig (368 rigs, roughly 45 s, and the "direct" single-output path in every frame); single-sample output 1 (no MSAA, unlike the window).
- **To reverse:** change `_shoot`'s view list and re-record (one command). Every golden moves.
- **Rough edge:** a pipeline shared by two of the eight views goes through a frame texture, not "direct" into the window. **Review fix round 1** therefore added single-output goldens. `solo` covers every preset × hands with output 1 alone at 4× MSAA in the default state (= scene+hands), drawn direct. `solo-scene+hands+through` covers the six effect-on presets × hands. That adds 58 goldens, for 427 in all and 73 distinct pictures. Three hands-absent solo frames (party-wake solo; hands-fx solo and solo-through) differ from their eight-output twin by 1 LSB in one pixel, so the direct MSAA path and the texture path are not bit-identical in general, and both are now pinned. A separate `solo-scene+hands` was not added because it is the same `Switches` as `solo`.
- **Judge it:** V.1.

**1xx — "LFOs and analyzer at rest" means never stepped and never fed**
- **Built:** the golden rigs declare the `lfo.*` / `tempo.*` params (so presets load them) but never step the LFOs and never feed the router an analyzer or LFO lane. Their routes contribute nothing and every param sits at its base plus the hand rows.
- **Other options:** step the LFOs at a pinned phase 0 (adds the LFO maths to every golden, and a random-shape LFO's seed); publish rest values explicitly.
- **To reverse:** add `lfos.step/publish` to `Rig.frame` and re-record.
- **Rough edge:** lfo-breathe's golden shows its bases, not its breathing.
- **Judge it:** V.1.

**1xx — "Hands present" in the goldens is one fixed two-hand pose with the ghost on**
- **Built:** `tests/fake_hands.py` hands at test_ghost's pose (left open at (−90, 210, 0) mm, right fist at (90, 200, 10)), polled fresh every frame through the real `HandsIO` (One Euro, dead zone, follower) so the preset's hand rows move. `ghost.on` is set true in every rig (a session param no preset carries). "Hands present with the ghost off" is not a separate set: its picture is the `hands=False` state's.
- **Other options:** several poses per preset (preset_shots' POSES), which would multiply the golden count; the ghost left at its session default (off), which would mean SCENE_HANDS / HANDS are never reached.
- **To reverse:** extend `FakeHands` / `HANDS` and re-record.
- **Rough edge:** one pose per preset. A hand row's full throw is not covered by goldens (preset_shots' sweeps cover it numerically).
- **Judge it:** V.1.

**1xx — The 1080p-cap golden is party-trip on a 2× HiDPI 1080p screen**
- **Built:** one extra golden: party-trip, hands present, `scene+hands`, a 3840×2160 output at dpr 2 (1920×1080 logical) under `max_frame = (1920, 1080)`. The frame is drawn at 1920×1080 and shown scaled. All other goldens also run under the 1080p cap (the app default), which has no effect at 960×600.
- **Other options:** an output of exactly 1920×1080 (the cap does nothing there); a preset without effects.
- **To reverse:** change `CAP` in the tool and re-record.
- **Rough edge:** hashing 33 MB once. Only one preset and one state are covered at the cap.
- **Judge it:** V.1.

**1xx — GPU time per pass: six passes, read 3 frames late, a median over 60 frames**
- **Built:** `render.PassTimer`, with passes scene (the face picture, the scene pass and the MSAA resolve), cover, hands (the hands' layer and the hands-through composite), lookback (every composite and the capture), fx (each chain run) and compose (every output's picture, its hands over, readout and dim). Queries never nest. A pass that runs several times a frame is summed, and a pass that did not run counts 0 for that frame. `stats["gpu_ms"]` holds the medians and `stats["gpu_note"]` says why there are none. The SYSTEM page shows a heading "gpu per pass, ms (median of the last frames):" and then one line per pass.
- **Other options:** one dot-separated line (the prompt's example text); nested queries for whole pipelines (GL forbids nesting); reading every query at once (stalls the CPU on the GPU every frame).
- **To reverse:** local to `PassTimer` and `Panel.gpu_lines`.
- **Rough edge:** Apple's driver reports some tiny passes as 0.00 ms. The figures are GPU time only, not the CPU's time to issue the pass. The lines show one frame's medians, with no history.
- **Judge it:** V.2.

**1xx — The golden tool keeps one standalone GL context for the process**
- **Built:** `tools/golden_frames.context()` makes one standalone context with `gc_mode = "auto"` and collects each rig's objects after it. `tests/test_golden_frames.py` uses the same context.
- **Other options:** a fresh context per rig (the cleanest isolation, but `release()` leaves no context current and broke the GL tests that ran after it in the same module).
- **To reverse:** local to the tool.
- **Rough edge:** none seen. The hashes are byte-identical to a per-rig-context recording.
- **Judge it:** V.1.

## 3. As-built notes (shape of plan 21)

**At the machine.** Nothing visible changes except the SYSTEM page, which gains a "gpu per pass" block with one line per pass (median ms). The goldens are a developer tool: `uv run python tools/golden_frames.py` diffs, `--record` re-records, and `--only party-trip,legacy6` limits the run to those presets.

**Code.**
- `hyperspace/render.py`: `GPU_PASSES`, `PassTimer`, `_Timed`; `Renderer.timer`, `_pass_timer`, `_timed`. `_draw_frame` is now a wrapper that runs `_frame_passes` (the old body, with timed sections) and fills `stats["gpu_ms"]` / `stats["gpu_note"]` in `finally`.
- `hyperspace/ui.py`: `Panel.gpu_lines`, `Panel._gpu_timing`, and one call in `_page_system` after `_stall_status`.
- `hyperspace/params.py`: `instance_id`, `instance_of`.
- `tools/golden_frames.py` (new); `tests/golden/frames/frames.json` + `png/` (73 files; 427 goldens after review fix round 1, including 46 `solo` and 12 `solo-scene+hands+through`). The manifest stores GL_RENDERER and GL_VERSION.

**For A4 (from review):** `FxState.declare` should refuse, or warn about, a purely decimal `@param` key once instances exist, because `fx.acid.2` would read as a marker. Today a test pins that no key is decimal; A4 should guard it at the source. An explicit `.1.` segment is never written, and `instance_of` reads it as part of the key by design (commented and pinned).
- `docs/ENGINEERING.md` §2: "Node instances: the naming rule".

**Tests.** `tests/test_golden_frames.py` (new, 6 tests); `tests/test_params.py` (+2). 1893 passed, 2 skipped, against 1885 + 2 on the base.

**What no person has verified.** The SYSTEM page's GPU lines in the live app, which were only drawn headlessly. The PNGs looked right to me (hands visible in the hands-only states, bent in party-trip's through state). The goldens are not proven against a real Leap hand: they use the synthetic pose.

**Rough edges.**
- The goldens are only meaningful on "Apple M3 Max". Anywhere else the test skips, so a CI or another Mac proves nothing about pixels.
- lfo-breathe's golden is its bases, since the LFOs are at rest.
- Tiny passes can read 0.00 ms on Apple's driver.
- The manifest records each state's `route` from `outputs.route`. A1's graph should keep `outputs.route` (or an equivalent) so the tool can still name the route.

## 4. Deliberately not done / where docs and code differ

- The prompt's example SYSTEM text is a single dot-separated line (`scene 1.2 · cover 0.1 · …`), but it also says "one line per pass". I built one line per pass under a heading.

The goldens instead feed full `fake_hands` namespaces (features and skeleton, as `LeapSource._frame` does) through the same `HandsIO`, so the hands both move the routes and draw.
