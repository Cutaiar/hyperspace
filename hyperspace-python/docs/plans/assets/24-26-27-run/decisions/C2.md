## 1. Register-row drafts

### 1xx. The band audio strip sits on the SHIFT-layer faders, not the knobs (amends D6)

- **Built.** With SHIFT latched, track faders S1–S6 are the six bands'
  post-drive (`band.{i}.post`), S7 is `master.dyn` and S8 is
  `master.trim`, as global-layer rows in `apc40.DEFAULT_MAP`
  (`apc40.SHIFT_FADERS`). With SHIFT up, S1–S8 are the loaded preset's.
  MASTER (`master.gain`) and the crossfader (`output.dim`) stay invariant.
  The owner reaches the audio by latching SHIFT and pulling a fader. The
  fader then catches the band's value first (soft pickup, next row).
- **Other options.** Put the strip on the SHIFT-layer track knobs 6–8
  plus the device knobs. The knobs are endless and jump to the value
  (D7), so no pickup would be needed, but eight audio params do not fit
  on the free knobs. The working plan's open question asked "faders or
  knobs"; the dispatch said faders.
- **To reverse.** Drop `layer=G` from the eight rows in `DEFAULT_MAP`,
  move their keys out of `routing.FADER_SHIFT_ROWS` (or invert that
  remap), and regenerate `bindings.default.json`.
- **Rough edge.** Under SHIFT a fader rarely sits where its band is, so
  the first pull after a latch does nothing until it crosses the value.
  None of this has been tried on the APC40.
- **Judge it.** Check U.6.

### 1xx. A layer switch re-arms every layered fader from where it physically is (D7 made real)

- **Built.** One physical fader now serves two params (the preset's and
  the band's). On every SHIFT latch or unlatch, each layered fader row
  (preset or global; abs; no ring) takes the fader's last physical
  position (`MidiIO._hw`) and is caught only when its param already sits
  within the pickup tolerance (1.5/127). Otherwise it waits until the
  fader crosses the value or reaches it. A fader moved on one layer
  never jumps the other layer's param. On a load, C1's rule (every
  preset fader lets go) still decides.
- **Other options.** Keep each row's catch across the switch, which is
  what the code did before (no layered fader existed, so nothing showed
  it). The fader would then jump the other layer's param on its first
  move. Or uncatch with no position seed: a fader already sitting on the
  value would then need a crossing.
- **To reverse.** The `switch` block in `MidiIO.redraw` and the
  `switch=` argument in `_follow_table`.
- **Rough edge.** A fader not moved since launch or a reconnect has no
  position, so it catches only on a move that lands within tolerance; a
  stale position is never taken for a crossing (review of PR #180).
- **Judge it.** Check U.6.

### 1xx. Lines and points opacity: `view.lines_alpha`, `view.points_alpha`

- **Built.** Two continuous 0–1 params in the `view` group (performance,
  persisted, modulatable), both defaulting to 1. Each multiplies the
  alpha `draw_scene` already gives an edge or a point, as one factor on
  an existing line, so 1 gives the picture as it was and 0 makes the
  layer fully transparent. They sit as a pair of sliders on the VIEW page
  under the Points/Lines/Rotate/Faces checks ("Points opacity", "Lines
  opacity"). No desk row, no preset value. All 427 golden frames match.
- **Other options.** Use the ids `view.lines.opacity` / `view.points.opacity`,
  or add an opacity uniform in the shaders. Or apply the factor before
  the `np.clip` floor: then opacity 0 would leave a 0.015 / 0.05 floor
  and never reach transparent.
- **To reverse.** Remove the two `r.continuous` calls, the two
  `ViewState` fields, the two factors in `render.py` and the slider row
  in `ui.py`.
- **Rough edge.** A preset saved from now on carries both values (at 1
  unless moved). A preset that lacks them, every factory one included,
  puts them back to 1 on load (the loader gives every performance param
  missing from a file its group default), so a factory preset always
  shows its layers at full opacity. A2's
  rewrite of `draw_scene` must keep the two factors.
- **Judge it.** Check U.7.

### 1xx. Fader rows in a preset's desk: `preset.track_fader` and `knob_desk(…, faders=)`

- **Built.** `preset.track_fader(k, target)` is track fader k on the
  preset layer (abs, `ring: 0`, soft pickup, no light).
  `knob_desk(targets, faders=())` adds `faders[k]` on fader k + 1, with
  None leaving a fader dark. The default `()` adds nothing, so every
  factory spec writes exactly today's desk. `fresh_desk` / `file_desk`
  bind no fader. A preset desk's fader rows load, save and redraw like
  knob rows; nothing new in the file format.
- **Other options.** A separate `fader_desk(...)` factory beside
  `knob_desk`.
- **To reverse.** The two helpers and the parameter.
- **Rough edge.** No factory preset uses it yet (decision 23). The
  fader sets are the owner's authoring pass.
- **Judge it.** Check U.5.

### 1xx. The session file's eight fader rows move to SHIFT once, with a backup

- **Built.** On load, `routing.remap_factory` gives each exact old
  invariant fader row (`FADER_SHIFT_ROWS`: `cc:k:7` → the factory target,
  abs, no layer) the global layer, with the note "moved cc:k:7 →
  band.k.post to the SHIFT layer (the APC40 map of plan 24: the track
  faders are the presets')". The file is backed up
  (`bindings.json.bak-v3`) and written back once; the next load is quiet.
  A fader row the owner changed is kept invariant, so that fader stays
  the owner's on both layers, and a preset row on it drops with D6's
  note. A schema-1/2 file gets the strip on SHIFT through
  `sort_layers` (8 more "added … (the global layer)" notes).
- **Other options.** Drop the old rows and add new ones. The note would
  read as two changes, and an owner's flags (pickup off, say) would be
  lost.
- **To reverse.** `FADER_SHIFT_ROWS` and its `elif` in `remap_factory`.
- **Rough edge.** This is the first remap that changes a row's layer and
  nothing else, so the remap's note uses "moved", not "remapped".
- **Judge it.** Check U.6 (first launch on the owner's machine: the
  SYSTEM line says the file was updated, and a backup exists).

## 3. As-built notes (for `docs/plans/24-…`)

**At the machine.** With SHIFT up the track faders S1–S8 belong to the
loaded preset. No factory preset binds them, so they are dark. A preset
whose desk binds them lights them on the on-screen desk and drives its
params. Latch SHIFT and S1–S6 are the bands' post-drive, S7 dynamics and
S8 trim, as before but one latch away. MASTER is still audio drive and
the crossfader is still the master dim, on both layers. Each fader picks
up its own param after a latch. The VIEW page has Points opacity and
Lines opacity sliders, both at 1.

**Code.**
- `apc40.py`: `TRACK_FADERS`, `SHIFT_FADERS`, and the eight fader rows on
  the global layer (docstring: D6's list loses the faders).
- `routing.py`: `FADER_SHIFT_ROWS`, its `elif` in `remap_factory`, and
  `APC_REMAP_PLAN` naming plan 24 for those sources.
- `midi.py`: `redraw(switch=)` re-arms the layered faders on a layer
  switch; `_follow_table` passes it.
- `preset.py`: `track_fader`, `_is_track_fader`, `knob_desk(…, faders=())`,
  and docstrings on `fresh_desk` / `file_desk`.
- `view.py`: `ViewState.lines_alpha` / `points_alpha`. `params.py`:
  `view.points_alpha`, `view.lines_alpha`. `render.py`: one factor on
  each of two existing lines in `draw_scene`. `ui.py`: the slider pair on
  the VIEW page.
- `bindings.default.json` regenerated (the eight rows gain
  `"layer": "global"`).

**Tests.** `tests/test_desk_faders.py` (11 tests: fake ports, a scratch
library, the GL ones on a standalone context). The fixture is
`tests/fixtures/desk-faders/faders.json` (force-added). Existing tests
that used S1/S3 as "an invariant fader" now use MASTER (SM) or the
crossfader. The PR body lists each one.

**What no person has verified.** All of it on the APC40: the pickup
across the latch, the feel of the audio strip under SHIFT, and the
opacity sliders by eye (the goldens prove only that 1 is unchanged).

**Rough edges.**
- A fader not moved since launch (or since a reconnect) has no position
  after a latch: it catches only when a move lands on the value (review
  of PR #180: a stale position is never used as a crossing; a power-up
  also clears every row's own last position).
- The coverage report (C3) now counts S1–S8 as dark on every factory
  preset (eight more dark controls each) until the owner authors fader
  sets.
- `ui_desk`/`learn`: a preset-layer fader is now mappable by Learn, so a
  fader moved while a desk learn is armed is a learn candidate (it was
  invariant before, so it used to do its job through the learn). That is
  the intended consequence of decision 17.
