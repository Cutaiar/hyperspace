## 1. Register-row drafts (written as rows 210–213; row 141 amended)

- **210. The device qualifier is general: any scheme takes `@<role>`; an
  unqualified row is the primary device's.** Built: `base_scheme`,
  `Binding.device`, `bare`, `is_continuous` work for every scheme;
  `Binding.head` is the qualified Router key; MIDI's primary is B2's
  `midi_roles` unchanged, every other scheme's the first enabled entry of
  its kind (`primaries_of`, `DeviceRegistry.primaries`,
  `Bindings.primaries`); no file migrates. Other options: role-named
  schemes (`p2:A`), a `primary = true` key, migrating old rows. To
  reverse: `base_scheme` back to its MIDI test. Rough edge: `pad@pad:A`
  means nothing; swapping entries swaps the bare rows' pad; a role with
  `@` reads as a qualifier. Judge: 219.
- **211. A joystick per pad device; one USB reader, the first `usb = true`
  entry's.** Built: `gamepad.Claims` on `Context.pads`; next free GLFW
  joystick in list order or `joystick = n` (0–15, config-checked);
  lost → release → next free; pinned waits; SYSTEM `glfw n`; second
  `usb = true` reads GLFW only, `usb: pad has the wired pad`. Other
  options: GUID matching; USB to whichever pad has no GLFW joystick; a
  reader per entry. To reverse: ~40 lines. Rough edge: **with the
  defaults (usb = true on both) the wired pad on the second entry is never
  read** — the Bluetooth pad's entry needs `usb = false`; one wired pad
  only; GLFW indices can move across reconnects. Judge: 219.
- **212. The camera job and the factory pad rows are the primary pad's; a
  second pad starts with no rows; one feel.** Built per decision 24;
  `Router.source_feel` reads `axis@<role>` as `axis`. Other options: copy
  factory rows per pad; camera job on every pad; per-pad feel. Rough
  edge: per-pad feel is plan 28/29's; the menu's "Learn pad" item shows
  only while the first open pad is connected. Judge: 219.
- **213. The hands stay single.** `HandsDevice` not `repeatable`; the B1
  refusal stands. Judge: 174.
- **Row 141, "Changed in B6"**: the registry claims (scheme, role); a
  second pad opens under its role; the refusal stands for a kind that
  cannot qualify; a role listed twice is refused by the registry too.

Decisions this WP took itself (beyond the six rulings):
- **Learn pad stays one want** (`"pad"`), completed by whichever pad moves
  first; `Learn.accepts("pad")` reads the base scheme. No "Learn p2"
  item — ruling 2's "no page change".
- **The primary of a repeatable kind with no enabled entry** is the first
  listed (so an off second pad still publishes qualified schemes, and an
  off-only list publishes bare ones, as before).
- **A kept device whose qualifier changes is reopened** on a config edit
  (`DeviceRegistry.apply`): removing the first pad makes the second the
  primary with its rows bare, the factory rows and the camera job.
- **A role listed twice is refused in `make_all`** too (`RefusedDevice`
  with "role 'x' is listed twice — not opened"); config already drops it,
  this is the registry's own guard for ruling 2's "true collision".
- **Qualified rows say whose they are** in `describe` ("pad A on p2",
  "left stick X on p2 pushes …"), as a desk's say "on launch".
- **ROUTING keys a row's source on `Binding.head`** (`source_schemes`,
  `_sources`), so a route on a pad the rig lacks still shows its scheme.
- **USB ownership is decided at `attach` (device open), list order**, not
  at first need — as the ruling says. Released on close.
- **Holds** (`hold` op timers) are kept per pad.

## 4. What a document says that the code does not do, or was not done

- Nothing in the brief was left unbuilt. Every ruling is built as
  written. **Ruling 3's USB rule as written has a trap**: with both
  entries at the default `usb = true`, the first pad owns the reader even
  while it reads the Bluetooth pad through GLFW, so the wired pad on the
  second entry is never read. Built as written; the docs, the block to
  paste, check 219 and the line's own note (`usb: pad has the wired pad`)
  all say to put `usb = false` on the Bluetooth pad's entry. The smoke
  run shows the note. If the owner wants it to work with the defaults,
  the change is "the first `usb = true` pad with no GLFW joystick owns
  the reader" (row 211's other option) — a few lines in `Pad._usb_state`.
- "Learn pad" in the param menu is gated on `rig.adapter("gamepad")`
  being on (the first open pad): with only the second pad connected the
  item is missing. Left as a rough edge (no page change).
- `test_device_inputs.py::test_a_qualified_source_is_its_roles_and_adds_no_colon`
  had one assertion that encoded "a scheme that is not MIDI takes no
  qualifier" (`hand@x:1`'s scheme `hand@x`); it now asserts the B6 rule.
  `test_devices.py::test_a_second_enabled_device_claiming_a_scheme_is_refused_with_a_note`
  is rewritten to the new rule (a second pad opens; a second hands entry
  is refused). No boundary test changed; no MIDI test changed.
