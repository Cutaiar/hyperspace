## 1. Register-row drafts

### 1xx. SAVE is track 8's clip stop, a momentary on `desk.save`

- **Built.** Track 8's clip stop (G6·8) is the desk's **SAVE**: hold it
  and tap a bank pad (clip rows 1, 4, 5) to save the live state into that
  pad's slot. It is one invariant row (`apc40.SAVE`), the same on both
  layers, lit while held. The row is a `momentary` on a new session param
  `desk.save` ("Save", never saved, never performed), not a note the
  adapter tracks on its own. So the on-screen desk draws it, Learn
  refuses it like any invariant control, and a device taking the adapter
  over (B2) carries it as a port. A reconnect releases it, so a note-off
  lost to a pulled cable cannot turn the next pad press into a save. A
  bindings.json gains the row once, only where nothing already uses
  clip stop 8. Clip stops 1–7 stay free for Learn.
- **Other options.** Another free button (the working plan's open
  question): a clip-stop is the nearest free button to the pads, and
  track 8's is at the end of the row. SAVE as a modifier read inside the
  adapter (no param): the panel could not show it, and B2 would have to
  re-invent it.
- **To reverse.** One row in `apc40.DEFAULT_MAP` and one in
  `routing.APC_NEW_ROWS` (move it to another note), or drop both to
  retire it.
- **Rough edge.** An owner's row already on clip stop 8 in a preset's
  desk is dropped at load with the D6 note. In a session file, it keeps
  the control and SAVE is not added there.
- **Judge it.** Check U.1.

### 1xx. The two-handed save's naming and blink

- **Built.** On a filled pad the new preset is named from the **loaded**
  preset (`save_new`'s rule: TRIP → TRIP 2, counted against every file,
  listed name and bank name), not from the preset the slot held. The
  footer says "saved TRIP 3 → slot 11 (TRIP 2 is still in the preset
  list)". The tapped pad blinks for 1.5 s (`BLINK_S`) and then shows
  green as the loaded slot. A save that could not be written blinks
  nothing and logs "nothing saved". A tap under SAVE never loads the pad
  first and never starts its hold.
- **Other options.** Name the new preset from the slot's old preset
  (FIELD → FIELD 2 on F3). That reads well when the old preset was
  loaded, but differently from every other save on the desk.
- **To reverse.** One line in `library.Project._save_new` (the base
  passed to `next_name`).
- **Rough edge.** None of it has been on the APC40.
- **Judge it.** Check U.1.

### 1xx. A preset load releases every fader the preset binds (row 44 changed)

- **Built.** Every load re-arms soft pickup on **every fader the new
  preset's desk binds** (a preset-layer row), whether or not the load
  moved its param, so each one picks up from the new preset the same way
  every time. A fresh row starts from where its fader physically is (the
  last value the control sent, `MidiIO._hw`), so a fader already sitting
  on the value catches on its first move. The session's faders
  (invariant or global: the crossfader's dim, MASTER, and today S1–S8)
  keep row 44's rule, since a preset never moves their params (D9). Also
  on every load and at power-up, every control of the APC40's layout
  that no active row draws is sent dark, not only the controls a row
  once named.
- **Other options.** Row 44 as it was, which releases only when the load
  moved the param. On a real load the preset rows are fresh objects
  anyway, so this mostly makes the rule explicit and adds the position
  seed. The dark pass on every redraw (SHIFT too) would be about a
  hundred more messages per SHIFT press.
- **To reverse.** One condition (`b.layer == "preset"`) and one call
  (`_dark_desk`) in `MidiIO.redraw`.
- **Rough edge.** Nothing is visible until C2 puts faders on the preset
  layer. A fader nobody has moved since launch has no position, so its
  first move after a load must land within the pickup tolerance or wait
  for the second move to cross.
- **Judge it.** Check U.3 (and check 55 (e) as it stands).

### 1xx. The factory files keep the four toggle rows; a load drops them quietly

- **Built.** Decision 23 keeps every file under `hyperspace/library/`
  byte-identical, so the factory presets still carry the four render
  toggle rows on scene launch 1–4. The generator keeps writing them
  (`preset.file_desk` is the fresh desk plus those rows, and is
  `Factory.desk`'s default and `write_factory`'s fallback).
  `preset.fresh_desk`, which is what a load leaves and what a file with
  no desk gets, does not have them. A load drops those four exact rows
  **without a note** (`routing.TOGGLE_DESK_ROWS`, part of
  `RETIRED_DESK_ROWS`), as plan 19 did with the shape pads, because the
  session's invariant rows do the same job. An owner's other row on scene
  launch 1–4 drops **with** the D6 note. The preset is not dirty after the
  load.
- **Other options.** Regenerate the factory files without the rows
  (forbidden this run). Drop them with a note (twenty-three factory
  presets would each say so on every load).
- **To reverse.** After the creative pass, point `Factory.desk` and
  `write_factory` at `fresh_desk` and run `python -m hyperspace.preset`:
  the rows leave the files. Emptying `TOGGLE_DESK_ROWS` brings the note
  back.
- **Rough edge.** Until then the factory files and the loaded desk differ
  by four rows. `test_presets` / `test_plan12_presets` say so.
- **Judge it.** Check U.2.

### 1xx. The desk event log's shape

- **Built.** The SYSTEM page, under **midi**, has a fold "desk log — the
  last N presses". Each line has the wall time, the control in the
  desk's words ("G1·5 (clip 1·5)"), what the press did ("Preset → TRIP",
  "Points → on", "saved into slot 15: TRIP 2", "nothing (no row on the
  preset layer)", "held: nothing saved (a filled pad only loads)",
  "learn: …"), and the layer it was read on (preset / global / both for an
  invariant control). Newest first, twenty kept. Button presses, holds
  that fired and two-handed saves are logged. Knob and fader moves are
  not (they would push everything else out in a second), and neither are
  releases.
- **Other options.** Log knob moves too, collapsed per control. Show the
  log on the ROUTING page. Write it to a file.
- **To reverse.** `midi.DESK_LOG_SIZE`, `midi.DeskLog`, and the one
  helper `Panel._desk_log` (with `ui.desk_log_lines`).
- **Rough edge.** It lives in memory only and is lost at restart. With no
  APC40 adapter there is no log.
- **Judge it.** Check U.4.

## 3. As-built notes (for `docs/plans/24-…`)

**At the machine.** Hold track 8's clip stop (SAVE) and tap any bank pad
to save the live state into it. An empty pad gets a new preset, and so
does a filled pad (TRIP 2), whose old preset stays in the list. The pad
blinks. Holding an empty pad still saves into it, and holding a filled
pad still only loads. Scene launch 1–4 (points, lines, faces, rotate)
work and light on both layers. Loading a preset redraws every light on
the desk. SYSTEM → midi → "desk log" lists the last twenty presses.

**Code.**
- `apc40.py`: `TOGGLES`, `SAVE`, the map's toggle rows without a layer,
  and the SAVE row.
- `routing.py`: `SAVE_PARAM` and `desk.save` (`register_desk`),
  `TOGGLE_DESK_ROWS` ⊂ `RETIRED_DESK_ROWS`, and five rows in
  `APC_NEW_ROWS` / `APC_REMAP_PLAN` ("plan 24").
- `library.py`: `Project.save_into` (filled slots too), `save_empty`
  (#158's hold), and `_save_new`, which restores the old slot when the
  show can't be written and names the kept preset in its message.
- `params.py`: `Param.save_into`, `Registry.enum(save_into=)`, and
  `preset.select`'s `held=save_empty` / `save_into=save_into`.
- `midi.py`: `DeskEvent` / `DeskLog` / `DESK_LOG_SIZE`, `_save_tap`,
  `_log_press`, `_hw`, `redraw(whole=)`, `_dark_desk`, and the row 44
  change.
- `preset.py`: `file_desk`.
- `ui.py`: `desk_log_lines` and `Panel._desk_log`.
- `bindings.default.json` is regenerated.

**Review round 1 (`77efecb`).**
- **SAVE can never be latched.** `desk.save` is no desk target (`ui_routing.desk_target` excludes it beside SHIFT), so ROUTING's target combo, "Learn desk" and "Learn pad" never offer it. `Learn.learn_control` / `learn_pad_button` refuse it (`learn.SAVE_REFUSAL`). `routing.save_refusal` refuses any non-momentary row on it: `Bindings._check` / `bind` raise, `set_desk` drops with a note, and a hand-edited `bindings.json` loses the row with a note and is written back once.
- **SAVE's absence is said.** When the owner's `bindings.json` holds track 8's clip stop (`note:7:52`), SAVE is not added, and every launch says "SAVE not added: note:7:52 is yours (…)" on stderr and on the SYSTEM page line (`routing.save_missing`, appended to `Bindings.said`). It is never written into the file.

**Tests.** `tests/test_desk_trust.py` (22 tests after review round 1, fake ports) and the
fixture `tests/fixtures/desk-trust/old-desk.json` (force-added). Existing
assertions moved as the PR body lists.

**What no person has verified.** All of it on the APC40: SAVE's LED,
the blink velocity on a pad (`blink_of`), the whole-desk dark pass
(about 100 messages per load; whether the mk1 keeps up), and the fader
pickup after a load with the position seed.

**Rough edges.**
- The factory files still carry the toggle rows until the creative pass
  regenerates them.
- A fader never moved since launch has no position to seed.
- The log is in memory only.
- An owner's row on clip stop 8 in a preset desk is dropped with a note.
