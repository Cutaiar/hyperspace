## 1. Register-row drafts

**1xx — The FX node is the chain, one per pipeline, and the last node of its pipeline**
- **Built:** `graph.Fx` wraps `fx.FxChain`: it paints its input into the chain's first half-float texture (`FxChain.begin`) and the chain's last effect writes the destination; with no effect on it paints its input straight through and never touches the chain. The three default pipelines are three `Fx` nodes over the one chain (`fx`, `fx(scene+hands)`, `fx(hands)`), the effects' order inside each as today. As the end of a pipeline the node also decides where the picture lands: straight into the one output that takes it when that output is at the frame's size, unflipped and on this context; otherwise once into the pipeline's frame texture that every output of it shows — `Renderer._pipeline`'s rule, so the three hands-absent `solo` frames that differ by 1 LSB from their 8-view twins still differ the same way. The owner sees one SYSTEM line per chain node, 0.00 when its pipeline did not run.
- **Other options:** one FX node shared by the pipelines (the chain's ping-pong textures are shared state, so two pipelines cannot interleave through one node); an FX node only while an effect is on (the graph would rebuild on every `fx.on`, and the SYSTEM line would come and go); the direct-or-texture decision on the Output node (two outputs sharing a pipeline would each have to know the other).
- **To reverse:** local to `graph.Fx.run`/`paint` and `default_graph`.
- **Rough edge:** a SCENE+HANDS or HANDS `Fx` node sits in the graph (and on the SYSTEM page at 0.00) whenever an output has hands-through on, even with no effect on or no hand showing, because the node set follows the switches and the route is per frame. A4 names instances; these three are one chain, not instances, so their names are not param prefixes (`fx(...)`, never `fx.<x>`).
- **Judge it:** V.4.

**1xx — The History wrapper is two nodes: `history` (echoes and dream over its input) and `capture` (the ring)**
- **Built:** `graph.History.paint` is `Lookback.composite` (its input over the echoes and the dream, occluded by the `cover` mask port; a copy when the look-back is off) and its `run` moves the echoes' clock and pulls a finished dream once a frame. `graph.Capture.run` is `Lookback.capture` from its `image` port — the scene — exactly once a frame, ordered after every pipeline end, whatever the switches, and the effects' clocks advance there when no chain ran. Two nodes because the composite must read the ring before the frame's capture changes the echoes' weights, ages and tint, and the composite runs once per pipeline. The history never holds the hands, the effects or the dim: `capture` is wired to `scene`, and A3 makes that wiring a choice.
- **Other options:** one History node with a two-phase contract (`run` before the composites, `finish` after — a second evaluator phase for one node); capture inside the History node's run (the composite would then see the current frame as an echo: every echo golden moves); capture by the Output node (several outputs would capture several times).
- **To reverse:** merge the two classes and add the second phase to `Graph.evaluate`; no pixel changes.
- **Rough edge:** `history`'s GPU line sums its composites for every pipeline of the frame (today's "lookback" line did the same, plus the capture, which now has its own line).
- **Judge it:** V.4.

**1xx — The Output node is `Renderer._compose`, one per view, after the capture**
- **Built:** `graph.Output.run` calls `_compose` for its view: the pipeline's picture (already there when painted direct; shown 1:1 or scaled into `outputs.fit`'s rect otherwise), the hands over, the readout, the mirror, the dim (master × its own), or the five-step `Handoff` for a view with a presenter. `Handoff` and `Presenter` are untouched. Named `output.N` after the `output.N.*` params; one SYSTEM line each (A0's "compose" line summed them).
- **Other options:** moving `_compose` into graph.py (it would then need `Handoff`, `fit`, `_show`, `dim_pass`, the ghost's composites — all still the renderer's); one Output node for all views (no per-output timing).
- **To reverse:** trivial; the node is a wrapper.
- **Rough edge:** in A1 the Output's input is `outputs.route`'s pipeline for its switches this frame, not a fixed port: the node holds every pipeline end of the graph on named ports (`scene`, `scene+hands`, `hands`) and picks per frame, because whether a hand shows is only known after the hands' layer drew. A3 makes it wiring.
- **Judge it:** V.4, V.5.

**1xx — Node and port design: materialised images are pulled by their consumers; painted images draw into the consumer's framebuffer**
- **Built:** `graph.Node` has a unique `name` (the SYSTEM line, the timer key), `INPUTS` (port → type: `image`, `mask`, `geometry`), one `OUTPUT` type, `after` ordering dependencies, and `run(frame)`. A Scene or Layer node *makes* a texture (`image(frame)`); a History, Composite or FX node *paints* (`paint(frame, dst)`) into whatever framebuffer its consumer hands it, as today's passes do — the look-back composites straight into the chain's half-float input and the chain writes straight into the window. The default `paint` shows a made texture 1:1, so any image feeds any image port. Geometry nodes have `prepare`/`draw` and are drawn by their scene; they are not timed (their time is the scene's). The graph refuses a wrong port type, an unknown port, a dependency outside the graph and a duplicate name at build time. Method names: `run`, `paint`, `draw`, `image` — never `apply`, `modulate`, `snapshot`, `set_value` (pinned by `tests/test_graph.py` as `test_render.py` pins render.py).
- **Other options:** every node materialises a texture (an RGBA8 texture between the look-back and the half-float chain quantises the picture: goldens move); a `Port` object per connection (more machinery than seven nodes need; plan 28's editor can add it).
- **To reverse:** the pull is inside three `paint` methods; a materialising design would replace them and re-record goldens.
- **Rough edge:** a painted node can run more than once a frame (the history for two pipelines) — by design, and its GPU line sums them.
- **Judge it:** V.4.

**1xx — The default graph is keyed by the views' switches alone and the last one is reused**
- **Built:** `graph.graph_key(views)` is each view's (scene, hands, through); `Renderer._graph_for` keeps the last graph and builds a new one only when the key changes (a switch toggled, an output opened or closed). Size, flips, dim, a presenter and the cap are read when the nodes run. Which pipelines run in a frame is `outputs.route` per view (an effect on, a hand showing), resolved after the hands' layer: a pipeline with no output this frame is skipped. `Renderer.on_reload` drops the graph so a saved graph.py rebuilds it from the new classes (the nodes hold no GL resources; they are not re-classed).
- **Other options:** key on `fx.active()` and hand visibility too (a rebuild on every hand that enters the box and every effect toggle — cheap, but the SYSTEM page would flicker its lines); a cache of every graph seen (nothing to gain for a handful of switch states).
- **To reverse:** local to `_graph_for` and `graph_key`.
- **Rough edge:** `FxChain.tick` (the effect folder's 30-frame watch) now runs at the top of the frame, before the scene pass, instead of after it: an effect file saved to disk lands on the faces' picture on the poll frame itself rather than the frame after. No golden sees it (nothing is saved mid-run).
- **Judge it:** V.4, V.5.

**1xx — The cover mask is a Layer node of the scene's faces, wired to the history**
- **Built:** `graph.Cover` draws the faces' coverage mask (`Renderer._draw_cover`) only while the look-back occludes, from the face buffer the scene pass left, and feeds the `history` node's `cover` port (type `mask`). Its SYSTEM line stays `cover`.
- **Other options:** the cover inside the Scene node (its line would merge into `scene`); the cover drawn by the History node before its first composite (the same pixels, but a history node that draws geometry).
- **To reverse:** local.
- **Rough edge:** in A1 it depends on the scene node (the buffer), not on the shape geometry directly; A2/A3 can draw it from the geometry in the shared camera.
- **Judge it:** V.4.

## 3. As-built notes (shape of plan 21)

**At the machine.** Nothing visible changes but the SYSTEM page: "gpu per pass" is now "gpu per node", one line per node of the render graph (`scene`, `cover`, `hands`, `history`, `fx`, `capture`, `output.1`, …; `composite(scene+hands)`, `fx(scene+hands)`, `composite(hands)`, `fx(hands)` while an output has hands-through on; `output.2` with a second output), and a node that leaves the graph leaves the list. Every frame of every output is the one A0 recorded.

**Code.**
- `hyperspace/graph.py` (new): `Frame`, `Node`, `Shape` (geometry), `Scene`, `Cover` and `HandsLayer` (layers), `History` and `Capture` (history), `Composite`, `Fx`, `Output`, `Graph` (add / order / timed / evaluate), `graph_key`, `pipelines_of`, `default_graph`, the node-name tables (`COMPOSITE_NAMES`, `FX_NAMES`, `PORTS`). Imports moderngl and `outputs` only.
- `hyperspace/render.py`: `_draw_frame` is now "settle the frame, build or reuse the graph, evaluate it"; `_graph_for`; `_frame_passes` and `_pipeline` are gone; `PassTimer` is per node (`end_frame(names)`, `_pending` carries each frame's names, `medians` in graph order, `GPU_PASSES` removed); `Renderer._graph`; `on_reload` drops it. The passes themselves (`draw_scene`, `_face_picture`, `_draw_cover`, `_compose`, `_show`, `_frame_target`, `dim_pass`, `_hands_failed`, `_view_failed`, `_rebind`) are unchanged and called by the nodes.
- `hyperspace/hotreload.py`: `graph` in `MODULES` after `view`, before `render`.
- `hyperspace/ui.py`: `Panel.gpu_lines` heading "gpu per node".
- `hyperspace/outputs.py`, `lookback.py`, `fx.py`, `ghost.py`: untouched (the WP table listed them as "mostly touches"; wrapping needed no change in them).

**Tests.** `tests/test_graph.py` (new, 11 tests: imports and the banned names, the default graph's shape and order for one view, `pipelines_of`, the graph per switch set, `graph_key`, port typing and the graph's checks, tie order, GL: reuse / rebuild / reload / pre-A1 renderer, a pipeline with no users does not run, the timer's names and a node that left, a made image paints 1:1). `tests/test_golden_frames.py`: `test_each_pass_has_a_rolling_median_in_ms` → `test_each_node_has_a_rolling_median_in_ms` (node names from `r._graph.timed` instead of `GPU_PASSES`), `test_the_gpu_lines_on_the_system_page` (heading "gpu per node", `output.1` as the second sample line), module docstring. Nothing else changed: `test_outputs.py`, `test_render.py`, `test_hotreload.py` (its two pinning tests are data-driven and pass with `graph` in the list) untouched. 1915 passed, 2 skipped (1904 + 2 on the base, + 11).

**What no person has verified.** The SYSTEM page's per-node lines in the live app (drawn headlessly, and the smoke run does not open the panel). The smoke run (`HYPERSPACE_FRAMES=120`, scratch home, `-ApplePersistenceIgnoreState YES`) ran 120 frames and exited 0 with an empty stall log.

**Rough edges.**
- The route is per frame in A1 (an Output picks its pipeline end after the hands' layer drew); A3 turns `Switches.through` into wiring.
- The scene's clear lives in `draw_scene`, so a Scene holds one geometry in A1; A3 moves the clear to the Scene node when the hands join it.
- `FxChain.tick` moved before the scene pass (see the register row). `Lookback.tick`/`pull` live in the `history` node's `run`, which now runs **after** the hands' layer (before A1 they ran before `Ghost.layer`), and `target.viewport = vp` (output 1's rect on its framebuffer object) is set at the top of the frame instead of after the cover; both are pixel-neutral (the hands' layer reads neither the echoes' clock nor the dream, and nothing reads the first target's viewport before its own direct use sets it again).
- Graph nodes are not hot-reload targets; a saved graph.py reloads render.py after it and `Renderer.on_reload` rebuilds the graph. The timer is not a reload target either: `on_reload` drops it (`_drop_timer`, which frees its queries through its own `_off`) and `_pass_timer` also replaces a timer whose class is not this module's `PassTimer` — a live reload from A0's code to A1's otherwise left an A0 timer whose `end_frame()` took no names and raised on every frame (review fix round 1; pinned in `test_the_graph_is_built_once_per_set_of_switches_and_reused`).

**What A3/A4 must change (readiness notes, no code in A1).**
- `Scene.INPUTS` is one fixed `geometry` port. A3 needs any number of geometries (the shape and the hands in one scene): a list-valued port, or per-instance `INPUTS` built in `__init__` (`geometry`, `geometry.2`, …) — and the scene's clear moves out of `draw_scene` into `Scene.run`, with solid geometry drawn first, then the sorted see-through shape.
- `Composite.paint` ignores its `over` port and calls `r.ghost.composite` directly (the hands' layer is the only layer today, and its blend lives in `Ghost._lay`). A3's Composite must read `over.image(frame)` and own its blend (over, add, depth-aware), so a second hands layer or any other layer can feed it.
- `Output`'s `scene` / `scene+hands` / `hands` ports are decorative in A1: `run` reads `frame.routes()` (`outputs.route` per frame) to pick its pipeline end. A3 wires the one input and deletes `Frame.routes` / `users`; `Fx.run`'s "no users this frame → skip" becomes "no consumer".
- `Fx` carries an `outputs` pipeline `key` (for `_frame_target`, `stats["pipelines"]`, `NAMES` in `View.error`). Once the pipelines are wiring, the frame texture is keyed by the node, not by `SCENE`/`SCENE_HANDS`/`HANDS`, and `View.error` names the node.
- Every node reaches the renderer's singletons (`r.scene`, `r.cover`, `r.lookback`, `r.fx`, `r.ghost`, `r._blank`, `r._frames`) instead of owning or receiving its resource. A4's second instance of anything — a second hands layer (its own `Ghost`/targets), a second chain (its own `FxChain` and ping-pong textures), a second history (its own `Lookback` atlas) — needs per-node resources: give each node its resource in `__init__` (the default graph hands it the renderer's), and release them with the graph (today nodes hold none, so `on_reload` just drops the graph; with owned resources it must release them first, and `Renderer.release`/the app's close order must include the graph).
- `Frame.routes()` is only right once `HandsLayer` ran; the two callers are ordered after it by `after=gate` and the `layer` port. Any new node that asks must keep that dependency, until A3 removes the per-frame route.

**Hand checks.** A0's draft V.2 ("gpu per pass", six fixed lines `scene cover hands lookback fx compose`) is superseded by V.4 below (one line per node, names from the graph, a node leaving the list): the docs WP should fold V.2 into V.4 rather than number both.
